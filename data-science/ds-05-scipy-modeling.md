# 第5章 SciPy 数值方法与建模：从约束到解

> **学习目标**：把"一个现实问题"翻译成数学对象，求出它的解，并且能说清这个解可不可信。
>
> - **会写下来**：认清四种模型形态（方程组 / 目标+约束 / 插值 / 微分方程），知道每种形态该用哪个模块
> - **会问可解**：动手求解之前先判断有没有解、唯不唯一、良不良态（秩、正定性、条件数）
> - **会求解**：在分解法/迭代法、梯度法/无梯度法、显式/隐式之间做出有依据的选择
> - **会验证**：把残差、KKT 违背量、收敛阶、守恒量写成可执行断言，而不是"跑完没报错"

第 4 章处理的是 **"样本 → 总体"**：从有限数据反推未知的总体参数，核心武器是零分布与不确定性。本章处理的是 **"约束 → 解"**：把现实问题写成方程、目标或演化规律，然后把它解出来。同一个库，两套完全不同的心智模型——第 4 章问"这个结论有多可信"，本章问"这个答案对不对、准不准、值不值得算"。

卷 2 的欠账在这里结清：`ds-00` 0.2.8–0.2.11 备好的行列式、秩、条件数、特征值与梯度，`ds-01` 的数组原语与 `np.linalg` 最小集，`ds-02` 的表格与缺失值，`ds-03` 的结果可视化——它们全都在本章第一次被用来**造出一个答案**，而不是描述一份数据。

**本章边界**：只讲 "问题 → 解" 这一条链。落到统计推断（区间、检验、分布拟合）的问题请回 `ds-04`；落到机器学习（正则化路径、模型选择、交叉验证）的问题属于卷 3。本章刻意**不**引入新的第三方库：sympy（符号推导）、networkx（图算法全集）、cvxpy（凸优化建模）、pandas 之外的数据源都不在范围内，遇到边界会明确说"该去哪里"，而不是硬凑一个半成品。

> **版本注意（SciPy 1.18 基线）**：本章以 SciPy 1.18 为准，与网上大量 1.x 早期教程有八处显著差异，正文中会逐一标注——
> ① **`integrate.simps` / `trapz` / `cumtrapz` / `romberg` / `quadrature` 已全部移除**，采样点积分改用 `simpson` / `trapezoid` / `cumulative_trapezoid`；连 `np.trapz` 也没有了，改名为 `np.trapezoid`（5.8）；
> ② **`signal.cwt` / `morlet2` / `ricker` 已移除**（连续小波变换请用 PyWavelets），`signal.lsim2` 也已删除（5.12）；
> ③ **`scipy.odr` 自 1.17 起弃用、将在 1.19 移除**，两轴都带误差的拟合官方指向 `odrpack` 包（5.6）；
> ④ **`scipy.linalg.cond` 不存在**——条件数只有 `numpy.linalg.cond` 一个入口（5.2.3）；
> ⑤ **`scipy.linalg.lstsq` 返回普通 4 元组，没有 `.x` / `.rank` / `.s` 命名属性**；而且**秩亏时 `residues` 返回 `nan` 而不是报错**（`numpy.linalg.lstsq` 则返回空数组），这是本章最安静的陷阱（5.2.5）；
> ⑥ **`optimize.linprog` 的 `simplex` / `interior-point` / `revised simplex` 三种 method 仍可调用但已弃用**，新代码只用 HiGHS 系列；整数规划优先用 `optimize.milp`（5.5）；
> ⑦ `special.fact2` 改名为 `factorial2`，`special.sph_harm` 改名为 `sph_harm_y`（5.12）；
> ⑧ `interpolate.interp1d` 在官方文档里已明确标注 legacy（5.7），`optimize.curve_fit(full_output=True)` 现在对 `lm` 与 `trf` 统一返回 5 元组（5.6）。

### 5.0.5 记号与代码约定

- **随机数**：一律 `rng = np.random.default_rng(seed)`，与 `ds-00` 0.1.5 一致。本章新增一条：`scipy.stats.qmc` 的生成器**必须**显式传 `rng=`，而 `optimize.differential_evolution` 同时接受 `rng=` 与遗留的 `seed=`，**只用 `rng=`**。
- **记号**：沿用 `ds-00` 的符号表。本章新增或首次大量使用：$A$（系数矩阵）、$x$（未知向量/决策变量）、$b$（右端项）、$f(x)$（目标函数）、$c$（线性目标系数）、$J$（雅可比）、$H$（Hessian）、$\mathrm{cond}(A)$（条件数）、$\sigma_i$（奇异值）、$\lambda_i$（特征值）、$\nabla f$（梯度）。
- **矩阵尺寸记号**：$m$ 是方程个数（行），$n$ 是未知数个数（列）。**报规模时一律写 "$m \times n$"**，不要只写 $n$——本书全部数值结论都依赖这两个数分得清。
- **代码块**：`>>>` 是 REPL 会话（输出为实跑结果），无提示符的是完整脚本片段。凡是求解器返回的对象，**优先用命名属性或显式解包**，不要依赖元组位置——5.2.5 会给出一个为此付出代价的例子。
- **结果报告格式**：报告一个数值解时，固定写四件事：**方法名 + 残差 + 迭代/调用次数 + 条件数（或收敛判据）**。只报结果不报这四项，等于没报。

## 5.1 从约束求解：定位、数学前置与四步骨架

### 5.1.1 与第 4 章的分工：同一个库，两种世界观

| | 第 4 章（`ds-04`） | 本章（`ds-05`） |
|---|---|---|
| 起点 | 一份样本数据 | 一个现实问题 |
| 中间物 | 分布、假设、统计量 | 方程、目标、约束、演化规律 |
| 终点 | 结论 + 不确定性 | 解 + 可信度 |
| 核心问题 | "这个结论有多可信？" | "这个答案对不对、准不准？" |
| 主要模块 | `scipy.stats` | `linalg`、`optimize`、`integrate`、`interpolate`、`sparse`、`signal` |
| 典型失败 | 把显著性当成重要性 | 把"算完了"当成"算对了" |

两章共用 `scipy` 这个名字，但**先验知识、犯错方式、验证手段全都不一样**。把它当成"一个库的上下半场"来学，最容易出的错是：用统计口径去评价一个数值解（"这个系数显著吗"——它压根不是估计出来的），或者用一个数值解的精度去代替统计不确定性（"残差是 1e-12，所以模型一定对"）。

### 5.1.3 本章的数学前置

`ds-00` 0.2.8–0.2.11 已经把本章要用的四件数学工具全部备好。这里只做一次"工程读法"的对接，说明它们各自在本章的哪一步出场：

| 数学对象 | 出自 | 在本章的用途 | 一句读法 |
|---------|------|-------------|---------|
| 秩与行列式 | `ds-00` 0.2.8 | 判断方程组有没有解、最小二乘要不要截断 | 秩决定"解有几个"，不是行列式 |
| 矩阵分解 | `ds-00` 0.2.9 | 选求解路径：Cholesky / QR / LU / SVD | 拆开的目的是把难事变简单 |
| 条件数 $\mathrm{cond}(A)$ | `ds-00` 0.2.9 | 判断解还剩几位可信；迭代法的收敛速度 | **约等于丢掉的十进制位数** |
| 特征值、正定性 | `ds-00` 0.2.10 | 判断能否用 Cholesky 与共轭梯度；鞍点识别 | 全正 = 碗，有正有负 = 鞍 |
| 梯度、雅可比、Hessian | `ds-00` 0.2.11 | 给求解器导数；判断收敛到的是不是极小值 | 能写解析式就别用差分 |

> **机制洞察**：数值方法这一整章，本质上只在做一件事——**把"数学上存在"变成"浮点里算得出"**。数学上 `A` 可逆不代表 `A` 在双精度里可解（5.2.3），数学上目标函数有唯一极小值不代表优化器能找到（5.4.4），数学上初值问题有唯一解不代表显式方法算得动（5.9.4）。本章的每一条陷阱，都是这条裂缝的具体形状。

### 5.1.4 四步骨架与三本账

任何一次"从问题到解"都要走同一条路，缺一步答案就不可信：

| 步 | 做什么 | 本章对应节 | 漏掉的后果 |
|----|--------|-----------|-----------|
| 1 **写下来** | 把现实问题翻译成数学对象：方程组 / 目标+约束 / 插值 / 微分方程 | 5.1.2、5.5.1 | 模型形态选错，后面全是白算 |
| 2 **问可解** | 有解吗？唯一吗？良态吗？（秩、正定性、凸性、条件数） | 5.2.3、5.3.6、5.4.4 | 解出来了，但解是噪声 |
| 3 **求解** | 选算法与后端（分解 vs 迭代、梯度 vs 无梯度、显式 vs 隐式） | 5.2–5.12 | 规模一上去就卡死，或精度悄悄丢掉 |
| 4 **验证** | 残差、KKT 违背量、收敛阶、守恒量、敏感性、量纲 | 5.13.4 | 把"算完了"当成"算对了" |

配套的是**三本账**。本书从 `ds-03` 3.14 起用"账"来记账式的数值判断，本章每一节都记同样三本：

| 账 | 记什么 | 典型指标 | 关键反直觉 |
|----|--------|---------|-----------|
| **精度账** | 解离真值有多远 | 误差、残差、后向误差 | 残差小 ≠ 误差小（5.2.3） |
| **成本账** | 算出来要多少工作量 | 复杂度、`nfev`、迭代数、`nnz` | 更快的算法常常更不准（5.4.2） |
| **稳定性账** | 结果对扰动有多敏感 | 条件数、刚性、局部极小、外推 | 问题本身的难度无法靠算法消除（5.2.3） |

### 5.1.5 本章的三条纪律

1. **先问可解性，再动手求解**。拿到方程组先 `cond`，拿到优化问题先想凸不凸，拿到 ODE 先估计刚性。**诊断花的时间永远少于返工。**
2. **残差必须亲自算**。求解器的返回值不是证据；`A @ x - b` 才是。本章每一节的实战都以一行残差/违背量检查收尾。
3. **量纲与尺度先行**。同一个问题把所有量换成同一量纲、把变量缩放到同量级，再做优化或拟合。尺度差几个数量级时，`minimize` 的收敛判据、`lstsq` 的 `cond`、`milp` 的可行性容差全部会失灵。

## 5.2 线性方程组与矩阵分解

本节是"代数层"的核心，也是本章篇幅最重的一节：**多元线性方程组**是数学建模中出现频率最高的问题形态——投入产出、电路网络、结构力学、最小二乘拟合、马尔可夫稳态，写到最后都是一句 $Ax = b$。

但"会写 $Ax = b$"和"会解 $Ax = b$"之间隔着一整个数值分析。本节的顺序就是四步骨架的展开：**怎么解（5.2.1–5.2.2）→ 什么时候不能用（5.2.3）→ 底层发生了什么（5.2.4）→ 方程数不等怎么办（5.2.5）→ 交付一个可复用的求解模板（5.2.6）**。未知数上万、矩阵几乎全是零的情形放在 5.3，因为那时换的不是算法参数，而是整套数据结构。

### 5.2.1 先解出来：`solve` 而不是 `inv`

写 $Ax = b$ 的 Python 版本时，最自然的冲动是"把 $A$ 除过去"，而矩阵没有除法，于是想到逆矩阵：

```python
>>> import numpy as np
>>> from scipy import linalg as la
>>> A = np.array([[3., 1., 1.],
...               [1., 4., 2.],
...               [2., 1., 5.]])
>>> b = np.array([10., 15., 18.])
>>> x_inv = np.linalg.inv(A) @ b          # ❌ 不要这样写
>>> x_inv
array([1.82608696, 2.06521739, 2.45652174])
>>> x = la.solve(A, b)                    # ✅ 这样写
>>> x
array([1.82608696, 2.06521739, 2.45652174])
>>> np.linalg.cond(A)                     # 3.12，良态
3.1207880730167408
```

两条路径在这道题上给出同一个答案（`cond` 只有 3.12）——这正是问题所在：**小规模良态问题看不出差别，等看出差别时已经晚了**。为什么 `solve` 更好，有三层理由，一层比一层硬：

**第一层，成本**。`la.solve(A, b)` 内部做一次 LU 分解（$\tfrac{2}{3}n^3$ 次浮点运算）再回代（$O(n^2)$）；`inv(A) @ b` 是先做分解、再做一次额外的矩阵求逆（又一个 $O(n^3)$），最后再乘一次。实测单独调用时，`la.inv(A)` 耗时约为 `la.solve(A, b)` 的 **1.8 倍**，而这还没算上后面那次矩阵乘法。要解 $k$ 个右端项时差距更明显：`solve` 可以复用一次分解，`inv` 路径则老老实实做完整套。

**第二层，精度**。求逆会额外引入一次舍入，而且误差会被条件数放大。更具体地说，差别体现在**残差**（也就是后向误差）上。取一批条件数递增的对称正定矩阵，真解取全 1 向量、右端项取 $b = A\mathbf{1}$：

```python
def spd(n, cond, seed):
    """构造一个 n×n 对称正定矩阵，条件数约为 cond。"""
    rng = np.random.default_rng(seed)
    Q, _ = np.linalg.qr(rng.normal(size=(n, n)))          # 随机正交阵
    return Q @ np.diag(np.logspace(0, np.log10(cond), n)) @ Q.T

# n = 60，逐个条件数档位对照
for c in [1e4, 1e8, 1e10, 1e12]:
    A = spd(60, c, 11)
    b = A @ np.ones(60)
    xs = la.solve(A, b, assume_a="pos")
    xi = la.inv(A) @ b
```

| $\mathrm{cond}(A)$ | 解误差 `solve` | 解误差 `inv` | 残差 `solve` | 残差 `inv` | 残差之比 |
|---|---|---|---|---|---|
| $10^{4}$ | 2.2e-13 | 3.4e-13 | 1.8e-12 | 6.0e-10 | 3.3e+02 |
| $10^{8}$ | 1.0e-09 | 2.0e-09 | 1.5e-08 | 1.2e-02 | 8.2e+05 |
| $10^{10}$ | 5.7e-08 | 3.3e-07 | 1.4e-06 | 7.0e+01 | 4.9e+07 |
| $10^{12}$ | 2.0e-05 | 3.8e-05 | 2.4e-04 | 1.6e+06 | 6.5e+09 |

残差之比与条件数同步增长，最后到 $6.5\times10^{9}$——`inv` 路径产出的 "解" 在代回方程后，残差比 `solve` 大了近十个数量级。有意思的是**解的最大误差两者只差几倍**：误差藏在了矩阵最不敏感的方向上，所以"代回去差不多对"这个直觉在这里完全失效（5.2.3 会把这件事说透）。

**第三层，用法**。绝大多数场景根本不需要矩阵的逆，只需要 $A^{-1}b$ 这个**作用结果**。真正需要显式逆矩阵的场合极少（例如要反复对许多不同右端项求积、或逆矩阵本身就是结论），那时也应当先问一句：能不能改成一次分解 + 多次回代？

> **⚠️ 陷阱**：`np.linalg.inv(A) @ b` 与 `la.solve(A, b)` 在教科书例子上永远一致，所以这个错误会在整个学习阶段潜伏，直到某天遇到病态矩阵才爆发。**把 `inv` 从肌肉记忆里删掉**：需要解方程就用 `solve`，需要伪逆就用 `pinv`（5.2.5），需要分解就用 `lu`/`cho_factor`（5.2.4）。

配套的结构化入口，是拿到矩阵后第一件该看的事——它决定用哪条最快的路径：

| 矩阵性质 | 推荐入口 | 相对 `solve`（通用 LU）的成本 | 前提 |
|---------|---------|---------------------------|------|
| 对称正定 | `la.cho_factor` + `la.cho_solve` | 约一半 | 必须正定，否则报错 |
| 一般方阵 | `la.solve(A, b)` | 基准 | 满秩 |
| 三角矩阵 | `la.solve_triangular` | $O(n^2)$ | 已知三角 |
| 三对角/带形 | `la.solve_banded` | $O(n)$ | 带宽很窄 |
| 稀疏 | `sparse.linalg.spsolve` | 依赖 `nnz`，可快几十倍 | 5.3 |

后三行的收益不是常数因子，而是**复杂度的量级差别**。实测一个 $N = 2000$ 的三对角系统（主对角 2、上下对角 −1，正是 `ds-00` 0.2.7 里那个一维 Laplacian 的放大版）：

```python
# 带形存储：3 行 × N 列，第 0 行放上对角，第 1 行放主对角，第 2 行放下对角
A_band = np.zeros((3, N))
A_band[0, 1:] = -1.0
A_band[1, :]  =  2.0
A_band[2, :-1] = -1.0
```

```python

>>> xd = la.solve(A_dense, np.ones(N))                    # 稠密求解
>>> np.abs(xb - xd).max()
```

耗时对比：`solve_banded` **0.047 ms**，稠密 `solve` **23.5 ms**——**506 倍**，而且两者的解逐位相同。差别不在算法聪不聪明，而在**有没有利用结构**：稠密求解器老老实实分解了一个 $2000 \times 2000$ 的矩阵，其中 99.8% 的元素是零。

> **实战建议**：写 `la.solve` 之前先回答三个问题——矩阵对称吗？正定吗？带形/稀疏吗？三个问题各对应一个更快的入口，加起来能让常见问题的耗时降一到两个数量级。这个"三问"就是 5.2.7 求解模板的第一段。

### 5.2.2 结构决定路径：对称、三角与带形

`ds-00` 0.2.9 列过 LU / QR / Cholesky / SVD 四种分解"各答什么问题"。落到 scipy 的 API 上，它们的对应关系是：

| 分解 | scipy 入口 | 返回什么 | 直接用途 |
|------|-----------|---------|---------|
| LU | `la.lu(A)` | `P, L, U`，满足 $A = PLU$ | 理解 `solve` 内部在做什么 |
| LU（因子式） | `la.lu_factor(A)` | `(lu, piv)`，紧凑存储 | 一次分解、多次求解 |
| Cholesky | `la.cholesky(A)` / `la.cho_factor(A)` | 下三角 $L$ | 对称正定系统 |
| QR | `la.qr(A)` | `Q, R`（可选 `mode='economic'`） | 最小二乘（5.2.5） |
| SVD | `la.svd(A)` | `U, s, Vt` | 秩、条件数、伪逆、截断 |

`lu` 与 `lu_factor` 的分工值得单独说。`la.lu` 返回三个**人类可读**的矩阵，适合检查和讲解；`la.lu_factor` 返回一个紧凑的因子对象，适合真正拿来算：

```python
>>> A = np.array([[0., 1.],
...               [2., 3.]])
>>> P, L, U = la.lu(A)
>>> P
array([[0., 1.],
       [1., 0.]])
>>> np.allclose(P @ L @ U, A)             # True：分解恒等式成立

>>> lu_piv = la.lu_factor(A)
>>> la.lu_solve(lu_piv, np.array([1., 5.]))
array([1., 1.])
>>> la.solve(A, np.array([1., 5.]))       # 对照
array([1., 1.])
```

注意 `P`：`A` 的第一行第一列是 0，没法直接拿它当主元，所以分解过程**交换了两行**。这就是"选主元"（pivoting），也是 `solve` 在背后替你做的事。它看起来只是个技术细节，实际是整个直接法里最要命的一步：

```python
>>> B = np.array([[1e-20, 1.0],
...               [1.0,   1.0]])
>>> np.linalg.cond(B)
2.6180339887498953                        # 条件数只有 2.6，极其良态
>>> la.solve(B, np.array([1., 2.]))       # scipy（带选主元）
array([1., 1.])                           # ✅ 正确
```

同一个矩阵，如果手写一个**不选主元**的高斯消元：

```python
def naive_solve(A, b):
    A = np.array(A, dtype=float); b = np.array(b, dtype=float); n = len(b)
    for k in range(n - 1):
        for i in range(k + 1, n):
            f = A[i, k] / A[k, k]
            A[i, k:] -= f * A[k, k:]
            b[i] -= f * b[k]
    x = np.zeros(n)
    for i in range(n - 1, -1, -1):
        x[i] = (b[i] - A[i, i + 1:] @ x[i + 1:]) / A[i, i]
    return x
```

```python
>>> naive_solve(B, [1., 2.])
array([0., 1.])                           # ❌ 完全错误：真解是 [1, 1]
```

条件数是 2.6，问题本身好得不能再好，答案却是错的。原因在第一步：$a_{11} = 10^{-20}$，第一个乘数是 $1/10^{-20} = 10^{20}$，于是 $a_{22}$ 被更新成 $1 - 10^{20}$——**原始信息 $1$ 被彻底吃掉了**。选主元做的事很简单：先交换行，让主元尽可能大。

> **机制洞察**：误差的来源不止"条件数大"这一种。本例里 $\mathrm{cond}(B) = 2.6$ 却算出完全错误的解，说明**算法本身也会制造误差**，而条件数只描述问题、不描述算法。数值分析把这两件事分开记账：**问题的敏感度**用条件数，**算法的稳定性**用后向误差。稳定的算法（带选主元的消元、Householder QR、Givens 旋转）保证"算出的解是某个邻近问题的精确解"，误差不会无中生有。配套文件 `ds-05b` S2 会给出增长因子的定量刻画。

### 5.2.3 什么时候不能用：条件数与残差诊断

这是本节最重要的一小节。前面两小节讲"怎么解得更快更稳"，这一小节讲 **"这个解到底值不值得相信"**——而且它要拆掉两个几乎所有人都有的直觉。

**直觉一：残差小就说明解对了。** 错。看 Hilbert 矩阵（$H_{ij} = 1/(i+j-1)$，`ds-00` 0.2.9 已经见过它的病态），真解取全 1、右端项取 $b = H\mathbf{1}$：

```python
>>> for n in [6, 8, 10, 12]:
...     H = la.hilbert(n)
...     x = la.solve(H, H @ np.ones(n))
...     err = np.abs(x - 1).max()          # 误差：离真值多远
...     res = np.abs(H @ x - H @ np.ones(n)).max()   # 残差：代回方程差多少
...     print(f"n={n:2d} cond={np.linalg.cond(H):.1e} 误差={err:.1e} 残差={res:.1e} 误差/残差={err/res:.1e}")
n= 6 cond=1.5e+07 误差=3.1e-10 残差=2.2e-16 误差/残差=1.4e+06
n= 8 cond=1.5e+10 误差=5.4e-07 残差=2.2e-16 误差/残差=2.5e+09
n=10 cond=1.6e+13 误差=4.5e-04 残差=4.4e-16 误差/残差=1.0e+12
n=12 cond=1.8e+16 误差=3.9e-01 残差=4.4e-16 误差/残差=8.7e+14
```

逐行读：$n = 12$ 时，解离真值差了 **0.39**（真值是 1，等于错了 39%），可残差是 **4.4e-16**——在双精度下已经小到不能再小。**"代回去完全对得上"和"解是对的"是两件事。**

真正说明问题的是最后一列：**误差/残差 ≈ 条件数**。这不是巧合，而是可以证明的关系：残差衡量的是"输出端的偏差"，误差衡量的是"输入端的偏差"，而条件数正是这两者之间的放大倍数。于是得到一条极其实用的换算：

$$\frac{\lVert \hat{x} - x \rVert}{\lVert x \rVert} \;\lesssim\; \mathrm{cond}(A) \cdot \frac{\lVert b - A\hat{x} \rVert}{\lVert b \rVert}$$

左边是你要的相对误差，右边第一项是条件数（问题有多难）、第二项是相对残差（算得有多"满足方程"）。**残差永远可以做到机器精度，误差不行。**

**直觉二：求解器会在我解不准的时候警告我。** 也错。`scipy.linalg.solve` 确实会发 `LinAlgWarning`，但触发条件比大多数人以为的严格得多。逐档扫描条件数：

```python
>>> import warnings
>>> rng_w = np.random.default_rng(0)
>>> for k in [1e10, 1e13, 1e14, 5e15, 1e16, 1e17]:
...     Q, _ = np.linalg.qr(rng_w.normal(size=(6, 6)))
...     V, _ = np.linalg.qr(rng_w.normal(size=(6, 6)))
...     A = Q @ np.diag(np.logspace(0, np.log10(k), 6)) @ V.T
...     b = A @ np.ones(6)
...     with warnings.catch_warnings(record=True) as w:
...         warnings.simplefilter("always")
...         la.solve(A, b)
...         print(f"cond={np.linalg.cond(A):.2e} 警告={[type(i.message).__name__ for i in w]}")
cond=1.00e+10 警告=[]
cond=1.00e+13 警告=[]
cond=1.00e+14 警告=[]
cond=5.23e+15 警告=['LinAlgWarning']
cond=1.26e+16 警告=['LinAlgWarning']

```

阈值卡在 $\mathrm{cond} \approx 1/\epsilon \approx 4.5\times10^{15}$（LAPACK 估计的 `rcond` 小于机器精度 $\epsilon = 2.22\times10^{-16}$ 时才报）。也就是说：

> **⚠️ 陷阱**：$\mathrm{cond}$ 在 $10^{6}$ 到 $10^{15}$ 之间是一整片 **"静默失准区"**。第 5.2.1 节那张表里 $\mathrm{cond} = 10^{12}$ 的矩阵，解误差已经到了 $10^{-5}$ 量级，而求解器**一声不吭**。指望警告来兜底，等于放弃了整个静默失准区——那才是实践中绝大多数病态问题所在的地方。

所以诊断必须自己动手。一个可直接复用的体检函数：

```python
import numpy as np
from scipy import linalg as la

def solve_checked(A, b, name="A"):
    """解 Ax=b 并给出可信度诊断。返回 (x, 报告字典)。"""
    A = np.asarray(A, dtype=float)
    b = np.asarray(b, dtype=float)
    cond = np.linalg.cond(A)
    digits = np.finfo(float).precision - np.log10(max(cond, 1.0))
    x = la.solve(A, b)
    res = np.abs(A @ x - b).max()
    brel = res / max(np.abs(b).max(), 1.0)
    report = {
        "cond": cond,
        "digits_left": digits,
        "residual": res,
        "backward_error": brel,
        "error_bound": cond * brel,
        "suspect": cond > 1e10,
    }
    if report["suspect"]:
        print(f"[{name}] cond={cond:.1e}，结果可能只剩 {digits:.1f} 位有效数字；"
              f"相对误差上界 ≈ {report['error_bound']:.1e}")
    return x, report
```

这个函数里有两处值得说明：

- **`digits_left`**：`np.finfo(float).precision` 是 15（十进制有效位数），减去 $\log_{10}\mathrm{cond}$ 就是还能剩几位。$\mathrm{cond} = 10^{12}$ 时只剩 3 位。
- **`error_bound`**：直接把上面那条不等式右端算出来，作为相对误差的量级估计。它是个**上界**，实际误差通常小一到两个数量级，但量级判断足够用。

拿它体检两个矩阵，一眼就能看出差别：

```python
>>> x, rep = solve_checked(A, b)          # 5.2.1 那个 3×3 例子
（无输出：cond=3.1，未触发怀疑阈值）

>>> H = la.hilbert(10)
>>> x, rep = solve_checked(H, H @ np.ones(10))
[H10] cond=1.6e+13，结果可能只剩 1.8 位有效数字；相对误差上界 ≈ 2.4e-03
>>> np.abs(x - 1).max()                   # 实际误差
0.0004529...
```

预估的相对误差上界是 $2.4\times10^{-3}$，实际是 $4.5\times10^{-4}$——**上界对了量级，且偏保守**，正是它该有的样子。这条检查只要两行代码，却能把 5.2.1 到 5.2.6 的每一个结果都过一遍。

> **实战建议**：`cond > 1e10` 时**不要急着换求解器**。条件数描述的是问题本身，换算法救不回来。该做的是：① 换参数化或换模型（例如把多项式基换成正交基）；② 加正则化（5.2.5 的岭回归实测把误差降了 400 倍）；③ 提高精度（`np.longdouble` 或分段计算）；④ 接受它并如实报告有效位数。**"解出来了"不是交付标准，"解出几位"才是。**

3. `la.solve` 在 $\mathrm{cond} = 10^{14}$ 时不报警告。这是 scipy 的 bug 吗？如果不是，它为什么不报？
4. 5.2.2 里不选主元的高斯消元在 $\mathrm{cond}(B) = 2.6$ 的矩阵上失败了。用"问题敏感度 vs 算法稳定性"这对概念解释这件事。

### 5.2.4 分解家族：LU、Cholesky、QR、SVD 各答一个问题

前面三小节把 `solve` 当黑盒用。这一小节打开它，因为**选错分解方式是最常见的性能事故**，而选对的收益常常是按数量级计的（5.2.1 的带形求解快了 506 倍）。

四个分解对应的 API 与用途：

| 分解 | scipy 入口 | 返回什么 | 直接用途 | 前提 |
|------|-----------|---------|---------|------|
| LU | `la.lu(A)` / `la.lu_factor(A)` | `P, L, U` / `(lu, piv)` | 一般方阵求解、理解 `solve` | 需要选主元 |
| Cholesky | `la.cholesky(A)` / `la.cho_factor(A)` | 下（或上）三角 $L$ | 对称正定系统，成本减半 | **必须对称正定** |
| QR | `la.qr(A, mode="economic")` | 正交 $Q$、上三角 $R$ | 最小二乘、正交化 | 任何矩阵 |
| SVD | `la.svd(A)` | $U, s, V^{\top}$ | 秩、条件数、伪逆、截断 | 任何矩阵 |

**Cholesky 的第一价值是当诊断器用。** 它只对对称正定矩阵成立，所以它的报错本身就是结论：

```python
>>> S = np.array([[4., 1.],
...               [1., 3.]])
>>> la.cholesky(S, lower=True)
array([[2.       , 0.       ],
       [0.5      , 1.6583124]])
>>> la.cholesky(S, lower=False)           # lower=False 返回上三角
array([[2.       , 0.5      ],
       [0.       , 1.6583124]])

>>> bad = np.array([[1., 2.],
...                 [2., 1.]])
>>> np.linalg.eigvalsh(bad)               # 特征值有负 → 不是正定
array([-1.,  3.])
>>> la.cholesky(bad)
LinAlgError: Internal potrf return info = [2] for slices [0].
```

`potrf` 是 LAPACK 里 Cholesky 分解的例程名，`info = [2]` 表示"第 2 个主元非正"。**拿到这个报错不要急着换求解器**——它告诉你的是"模型不满足前提"，例如能量矩阵出现了负刚度、协方差矩阵因为数值误差失去了半正定性。这时该修的是模型或加一点对角正则化（`A + εI`），而不是改用 LU 把问题藏起来。

**QR 用 `mode="economic"`。** 默认的"完整" QR 会返回一个 $m \times m$ 的 $Q$，而最小二乘只需要前 $n$ 列：

```python
>>> X = np.random.default_rng(0).normal(size=(100, 4))
>>> Q1, R1 = la.qr(X)                     # 完整
>>> Q1.shape, R1.shape
((100, 100), (100, 4))
>>> Q2, R2 = la.qr(X, mode="economic")    # 经济型
>>> Q2.shape, R2.shape
((100, 4), (4, 4))
```

从 $(100,100)$ 降到 $(100,4)$，省掉的是 96 列**完全没用**的正交基。数据量大时这不是小钱。

**SVD 是唯一"什么都能干"的分解**，代价是慢（约 LU 的 5–10 倍）。它的奇异值同时给出三件事：

```python
>>> rng = np.random.default_rng(3)
>>> M = rng.normal(size=(8, 5)) @ np.diag([10., 1., 0.1, 1e-6, 1e-14]) @ rng.normal(size=(5, 5))
>>> s = la.svd(M, compute_uv=False)
>>> np.array2string(s, precision=4)
'[3.3325e+01 8.7319e+00 6.4785e-02 1.8645e-06 7.4799e-14]'
>>> s[0] / s[-1]                          # 条件数
445519796779600.6
>>> np.linalg.cond(M)                     # 与 np.linalg.cond 一致（末位不同）
445636911559124.0
```

**奇异值 → 条件数**（$\sigma_{\max}/\sigma_{\min}$）与 **奇异值 → 秩**（有几个显著大于零）。后者的麻烦在于"显著"是个判断，而 `matrix_rank` 的默认容差有自己的想法：

```python
>>> max(M.shape) * np.finfo(float).eps * s[0]     # matrix_rank 的默认容差
5.919639802623909e-14
>>> s[-1]                                          # 最小的奇异值
7.479939107636664e-14
>>> np.linalg.matrix_rank(M)                       # 刚好越过容差
5
>>> np.linalg.matrix_rank(M, tol=1e-6)             # 稍严一点
4
```

最小的奇异值 $7.48\times10^{-14}$ 只比容差 $5.92\times10^{-14}$ 大 26%，于是"这个矩阵秩是 4 还是 5"变成了一个**由机器精度决定的掷硬币**。

> **⚠️ 陷阱**：**不要用 `matrix_rank` 的默认容差做决策**。矩阵秩在浮点里不是良定义的整数，而是一个随容差连续变化的量。凡是"秩决定下一步做什么"的逻辑（要不要截断、要不要加正则化、能不能求逆），都必须**显式写出容差并说明理由**。正确的问法不是"它的秩是几"，而是"我准备把哪些奇异值当成零"。

同样的道理体现在 `pinv` 上——伪逆把小于容差的奇异值直接倒掉，容差取多小，`pinv` 的范数就能涨多大：

```python
>>> np.linalg.norm(np.linalg.pinv(M))              # 默认 rcond≈1e-15，把 7.5e-14 也保留了
1.337e+13
>>> np.linalg.norm(np.linalg.pinv(M, rcond=1e-10)) # 显式截断
5.363e+05
```

手动截断，能同时看到"稳健性"与"拟合能力"的交换：

| 截断阈值 | 保留的奇异值个数 | $\lVert A^{+} \rVert$ | $\lVert M A^{+} M - M \rVert$ |
|---------|---------------|---------------------|---------------------------|
| $10^{-6}$ | 3 | 15.4 | 1.9e-06 |
| $10^{-10}$ | 4 | 5.4e+05 | 3.5e-09 |

阈值从 $10^{-6}$ 放松到 $10^{-10}$，重构误差从 $1.9\times10^{-6}$ 降到 $3.5\times10^{-9}$（拟合更好了），但伪逆的范数涨了 **35000 倍**（对扰动更敏感了）。**这就是正则化的本质：用一点拟合精度换一点稳定性。** 5.2.5 会把这条曲线画完整。

> **实战建议**：选择分解的决策顺序是——① 对称正定吗？是则 Cholesky，结束；② 需要最小二乘吗？是则 QR 或 SVD；③ 需要秩/条件数/伪逆吗？是则只能 SVD；④ 以上都不是，才用 LU。**先问结构，再选算法**，不要一律 `solve` 了事，也不要一律上 SVD（它贵得多）。

### 5.2.5 方程数不等于未知数：最小二乘四兄弟

到目前为此，$A$ 都是方阵且满秩。现实中更常见的是另外两种：

| 情形 | 规模关系 | 数学上 | 求解入口 |
|------|---------|--------|---------|
| 恰定 | $m = n$ 且满秩 | 唯一解 | `la.solve` |
| 超定 | $m > n$ | 一般无精确解，退而求最小二乘解 | `la.lstsq`、`la.lsq_linear`、`optimize.nnls` |
| 欠定 | $m < n$ | 无穷多解，选最小范数解 | `la.lstsq`、`np.linalg.pinv` |

`lstsq` 家族的四个成员各管一件事：

| 入口 | 解决什么 | 返回什么 | 特别之处 |
|------|---------|---------|---------|
| `la.lstsq(A, b)` | 一般最小二乘 | **普通 4 元组** `(x, residues, rank, s)` | 默认 `lapack_driver='gelsd'`（基于 SVD，最稳） |
| `la.lsq_linear(A, b, bounds=...)` | 变量带上下界的最小二乘 | `OptimizeResult`（有命名属性） | 界是硬约束 |
| `optimize.nnls(A, b)` | 系数必须非负 | `(x, rnorm)` | 专用算法，比 `lsq_linear` 更聚焦 |
| `la.pinv(A)` / `np.linalg.pinv` | 需要矩阵形式的伪逆 | 矩阵 | 5.2.4 讲过容差问题 |

从最标准的一步开始：给 40 个点拟合一个三次多项式。设计矩阵用 `np.vander` 生成（`increasing=True` 表示列按 $1, x, x^2, x^3$ 排列）：

```python
>>> rng_fit = np.random.default_rng(42)               # 每个独立实验各用各的生成器
>>> x = np.linspace(-3, 3, 40)
>>> X = np.vander(x, 4, increasing=True)              # 40 × 4
>>> y = X @ np.array([1.5, -0.8, 0.4, 2.0]) + rng_fit.normal(0, 0.5, x.size)
>>> np.linalg.cond(X)
16.93220176956968
>>> x_hat, residues, rank, sv = la.lstsq(X, y)
>>> x_hat
array([ 1.57912429, -0.73694535,  0.38097821,  1.99345361])   # 真值 [1.5, -0.8, 0.4, 2.0]
>>> rank, np.sqrt(residues / (x.size - 4))            # 有效秩；残差均方根
(4, 0.4221995959557623)
```

系数的估计离真值都不远，残差均方根 0.4222 与我们注入的噪声水平 0.5 同量级——拟合合理。

> **⚠️ 陷阱（本章最安静的一个）**：`la.lstsq` 返回的是**普通元组**，不是带字段名的结果对象。`res.x`、`res.rank`、`res.s` 全部不存在，写出来会在运行时才炸。更危险的是第三项 `residues` 的类型与含义会随情形变化：

| 情形 | `scipy.linalg.lstsq` 的 `residues` | `numpy.linalg.lstsq` 的 `residuals` |
|------|----------------------------------|-----------------------------------|
| $m > n$ 且满秩，`b` 是一维 | **0 维数组**（不是浮点数，`res[0]` 会报错） | `(1,)` 数组 |
| 秩亏（`rank < n`），driver 为 `gelsd`/`gelss` | **`nan`** | 空数组 `[]` |
| driver 为 `gelsy`，或 $m \le n$ | 空数组 `(0,)` | 空数组 `[]` |

也就是说，**秩亏时 scipy 给你一个 `nan` 而不报错**。如果你写了 `if residues > tol: 认为拟合不好`，秩亏情形下这个判断会静默失效（`nan` 与任何数比较都是 `False`）。这个行为在 scipy 与 numpy 之间不一致（numpy 返回空数组），所以**跨库比较结果时要先看 `rank`，再看 `residues`。**

```python
>>> X2 = np.column_stack([x, 2*x, np.ones_like(x)])   # 第 2 列是第 1 列的 2 倍
>>> b, residues, rank, sv = la.lstsq(X2, y)
>>> rank, residues
(2, nan)                                              # ⚠️ 不报错，给 nan
>>> np.linalg.lstsq(X2, y, rcond=None)[1]             # numpy 的对照：空数组
array([], dtype=float64)
```

秩亏时 scipy 仍然返回了一个可用的解，而且这个解有明确含义——**最小范数解**。验证方法：解应当与零空间正交，且任何"解 + 零空间分量"的范数都更大：

```python
>>> b, residues, rank, _ = la.lstsq(X2, y)
>>> b
array([2.1140602 , 4.22812039, 2.78067096])
>>> _, s, Vt = la.svd(X2, full_matrices=False)
>>> s
array([2.51151196e+01, 6.32455532e+00, 1.68377519e-15])   # 第三个相对 25 就是 0 → 一维零空间
>>> v_null = Vt[2]
>>> b @ v_null                                        # 解与零空间正交
1.2503226190367706e-16
>>> np.linalg.norm(b + v_null) > np.linalg.norm(b)    # 加上零空间分量后范数变大
True
```

> **实战建议**：遇到秩亏，**不要**用 `lstsq` 默默拿一个最小范数解就完事。秩亏几乎总是信号——要么设计矩阵里有重复列（如上面的 $x$ 与 $2x$），要么变量尺度差了几个数量级，要么你需要的正是正则化。**先找出为什么秩亏，再决定用什么解。**

**接下来是本小节最重要的对照：永远不要用正规方程解最小二乘。**

所谓正规方程是 $\hat{x} = (A^{\top}A)^{-1}A^{\top}b$，也就是把最小二乘问题化成一个方阵方程组，然后 `solve` 它。它在数学上完全正确，在数值上完全不可接受，原因只有一句话：$\mathrm{cond}(A^{\top}A) = \mathrm{cond}(A)^2$（`ds-00` 0.2.9）。而 5.2.3 已经告诉我们，条件数每涨 10 倍就多丢一位有效数字。

用受控条件数的设计矩阵做一个干净的对照（$60 \times 12$，奇异值按对数均匀分布，真解全 1）：

```python
>>> rng_c = np.random.default_rng(20)
>>> U, _ = np.linalg.qr(rng_c.normal(size=(60, 12)))
>>> V, _ = np.linalg.qr(rng_c.normal(size=(12, 12)))
>>> def design(cond):
...     s = np.logspace(0, -np.log10(cond), 12)
...     return U @ np.diag(s) @ V.T
>>> for target in [1e6, 1e8, 1e10, 1e12]:
...     Xc = design(target)
...     yc = Xc @ np.ones(12)
...     b_svd = la.lstsq(Xc, yc)[0]                       # gelsd：SVD 路径
...     b_qr  = la.lstsq(Xc, yc, lapack_driver="gelsy")[0]  # gelsy：QR 路径
...     b_ne  = np.linalg.solve(Xc.T @ Xc, Xc.T @ yc)      # 正规方程
...     print(f"cond={target:.0e} svd={np.abs(b_svd-1).max():.2e} "
...           f"qr={np.abs(b_qr-1).max():.2e} 正规方程={np.abs(b_ne-1).max():.2e}")
```

| $\mathrm{cond}(X)$ | $\mathrm{cond}(X^{\top}X)$ | `lstsq`（gelsd/SVD） | `lstsq`（gelsy/QR） | 正规方程 | 正规方程/lstsq |
|---|---|---|---|---|---|
| $10^{6}$ | $10^{12}$ | 1.3e-11 | 1.9e-11 | 5.6e-05 | 4.3e+06 |
| $10^{8}$ | $10^{16}$ | 4.7e-11 | 1.8e-09 | **2.99e-01** | **6.4e+09** |
| $10^{10}$ | $10^{20}$ | 1.6e-07 | 1.9e-08 | 4.80e+00 | 3.0e+07 |
| $10^{12}$ | $10^{24}$ | 6.8e-06 | 4.4e-06 | 2.90e+00 | 4.2e+05 |

$\mathrm{cond}(X) = 10^{8}$ 那一行是最有说服力的：真解是 1，正规方程给出的答案误差 **0.299**（等于错了 30%），而 SVD 路径的误差是 **$4.7\times10^{-11}$**——**差了 64 亿倍**。同一份数据、同一个数学问题，只因为多算了一步 $X^{\top}X$，精度就整体蒸发了。

顺带一个细节：$X^{\top}X$ 的条件数达到 $10^{16}$ 后，正规方程的结果已经和真值毫无关系，再往上加只会得到"另一个随机数"。这也是为什么本章反复强调**报告要带条件数**：只报"我算了最小二乘"，读者无法判断这个结果是不是噪声。

**当精度不够时，正则化是比换算法更有效的武器。** 前面几行说明：条件数一旦进入 $10^{16}$ 以上，任何直接法都救不回来。但很多时候问题不需要"精确解"——只需要一个稳定、可解释的近似。这时加一个岭（ridge）惩罚项 $\lambda \lVert x \rVert^2$，把正规方程改成

$$(X^{\top}X + \lambda I)\,\hat{x}_\lambda = X^{\top}y$$

用它处理一个病态的高次多项式拟合（$[0,1]$ 上 30 个点、8 个基函数、真系数全 1、噪声 $10^{-4}$）：

```python
>>> t = np.linspace(0, 1, 30)
>>> Xp = np.vander(t, 8, increasing=True)
>>> rng_r = np.random.default_rng(11)
>>> yp = Xp @ np.ones(8) + rng_r.normal(0, 1e-4, t.size)
>>> np.linalg.cond(Xp), np.linalg.cond(Xp.T @ Xp)
(106441.2408426494, 11329736967.73511)
```

| $\lambda$ | $\lVert \hat{x}_\lambda \rVert$ | $\max_i \lvert \hat{x}_{\lambda,i} - 1 \rvert$ | 相对无正则的改善 | 残差 $\lVert X\hat{x} - y \rVert$ |
|---|---|---|---|---|
| 无正则 | 3.0881 | 8.51e-01 | — | 3.933e-04 |
| $10^{-10}$ | 3.0777 | 8.33e-01 | 1× | 3.934e-04 |
| $10^{-8}$ | 2.8557 | 2.68e-01 | 3× | 3.976e-04 |
| $10^{-6}$ | 2.8285 | 1.14e-02 | 74× | 4.025e-04 |
| $\mathbf{10^{-4}}$ | **2.8284** | **1.91e-03** | **445×** | 4.119e-04 |
| $10^{-3}$ | 2.8282 | 3.10e-03 | 275× | 8.948e-04 |
| $10^{-2}$ | 2.8265 | 1.49e-02 | 57× | 7.324e-03 |

这张表里有三个必须读出来的信息：

1. **$\lambda = 10^{-4}$ 是甜点**：系数误差从 0.851 降到 0.0019（**改善 445 倍**），而残差只从 $3.933\times10^{-4}$ 涨到 $4.119\times10^{-4}$（**涨了 4.7%**）。**用 4.7% 的拟合能力换 445 倍的参数准确度**，这笔交易在任何场景下都划算。
2. **$\lambda$ 太小没用，太大也有害**。$10^{-10}$ 几乎等于没加（改善 1×）；$10^{-2}$ 时残差涨了 19 倍，系数误差反而回升——惩罚项开始主导目标函数了。这就是偏差-方差权衡在数值上的具体形状。
3. **无正则解与真值的差距（0.85）几乎等于真值本身（1）**。这说明病态问题上的最小二乘解**本质上不可信**，而不是"稍微差一点"。看到 $\mathrm{cond}(X^{\top}X) \ge 10^{10}$ 就该主动考虑正则化，而不是等解出来发现不对。

> **机制洞察**：正则化不是在"作弊"或"降低标准"，它是在**引入一条真实存在的信息**——"系数不应该太大"。这条信息来自建模者对问题的了解，与数据无关。当数据本身不足（秩亏、条件数过大）时，先验信息是唯一能补上缺口的东西。第 4 章的贝叶斯观点会给出同一个结论的另一种语言：岭回归等价于给系数加一个正态先验。

**带约束的最小二乘**是另一类常见需求。最典型的是"系数必须非负"（物理量、浓度、比例）：

```python
>>> from scipy.optimize import nnls, lsq_linear
>>> rng_nn = np.random.default_rng(7)
>>> y_nn = X[:, 0] * 1.5 + X[:, 1] * (-0.8) + rng_nn.normal(0, 0.3, x.size)
>>> la.lstsq(X[:, :2], y_nn)[0]                 # 无约束
array([ 1.38144445, -0.81079411])
>>> nnls(X[:, :2], y_nn)[0]                     # 非负约束
array([1.38144445, 0.        ])
>>> lsq_linear(X[:, :2], y_nn, bounds=([0, 0], [np.inf, np.inf])).x
array([1.38144445e+00, 4.39532500e-20])
```

三兄弟的分工很清楚：`lstsq` 无约束、最快；`nnls` 只管非负、专用算法最稳；`lsq_linear` 管任意上下界，最通用也最慢。**注意 `nnls` 给出的是精确的 0，而 `lsq_linear` 给出 $4.4\times10^{-20}$**——后者是内点式算法的正常表现（不会精确落在边界上），比较结果时要用 `np.allclose` 而不是 `==`。另外 `nnls` 把负系数压到 0 而不是取绝对值，这是非负约束下最优解落在边界上的正确行为，但会让人误以为"这个方法把变量丢掉了"。

### 5.2.6 实战：一个多元线性方程组的完整求解与验算

把本节的所有工具串成一条流水线。场景取**投入产出模型**（Leontief 模型），它是最经典的多部门线性方程组，题面也足够接近真实赛题：

> 某地区有三个生产部门，直接消耗系数矩阵 $A$ 表示"每生产 1 单位总产出，需要消耗其他部门多少产品"：
>
> $$A = \begin{bmatrix} 0.15 & 0.20 & 0.10 \\ 0.25 & 0.10 & 0.20 \\ 0.10 & 0.15 & 0.05 \end{bmatrix}$$
>
> 三个部门的最终需求（消费+出口+投资）分别是 100、80、60。求各部门应当安排多少总产出？

**第 1 步：写下来。** 总产出 $x$ 要同时满足中间消耗与最终需求，即 $x = Ax + d$，整理得

$$(I - A)\,x = d$$

这就是本章要解的线性方程组。

**第 2 步：问可解。** 先做三件事——看结构、看行列式与特征值、看条件数：

```python
>>> A = np.array([[0.15, 0.20, 0.10],
...               [0.25, 0.10, 0.20],
...               [0.10, 0.15, 0.05]])
>>> d = np.array([100., 80., 60.])
>>> M = np.eye(3) - A
>>> A.sum(axis=0)                         # 列和：每单位总产出需要的中间投入合计
array([0.5 , 0.45, 0.35])
>>> max(abs(np.linalg.eigvals(A)))        # A 的谱半径
0.44347480261913674
>>> np.linalg.det(M), np.linalg.cond(M)
(0.637, 2.0502260661377405)
```

三条判断：列和全部小于 1（每个部门都有净产出），谱半径 $0.44 < 1$（经济是"生产的"，$(I-A)^{-1}$ 存在且非负），条件数 2.05（极其良态，可以放心用双精度）。**这一步花的时间不到十秒，却排除了后面 90% 的返工。**

**第 3 步：求解。** 矩阵不对称，用通用的 `solve`：

```python
>>> x = la.solve(M, d)
>>> x
array([167.50392465, 158.94819466, 105.88697017])
```

**第 4 步：验证。** 三行检查，缺一不可：

```python
>>> np.abs(M @ x - d).max()               # ① 残差：方程真的满足吗
1.4210854715202004e-14
>>> np.abs(A @ x + d - x).max()           # ② 原始经济含义：中间消耗 + 最终需求 = 总产出
2.8421709430404007e-14
>>> (x > 0).all()                         # ③ 物理合理性：总产出必须为正
True
```

三条全部通过。第 ③ 条常被忽略，却是最重要的一条——**一个数学上正确、经济上无意义的解，不能算答案**。马上会看到反例。

**第 5 步：看敏感性。** 系数 $A$ 是统计出来的，一定有误差。让 $A$ 的每个元素加 2% 的相对扰动，跑 2000 次看 $x$ 的分布：

```python
>>> rng_ab = np.random.default_rng(5)
>>> xs = np.array([la.solve(np.eye(3) - A * (1 + 0.02 * rng_ab.normal(size=A.shape)), d)
...                for _ in range(2000)])
>>> xs.mean(axis=0)
array([167.53696734, 158.98836768, 105.93562829])
>>> xs.std(axis=0) / x * 100              # 相对标准差（%）
array([0.6720893 , 0.81532695, 0.68561939])
```

作为对照，只扰动最终需求 $d$（同样 2%）得到相对标准差 `[1.63801991, 1.37213368, 1.37197878]`——**大约是前者的两倍**。这个不对称很有意思：$d$ 的扰动直接进入方程右边，而 $A$ 的扰动要经过 $(I-A)^{-1}$ 的"平滑"才传到 $x$。这也说明**提高 $d$ 的统计精度比精修 $A$ 更划算**。注意这一步已经是 5.10 的内容（不确定性量化）的预告——本章把它作为"验证"的一个自然延伸。

**现在看模型不成立时会发生什么。** 如果历史数据显示部门 1 的中间投入占比上升，把 $A$ 换成谱半径略大于 1 的版本：

```python
>>> A_bad = np.array([[0.30, 0.40, 0.30],
...                   [0.40, 0.30, 0.40],
...                   [0.30, 0.40, 0.30]])
>>> max(abs(np.linalg.eigvals(A_bad)))    # 谱半径 > 1
1.0352...
>>> la.solve(np.eye(3) - A_bad, d)
array([-2180., -2400., -2220.])
>>> (la.solve(np.eye(3) - A_bad, d) > 0).all()
False                                     # ❌ 总产出为负，经济上无意义
```

而如果把谱半径调到**正好等于 1**：

```python
>>> A_sing = np.array([[0.20, 0.40, 0.40],
...                    [0.40, 0.20, 0.40],
...                    [0.40, 0.40, 0.20]])
>>> max(abs(np.linalg.eigvals(A_sing)))   # 恰好 1.0（浮点上是 0.9999999999999999）
0.9999999999999999
>>> la.solve(np.eye(3) - A_sing, d)
LinAlgError: A singular matrix detected: slice(s) [0] are singular.
```

同一套代码，三种结局：良态可解、解出负数、直接奇异。**差别全在模型参数里，不在代码里。** 这正是四步骨架第 2 步（"问可解"）存在的理由——它检查的不是"程序会不会报错"，而是"这个模型配不配得到一个有意义的答案"。

> **⚠️ 陷阱**：谱半径接近 1 时条件数不大却结果巨大。取 $A$ 的谱半径 $0.9941$（列和 0.99）：$\mathrm{cond}(I-A) = 5.83$ 看着很正常，但解出来的总产出是 `[13000, 16000, 11000]`——比基准情形大 **80 倍**。**经济含义是"需求的每一分增长都被无限放大"，物理上不可持续。** 这类问题的危险在于既不报错、条件数也不高，只有回到量纲与常识才能发现。这就是 5.1.5 第三条纪律（量纲与尺度先行）要防的事。

> **实战建议**：把上面的流水线固化成一个函数，作为本节的可交付模板：

```python
def solve_linear_model(M, d, name="模型", positive=True):
    """解 M x = d，跑完四步骨架并返回 (x, 报告)。"""
    M = np.asarray(M, dtype=float); d = np.asarray(d, dtype=float)
    report = {}
    # 第 2 步：可解性与良态性
    report["cond"] = np.linalg.cond(M)
    report["suspect"] = report["cond"] > 1e10
    x = la.solve(M, d)
    # 第 4 步：三类验证
    report["residual"] = np.abs(M @ x - d).max()
    report["rel_residual"] = report["residual"] / max(np.abs(d).max(), 1.0)
    report["positive_ok"] = bool((x > 0).all()) if positive else None
    report["digits_left"] = np.finfo(float).precision - np.log10(max(report["cond"], 1.0))
    # 报警
    if report["suspect"]:
        print(f"[{name}] cond={report['cond']:.1e}，仅剩 {report['digits_left']:.1f} 位有效数字")
    if report["positive_ok"] is False:
        print(f"[{name}] ⚠️ 解出现非正分量，模型可能不成立：min(x)={x.min():.3g}")
    return x, report
```

```python
>>> x, rep = solve_linear_model(M, d, "投入产出")
>>> x, rep["positive_ok"]
(array([167.503925, 158.948195, 105.886970]), True)
>>> x, rep = solve_linear_model(np.eye(3) - A_bad, d, "投入产出(不良)")
[投入产出(不良)] ⚠️ 解出现非正分量，模型可能不成立：min(x)=-2400
```

## 5.3 稀疏矩阵与大系统

5.2 的所有方法都建立在一个隐含假设上：矩阵存在内存里，每个元素都能随机访问。当未知数涨到一万、十万时这个假设就崩了——一个 $100000 \times 100000$ 的双精度稠密矩阵要 **74.5 GB**，而这还只是"存下来"，没算分解时要额外申请的空间。

本节讲的是同一件事在"矩阵几乎全是零"时的做法。跨过这道坎，换来的是数量级的能力提升；但它也带来一套全新的失败模式：**稀疏求解器的耗时不由 $n$ 决定，而由"填充"决定**——这个量在求解之前看不见。

### 5.3.1 什么时候值得稀疏：两条判据

第一条判据是**内存**，它是确定性的、先验可以算出来的。一个 $n \times n$ 的 `csr_array` 需要存 `data`（非零值）、`indices`（列号）、`indptr`（每行起始位置）三个数组，总量约为 $(\text{nnz} \times 12 + n \times 4)$ 字节（`data` 与 `indices` 各 8/4 字节，`indptr` 4 字节）。拿一维 Laplacian（`ds-00` 0.2.7 那个三对角矩阵的放大版，每行只有 2–3 个非零）实测：

```python
>>> from scipy.sparse import diags_array
>>> for n in [1000, 10000, 100000]:
...     L = diags_array([-np.ones(n-1), 2*np.ones(n), -np.ones(n-1)],
...                     offsets=[-1, 0, 1], shape=(n, n), format="csr")
...     dense_gb = n * n * 8 / 1024**3
...     sparse_kb = (L.data.nbytes + L.indices.nbytes + L.indptr.nbytes) / 1024
...     print(f"n={n:6d} nnz={L.nnz:6d} 稀疏 {sparse_kb:9.1f} KB | 稠密 {dense_gb:8.4f} GB | 省 {n*n*8/(sparse_kb*1024):8.0f} 倍")
n=  1000 nnz=  2998 稀疏      39.0 KB | 稠密   0.0075 GB | 省      200 倍
n= 10000 nnz= 29998 稀疏     390.6 KB | 稠密   0.7451 GB | 省     2000 倍
n=100000 nnz=299998 稀疏    3906.2 KB | 稠密  74.5058 GB | 省    20000 倍
```

只要稀疏度保持恒定（这里是每行 3 个非零），**内存优势随 $n$ 线性增长**。$n = 100000$ 时稠密矩阵已经超出单机内存，稀疏矩阵只占 3.8 MB。

第二条判据是**耗时**，它就没那么干净了。稠密直接法是 $O(n^3)$，稀疏直接法的成本取决于**分解过程中新产生的非零元**（填充，fill-in）。对于一维 Laplacian，填充不会爆炸，于是差距很大：

```python
>>> N = 2000
>>> L = diags_array([-np.ones(N-1), 2*np.ones(N), -np.ones(N-1)],
...                 offsets=[-1, 0, 1], shape=(N, N), format="csr")
>>> Ld = L.toarray()
>>> # 稀疏度：nnz 只占全部元素的 0.15%
```

| | 稠密 `la.solve` | 稀疏 `spsolve` | 比值 |
|---|---|---|---|
| N = 2000（nnz 0.150%） | 22.7 ms | 0.278 ms | **82×** |

解也一致（最大差 $1.8\times10^{-12}$）。但**别把这个倍数当成普遍规律**——换成二维网格，优势会缩水甚至消失：

| | 稠密 `la.solve` | 稀疏 `spsolve` | 比值 |
|---|---|---|---|
| 二维网格 $m = 30$（$n = 900$，nnz 0.55%） | 5.9 ms | 1.67 ms | 3.5× |

二维问题的填充比一维严重得多（5.3.3 会量化），$n$ 又只有 900，稀疏求解器的固定开销开始显形。**"稀疏一定更快"是错的，"稀疏在 $n$ 大且填充可控时更快"才对。**

> **实战建议**：判断要不要用稀疏矩阵，按这个顺序：① 先算 `nnz / n²`，超过 **20%** 基本不用考虑（转换与索引开销吃掉收益）；② 再估内存，稠密版超过可用内存的 1/3 就必须换；③ 最后才看耗时——**先用 `timeit` 量一次，不要凭直觉**。本书的立场是：内存是第一判据，因为它是硬的；耗时是第二判据，因为它依赖具体结构。

### 5.3.2 存储格式与构造

`scipy.sparse` 提供多种格式，每种针对不同操作优化。选错了不会报错，只是慢：

| 格式 | 擅长 | 不擅长 | 什么时候用 |
|------|------|--------|-----------|
| `coo_array` | 快速构造（三元组） | 算术运算、索引 | **组装阶段**：从边列表/三元组建矩阵 |
| `csr_array` | 行切片、矩阵向量乘 | 列切片、改结构 | 迭代法、`csgraph` 的输入 |
| `csc_array` | 列切片、**多数直接分解** | 行切片 | `spsolve`、`splu` 的输入 |
| `dia_array` | 对角结构、算术 | 一般构造 | 带形/三对角矩阵 |
| `lil_array` | 逐个元素赋值 | 一切运算 | 少量元素的增量修改 |

日常最常用的是 `coo → csr` 的两步走：用 `coo` 快速组装，转成 `csr` 再算：

```python
>>> from scipy.sparse import coo_array
>>> rng = np.random.default_rng(0)
>>> rows = rng.integers(0, 1000, 20000)
>>> cols = rng.integers(0, 1000, 20000)
>>> vals = rng.normal(size=20000)
>>> C = coo_array((vals, (rows, cols)), shape=(1000, 1000))
>>> C.nnz, C.tocsr().nnz
(20000, 19799)
```

`nnz` 从 20000 降到 19799——**重复的 $(i,j)$ 位置在转换时被自动求和**，这是 `coo` 的一个重要语义（也正是有限元组装想要的行为）。

**带形与网格结构用 `diags_array` 或 `kron`。** `diags_array` 的长度规则很容易踩坑：

```python
>>> from scipy.sparse import diags_array
>>> diags_array([np.ones(3), np.ones(4), np.ones(3)],
...             offsets=[-1, 0, 1], shape=(4, 4)).toarray()
array([[1., 1., 0., 0.],
       [1., 1., 1., 0.],
       [0., 1., 1., 1.],
       [0., 0., 1., 1.]])
```

三条对角线的长度分别是 3、4、3：**每条的长度必须等于该偏移上对角线的真实长度，不含填充**。offset $-1$（下对角）在 $4\times4$ 上有 3 个元素，offset $0$（主对角）有 4 个，offset $+1$（上对角）有 3 个。这是 `diags_array`（1.11 起）与旧 `dia_array` 的关键差别——旧接口要求你**自己补零填充**。搞错长度不会静默出错，而是抛 `ValueError: Diagonal length ... does not agree with array size`，但错误信息里的偏移编号容易让人看错。

二维网格的 Laplacian 可以用 Kronecker 积一行搭出来：

```python
>>> from scipy.sparse import kron, eye
>>> I4 = eye(4, format="csr")
>>> T1 = diags_array([-np.ones(3), 2*np.ones(4), -np.ones(3)],
...                  offsets=[-1, 0, 1], shape=(4, 4), format="csr")
>>> K = kron(I4, T1) + kron(T1, I4)       # 二维五点差分
>>> K.shape, K.nnz, (abs(K - K.T)).nnz
((16, 16), 160, 0)                        # 对称
```

`kron(I, T) + kron(T, I)` 是"网格上的差分算子"的标准写法，从 4×4 直接跳到一维有 16 个未知数、二维有 256 个，不用改公式。

> **⚠️ 陷阱：`csr_array` 与 `csr_matrix` 是两个东西。** 1.18 里两者都能用，但 `repr`、`*` 的语义、索引返回类型都不同：

```python
>>> from scipy.sparse import csr_array, csr_matrix
>>> print(repr(csr_array([[1, 0], [0, 2]])))
<Compressed Sparse Row sparse array of dtype 'int64'
	with 2 stored elements and shape (2, 2)>
>>> print(repr(csr_matrix([[1, 0], [0, 2]])))
<Compressed Sparse Row sparse matrix of dtype 'int64'
	with 2 stored elements and shape (2, 2)>
```

`*` 在 `matrix` 上是矩阵乘法，在 `array` 上是逐元素乘——和 `ds-01` 里 `np.matrix` 的老问题同源。**新代码一律用 `*_array`**：scipy 1.11 起把 array 定为推荐接口，`matrix` 系列属于兼容层。

### 5.3.3 直接法：填充才是成本

`sparse.linalg` 的两个直接法入口：

| 入口 | 用法 | 什么时候用 |
|------|------|-----------|
| `spsolve(A, b)` | 一次调用解一个右端项 | 只解一次 |
| `splu(A)` | 返回可复用的分解对象 `lu`，再 `lu.solve(b)` | **同一个矩阵要解很多次** |

后者常常被忽略，代价却很大。取 $N = 1000$ 的一维 Laplacian，解 20 个右端项：

```python
>>> from scipy.sparse.linalg import splu, spsolve
>>> lu = splu(L.tocsc())
>>> # 20 次独立求解 vs 一次分解 + 20 次回代
```

| 做法 | 耗时 | 相对加速 |
|------|------|---------|
| 20 次 `spsolve`（每次都重新分解） | 5.81 ms | 基准 |
| `splu` 一次，`lu.solve` 逐列 20 次 | 0.47 ms | 12× |
| `splu` 一次，`lu.solve(B)` 一次传整个矩阵 | **0.20 ms** | **29×** |

**分解一次、回代多次**是稀疏直接法最重要的用法。它出现在所有"时间步进"的场景里：热传导每一时刻解同一个矩阵、参数扫描反复解同一个结构、迭代求解器里的预处理。

**填充**是稀疏直接法最核心的概念，也是耗时不可预测的根源。分解 $A = LU$ 时，$L$ 和 $U$ 中出现非零元的位置往往比 $A$ 多得多——原本的零被"填"上了。用二维网格实测（$m = 40$，$n = 1600$，原 `nnz = 7918`）：

```python
>>> for spec in ["NATURAL", "MMD_ATA", "MMD_AT_PLUS_A", "COLAMD"]:
...     f = splu(G, permc_spec=spec)
...     print(f"{spec:14s} L+U nnz={f.L.nnz + f.U.nnz:8d} 填充比 {(f.L.nnz + f.U.nnz)/G.nnz:6.2f}×")
NATURAL        L+U nnz=  128078 填充比  16.18×
MMD_ATA        L+U nnz=   75814 填充比   9.57×
MMD_AT_PLUS_A  L+U nnz=  44470 填充比   5.62×
COLAMD         L+U nnz=   76300 填充比   9.64×
```

四行之间**最好与最差相差 2.88 倍**，而它们做的是同一个数学分解——差别只在**行列重排**（求一个置换矩阵 $P$，让分解产生的填充尽量少）。$L+U$ 的规模直接决定内存与耗时，所以这个选择比"用哪个求解器"重要得多。

三条要点：

1. **默认的 `COLAMD` 不是永远最优**。本例里 `MMD_AT_PLUS_A` 的填充比默认值少 **42%**。默认值是为"典型"矩阵调的，遇到特殊结构该试。
2. **`NATURAL`（不重排）几乎总是最差**，16.18× 的填充比说明重排不是可选项。
3. **教科书里的"对称 RCM 重排能减少填充"在这个例子上不成立**。我实测把 `reverse_cuthill_mckee` 的置换手动作用到矩阵上再 `splu`，填充比反而从 9.64× 涨到 9.99×——因为 `splu` 默认已经用了 COLAMD，而 RCM 优化的是**带宽**，不是填充。**带宽小不等于填充少**，这两个目标在二维网格上会冲突。

> **机制洞察**：填充是**图的消元顺序**问题，不是矩阵的代数性质问题。把矩阵看作一张图（非零元是边），高斯消元每消掉一个顶点，它的邻居之间就被连上边——这些新边就是填充。于是"怎样消元让新边最少"变成了一个图论问题（最小度、嵌套剖分等启发式）。这也是为什么稀疏求解器的表现**取决于矩阵的稀疏模式而不只是 nnz**：两个 nnz 相同的矩阵，一个来自一维链、一个来自三维网格，耗时能差好几个数量级。

**奇异与格式问题上的行为差异**要记住，因为它们不一致：

```python
>>> from scipy.sparse import csc_array
>>> S = csc_array([[1., 2.], [2., 4.]])       # 奇异
>>> spsolve(S, [1., 2.])                       # ⚠️ 返回 nan，只发警告
array([nan, nan])
>>> # MatrixRankWarning: Matrix is exactly singular
>>> splu(S)
RuntimeError: Factor is exactly singular
```

**`spsolve` 返回 `nan`，`splu` 抛异常**——同一件事两种行为。写管道时如果只处理异常，`nan` 会一路传播到结果里。另一个：

```python
>>> from scipy.sparse.linalg import splu
>>> from scipy.sparse import csr_array
>>> splu(csr_array([[4., 1.], [1., 3.]]))
SparseEfficiencyWarning: splu converted its input to CSC format
```

`SparseEfficiencyWarning` 不是错误，但它明确告诉你"我在偷偷做一次 $O(\text{nnz})$ 的格式转换"——在热循环里调用它会白白多花一倍时间。**构造时就指定 `format="csc"`。**

### 5.3.4 迭代法：什么时候它真的更快

`sparse.linalg` 提供了一整族 Krylov 方法：

| 方法 | 适用矩阵 | 备注 |
|------|---------|------|
| `cg` | **对称正定** | 最短递推，内存最省 |
| `minres` | 对称（可以不定） | |
| `gmres` / `lgmres` | 一般非对称 | 需要 `restart` 参数 |
| `bicgstab` | 一般非对称 | 每次迭代两次矩阵向量乘 |
| `lsqr` / `lsmr` | 最小二乘（长方形） | 等价于 `lstsq` 的迭代版 |

它们返回 `(x, info)`：**`info = 0` 才是收敛**，正数表示迭代次数超过了 `maxiter`，负数表示 breakdown。这个返回值必须检查——不检查就等于没做错误处理。

迭代法常被当成"稀疏问题的正解"，但实测会给出相反的结论。对 $N$ 从 500 到 8000 的一维 Laplacian（$\mathrm{cond}$ 从 $10^{5}$ 涨到 $1.6\times10^{6}$），用 `cg` 与 `spsolve` 对比：

```python
>>> cnt = [0]
>>> x, info = cg(A, b, rtol=1e-10, callback=lambda xk: cnt.__setitem__(0, cnt[0] + 1))
```

| $N$ | CG 迭代次数 | CG 耗时 | `spsolve` 耗时 | CG 慢 | CG 的前向误差 |
|-----|-----------|--------|--------------|-------|-------------|
| 500 | 250 | 9.8 ms | 0.23 ms | 42× | 2.5e-09 |
| 2000 | 1000 | 39.0 ms | 0.63 ms | 62× | 2.6e-07 |
| 8000 | 4000 | 123.0 ms | 1.60 ms | **77×** | **4.5e-05** |

三件事同时发生，每一件都值得记下来：

1. **迭代次数随 $N$ 线性增长**（250 → 1000 → 4000，正好是 $N/2$）。这是 CG 在一维 Laplacian 上的已知行为：迭代次数 $\sim\sqrt{\mathrm{cond}}$，而这里 $\mathrm{cond} \sim N^2$，所以迭代次数 $\sim N$。而 `spsolve` 对这种窄带矩阵几乎是 $O(N)$ 的，于是**差距随规模扩大**（42× → 62× → 77×）。
2. **CG 比直接法慢一个数量级以上**。原因很朴素：每次迭代都要做一次稀疏矩阵向量乘（$O(\text{nnz})$），250 次就是 $250 \times O(\text{nnz})$；而直接法的填充很小，总工作量更低。
3. **CG 的前向误差随 $N$ 恶化**（$2.5\times10^{-9}$ → $4.5\times10^{-5}$）。它停在 `rtol=1e-10` 判据上，而这个判据约束的是**残差**不是误差——正是 5.2.3 那个"残差小 ≠ 误差小"在迭代法里的翻版。

那迭代法什么时候真的赢？**当直接法的填充爆炸时**。三维网格、非结构化有限元、图拉普拉斯这些问题上填充比可以到几百倍，稠密因子存不下；此时迭代法每步只需要原矩阵的 `nnz`，是唯一可行的选择。判断方法是先试 `splu`，看 `lu.L.nnz + lu.U.nnz` 与 `A.nnz` 的比值：

```python
>>> f = splu(A_csc)
>>> fill_ratio = (f.L.nnz + f.U.nnz) / A.nnz
>>> fill_ratio
```

**填充比低于 ~10 时直接法基本必胜；超过 ~50 就该考虑迭代法；超过 ~200 时往往别无选择。**

对非对称问题，`gmres` 是默认选择，注意 `restart` 参数（重启次数太少收敛慢，太大内存高）：

```python
>>> A_ns = diags_array([-np.ones(N-1), 3*np.ones(N), -0.5*np.ones(N-1)],
...                    offsets=[-1, 0, 1], shape=(N, N), format="csr")
>>> x, info = gmres(A_ns, b, rtol=1e-10, restart=50)
>>> info, np.abs(spsolve(A_ns.tocsc(), b) - x).max()
(0, 6.425523446651482e-10)
```

> **实战建议**：**先用直接法，再考虑迭代法**，不要反过来。理由：直接法一次成功、结果精确、`fill_ratio` 一算就知道该不该换；迭代法要选方法、调 `rtol`、定 `restart`、可能还要预处理，调参成本高得多。**迭代法是填充爆炸时的退路，不是默认选项。**

### 5.3.5 稀疏特征值与奇异值

需要**全部**特征值时用稠密 `eigh`；只需要**少数几个极端**特征值时用 `eigsh`（对称）或 `eigs`（一般）。它们用的是 Lanczos/Arnoldi 迭代，只做矩阵向量乘，不需要分解：

```python
>>> from scipy.sparse.linalg import eigsh
>>> N = 1000
>>> L1 = diags_array([-np.ones(N-1), 2*np.ones(N), -np.ones(N-1)],
...                  offsets=[-1, 0, 1], shape=(N, N), format="csr")
>>> w, v = eigsh(L1, k=3, which="SM")     # SM = smallest magnitude
>>> w
array([9.84988668e-06, 3.93994497e-05, 8.86483980e-05])
```

一维 Laplacian 的特征值有解析式 $\lambda_k = 2 - 2\cos(k\pi/(N+1))$，最小的是

```python
>>> 2 - 2*np.cos(np.pi/(N + 1))
9.849886676738251e-06                     # 与 eigsh 的第一个特征值一致
```

`which=` 参数决定要哪一端，这是稀疏特征值问题里最容易搞错的地方：`"SM"` 是最小幅度、`"LM"` 是最大幅度、`"SA"` 是最小代数值、`"LA"` 是最大代数值。**对不定矩阵 `"SM"` 与 `"SA"` 完全不同**，而且 `"SM"` 收敛最慢（本例 $k=3$ 用 `"SM"` 花 513 ms，`"LM"` 只要 382 ms，且规模越大差距越大）。

稀疏奇异值用 `svds`，只需求少数几个：

```python
>>> from scipy.sparse.linalg import svds
>>> M = np.random.default_rng(3).normal(size=(2000, 500))
>>> s = svds(M, k=3, return_singular_vectors=False)
>>> np.sort(s)[::-1]
array([66.83125895, 66.41568436, 66.00419264])
>>> np.linalg.svd(M, compute_uv=False)[:3]     # 稠密对照
array([66.83125895, 66.41568436, 66.00419264])
```

结果与稠密 SVD 逐位一致，而 `svds` 只做矩阵向量乘：这个 $2000 \times 500$ 的稠密矩阵上 `svds` 用 247 ms。矩阵再大十倍时稠密 SVD 就不可行了，而 `svds` 仍然可行——**这正是它在推荐系统（隐语义）、主成分分析、谱聚类里被使用的原因。**

### 5.3.6 决策树与陷阱

把本节收成一张可以照着走的表：

| 情形 | 做法 |
|------|------|
| $nnz/n^2 > 20\%$ | 用稠密 |
| 稠密版内存超过可用内存 1/3 | 必须稀疏 |
| 只解一次 | `spsolve` |
| 同一矩阵解多次 | `splu` 一次 + `lu.solve` 多次（实测 29×） |
| 需要一个矩阵的少数特征值/奇异值 | `eigsh` / `svds` |
| `fill_ratio < 10` | 直接法（`splu` / `spsolve`） |
| `fill_ratio > 50` | 试迭代法（`cg` 对称正定 / `gmres` 一般） |
| 对称正定且规模极大 | `cg` + 预处理 |
| 从三元组建矩阵 | `coo_array` → `tocsr()` |
| 从对角/网格建矩阵 | `diags_array`、`kron` |
| 需要反复改单个元素 | 先 `lil_array` 改，再转 `csr` |
| 热循环里调用 `splu`/`spsolve` | 构造时就给 `"csc"`，避免 `SparseEfficiencyWarning` |

**陷阱清单（本节）**：

1. `spsolve` 遇到奇异矩阵返回 `nan` 并只发 `MatrixRankWarning`，而 `splu` 抛 `RuntimeError`——两者行为不一致，`nan` 会静默传播。
2. `splu`/`spsolve` 收到非 CSC 输入会发 `SparseEfficiencyWarning` 并偷偷转换。
3. `diags_array` 的对角线长度必须等于该偏移的真实长度（**不含填充**），与旧的 `dia_array` 约定相反。
4. `csr_matrix` 的 `*` 是矩阵乘法，`csr_array` 的 `*` 是逐元素乘。
5. 迭代法的 `info != 0` 表示未收敛，必须检查；只检查 `x` 是不是 `nan` 是不够的。
6. CG 只适用于**对称正定**矩阵；用在非对称矩阵上不会报错，只会不收敛或给出错误答案。
7. `eigsh(which="SM")` 收敛慢，且对不定矩阵与 `"SA"` 含义不同。
8. 稀疏化的收益**依赖稀疏模式**，两个 `nnz` 相同的矩阵耗时可能差几个数量级。

**随堂自测 5.3**

1. 一个 $50000 \times 50000$ 的矩阵，每行有 5 个非零元。估算：稀疏存储需要多少内存？稠密需要多少？在 32 GB 的机器上哪个可行？
2. 同一个稀疏矩阵要解 100 个右端项，用 `spsolve` 循环 100 次和用 `splu` 一次，预期差距多大？为什么？
3. 二维网格上 `splu` 的填充比从 5.62× 到 16.18× 不等（只换了 `permc_spec`）。这说明"分解一个稀疏矩阵"的复杂度由什么决定？
4. 实测 CG 在一维 Laplacian 上比 `spsolve` 慢 42–77 倍。既然更慢，为什么还有迭代法？给出一个它必胜的具体场景。
5. 迭代法停在 `rtol=1e-10`，但 $N = 8000$ 时前向误差是 $4.5\times10^{-5}$。用 5.2.3 的公式解释这个现象，并说明该改哪个参数。

**本节交付**：稀疏/稠密决策表（5.3.6）、`fill_ratio` 这个可以当场算出来的判据、"先用直接法"的默认策略、以及"`spsolve` 给 nan、`splu` 抛异常"这对不一致行为。

## 5.4 非线性优化：目标、约束与初值

5.2 与 5.3 解的是"等式"，答案是确定的。从这一节起答案变成一个**选择**：在所有满足约束的 $x$ 里挑一个让 $f(x)$ 最小的。这类问题在建模中无处不在——成本最小化、误差最小化、风险最小化、参数拟合。

非线性优化是本章 **最容易"跑出结果"也最容易"跑出错误结果"** 的一节。求解器几乎总会在零点几毫秒内返回一个带 `success: True` 的结果，它不会告诉你这个点是不是极小值、是不是全局最优、甚至是不是真的满足约束。本节的目标就是把这些"不会告诉你的事"一件件变成可以自己检查的东西。

### 5.4.1 统一写法：优化问题的五件套

任何优化问题都能写成同样五个部分。scipy 的接口就是这五件套的直译：

| 部分 | 数学 | `minimize` 参数 | 说明 |
|------|------|----------------|------|
| 目标函数 | $f(x)$ | `fun=` | **必须返回标量** |
| 决策变量 | $x \in \mathbb{R}^n$ | `x0=` | 初值，不是范围 |
| 变量界 | $l \le x \le u$ | `bounds=`（`Bounds`） | 逐元素 |
| 约束 | $g(x) \ge 0$、$h(x) = 0$ | `constraints=` | 见 5.4.3 的符号约定 |
| 梯度（可选） | $\nabla f$ | `jac=` | 能写就必须写，见 5.4.2 |

`minimize` 的默认方法不是固定的，它按问题类型自动选：

```python
>>> from scipy.optimize import minimize
>>> minimize(f, x0)                                    # 无约束无界 → BFGS
>>> minimize(f, x0, bounds=bnds)                       # 有界 → L-BFGS-B
>>> minimize(f, x0, constraints=cons)                  # 有约束 → SLSQP
```

> **警告**：自动选择很方便，但**不要把 `method` 留给默认**。原因有二：① 你在报告里说不清自己用了什么算法；② 换一个 `bounds` 就可能静默换掉整个算法，而这会改变收敛行为与精度（下表会看到，不同方法的解能差好几个数量级）。**显式写 `method=` 是一条纪律**，跟第 4 章"显式写 `ddof`"同一性质。

### 5.4.2 无约束优化：方法对照与"给不给梯度"

拿经典 Rosenbrock 函数当基准——它的谷底弯曲，是检验优化器的标准题：

$$f(x, y) = (1-x)^2 + 100(y - x^2)^2, \qquad \text{最小值 } 0 \text{ 在 } (1, 1)$$

从 $(-1.2, 1.0)$ 出发，让十个方法各跑一遍：

```python
>>> from scipy.optimize import minimize, rosen, rosen_der, rosen_hess
>>> x0 = np.array([-1.2, 1.0])
>>> r = minimize(rosen, x0, method="BFGS", jac=rosen_der)
```

| method | `nit` | `nfev` | $f(x)$ | $\max\lvert x - 1 \rvert$ | 耗时 |
|--------|-------|--------|--------|--------------------------|------|
| Nelder-Mead | 85 | 159 | 8.18e-10 | 4.22e-05 | — |
| Powell | 23 | **607** | **1.79e-26** | **1.92e-13** | — |
| CG | 36 | 78 | 1.88e-14 | 5.49e-09 | 3.24 ms |
| **BFGS** | 32 | **39** | 2.54e-15 | 5.39e-08 | **1.85 ms** |
| L-BFGS-B | 36 | 132 | 1.52e-11 | 7.47e-06 | 9.44 ms |
| TNC | 25 | 83 | 6.48e-09 | 1.61e-04 | — |
| SLSQP | 34 | 47 | 1.12e-08 | 1.49e-04 | 1.17 ms |
| trust-constr | 62 | 62 | **5.20e-20** | 4.57e-10 | 52.37 ms |
| dogleg | 23 | 24 | 2.90e-12 | 3.40e-06 | 4.07 ms |
| trust-ncg | 29 | 30 | 9.27e-14 | 6.10e-07 | 5.25 ms |

这张表要读出四件事：

1. **所有方法都"成功"了**（`success=True`），但解的质量差了 **15 个数量级**（Powell 的 $1.8\times10^{-26}$ 对 SLSQP 的 $1.1\times10^{-8}$），$\max\lvert x-1 \rvert$ 更是从 $1.9\times10^{-13}$ 到 $1.6\times10^{-4}$ 横跨九个数量级。**"优化完成"这句话本身不携带任何精度信息。**
2. **函数调用次数与精度不成正比**。Powell 用了最多的 `nfev`（607）换来最高的精度；dogleg 只用了 24 次就达到 $2.9\times10^{-12}$。**要让求解器更准，加 `tol` 比换方法更直接。**
3. **`trust-constr` 在小问题上贵得离谱**：52.37 ms，是 BFGS 的 **28 倍**，只为了多几位小数。它是为带约束的大问题设计的，用在小无约束问题上纯属浪费。
4. **没有"最好的方法"**。BFGS 是 $nfev$ 最少的（39），dogleg 是收敛最快的（23 次迭代），Powell 是最准的——但它们在别的函数上会互相换位。**默认从 BFGS 开始，遇到问题再换。**

**梯度：给不给，差三倍。** 同一条命令，去掉 `jac=`：

| | `nfev` | `njev` | `nit` | $f(x)$ |
|---|---|---|---|---|
| 不给 `jac`（差分近似） | 117 | 39 | 32 | 2.02e-11 |
| 给 `jac`（解析梯度） | **39** | 39 | 32 | **2.54e-15** |

**迭代次数完全一样（32），函数调用次数却是 3 倍**——因为每次梯度评估都要用差分做 $n+1$ 次函数调用（这里 $n=2$）。$n$ 越大差距越大，$n = 100$ 时差分梯度的成本是解析梯度的 **101 倍**。精度也差 6 个数量级（$2.0\times10^{-11}$ 对 $2.5\times10^{-15}$），因为差分本身有截断误差与舍入误差（`ds-00` 0.2.11）。

> **实战建议**：**能写解析梯度就必须写**。这不是"优化技巧"，而是量级差别。写完之后用 `check_grad` 核对：

```python
>>> from scipy.optimize import check_grad
>>> check_grad(rosen, rosen_der, x0)
9.737757311449259e-06
```

返回值是"解析梯度与差分梯度的最大相对差"。**$10^{-6}$ 量级是正常值**（差分本身的精度就在这个量级）；如果返回 $10^{-2}$ 以上，说明解析式写错了；返回 `nan` 说明某个点上梯度算不出来。这个检查应该写成断言放进代码。

**精度要自己调。** 默认容差下 BFGS 停在

```python
>>> r = minimize(rosen, x0, jac=rosen_der)
>>> r.x, r.fun, r.success
(array([0.99999997, 0.99999995]), 2.5353057938593763e-15, True)
```

$f$ 已经小到 $10^{-15}$，但 $x$ 只精确到 $5\times10^{-8}$。加上 `tol=1e-12`：

```python
>>> r2 = minimize(rosen, x0, jac=rosen_der, tol=1e-12)
>>> r2.x, r2.fun, r2.nit
(array([1., 1.]), 5.374e-30, 35)
```

$x$ 精确到机器精度，$f$ 从 $10^{-15}$ 降到 $10^{-30}$，代价只是多 3 次迭代。**默认容差是给"能收敛就行"的场景调的；如果你要的是参数值，自己定 `tol`。**

> **⚠️ 陷阱：`OptimizeResult` 的字段随方法变化。** 上面每个方法返回的对象字段都不一样：

| 方法 | 独有字段 | 没有的字段 |
|------|---------|-----------|
| BFGS | `hess_inv`、`jac`、`njev` | — |
| Nelder-Mead | `final_simplex` | `njev`、`jac`、`hess_inv` |
| Powell | `direc` | `njev`、`jac` |
| TNC | `jac` | `njev`、`hess_inv` |
| SLSQP（带约束） | `multipliers` | `hess_inv` |

```python
>>> minimize(rosen, x0, method="Nelder-Mead").njev
AttributeError: njev
```

**写通用封装函数时不要假设 `njev` 存在**，用 `r.get("njev", None)` 或 `hasattr`。

### 5.4.3 约束优化：三个入口与一个符号陷阱

约束有三种表达方式，按由简到繁：

```python
>>> from scipy.optimize import Bounds, LinearConstraint, NonlinearConstraint
>>> bnds = Bounds([0, 0], [1, 1])                          # 变量界（逐元素）
>>> lin = LinearConstraint([[1, 1]], -np.inf, 1.0)         # 1 <= x1 + x2 <= 1，即 x1+x2 <= 1
>>> nonlin = NonlinearConstraint(lambda v: v[0]**2 + v[1], -np.inf, 1.0)   # x1² + x2 <= 1
```

`LinearConstraint(A, lb, ub)` 的语义是 $lb \le A x \le ub$，**逐行**。用 `np.inf` 表示单边约束。

拿一个能对照解析解的小问题验证：最小化 $(x_1 - 2)^2 + (x_2 - 1)^2$，约束 $x_1^2 + x_2 \le 1$。

```python
>>> def obj(v):    return (v[0] - 2)**2 + (v[1] - 1)**2
>>> def obj_g(v):  return np.array([2*(v[0] - 2), 2*(v[1] - 1)])
>>> def g1(v):     return 1 - (v[0]**2 + v[1])      # 注意：ineq 要求 g1(x) >= 0
>>> def g1_g(v):   return np.array([-2*v[0], -1.0])
>>> cons = [{"type": "ineq", "fun": g1, "jac": g1_g}]
>>> for m in ["SLSQP", "trust-constr"]:
...     r = minimize(obj, [0.5, 0.5], jac=obj_g, constraints=cons, method=m)
...     print(f"{m:12s} x={np.round(r.x, 8)} f={r.fun:.8f} nit={r.nit} 违反量={-g1(r.x):.1e}")
SLSQP        x=[0.83512254 0.30257059] f=1.84334728 nit=5 违反量=-2.4e-07
trust-constr x=[0.83512235 0.30257066] f=1.84334763 nit=34 违反量=-7.3e-09
```

解析解：在边界 $x_1^2 + x_2 = 1$ 上最小化 $(x_1-2)^2 + x_1^4$，令导数为零得 $2(x_1-2) + 4x_1^3 = 0$：

```python
>>> from scipy.optimize import brentq
>>> x1 = brentq(lambda a: 2*(a - 2) + 4*a**3, 0.5, 1.0)
>>> x1, 1 - x1**2, (x1 - 2)**2 + (1 - x1**2 - 1)**2
(0.835122348000154, 0.3025706629957006, 1.8433476246183125)
```

两个求解器都与解析解一致（SLSQP 到 $2\times10^{-7}$，trust-constr 到 $3\times10^{-7}$）。SLSQP 用 5 次迭代、trust-constr 用 34 次——**小问题上 SLSQP 更划算，但 trust-constr 的约束违反量小两个数量级**（$-7.3\times10^{-9}$ 对 $-2.4\times10^{-7}$）。选哪个取决于你更在意速度还是可行性精度。

> **⚠️ 陷阱（我自己在这个例子上踩了）：字典式约束的 `type: "ineq"` 表示 $g(x) \ge 0$，不是 $\le$。**
>
> 如果按直觉把约束写成 `fun=lambda v: v[0]**2 + v[1] - 1`（也就是把"$\le$"直接写成了表达式），那么你实际告诉求解器的是"$x_1^2 + x_2 \ge 1$"——一个完全不同的问题。实测结果：

```python
>>> cons_wrong = [{"type": "ineq", "fun": lambda v: v[0]**2 + v[1] - 1,
...                "jac": lambda v: np.array([2*v[0], 1.0])}]
>>> rw = minimize(obj, [0.5, 0.5], jac=obj_g, constraints=cons_wrong, method="SLSQP")
>>> rw.x, rw.fun, rw.success, rw.x[0]**2 + rw.x[1]
(array([2., 1.]), 0.0, True, 5.0)
```

**求解器返回了无约束最优解 $(2, 1)$，目标值 0，`success=True`，而约束 $x_1^2+x_2 \le 1$ 被违反了 4 个单位。** 没有任何警告。这类错误的特点是：**结果看起来"太好了"**（目标值 0，比正确解的 1.843 小得多）。凡是优化结果比预期好很多，第一个该检查的就是约束的符号。

> **实战建议**：`NonlinearConstraint` 比字典式约束安全，因为它的 `lb`/`ub` 位置把方向写死了，很难搞反。能用它就别用字典：

```python
>>> from scipy.optimize import NonlinearConstraint
>>> con = NonlinearConstraint(lambda v: v[0]**2 + v[1], -np.inf, 1.0)   # 方向一目了然
>>> r = minimize(obj, [0.5, 0.5], jac=obj_g, constraints=[con], method="trust-constr")
>>> r.x, r.fun
(array([0.83512233, 0.30257065]), 1.84334767...)
>>> r.x[0]**2 + r.x[1]                     # 约束值，稳稳压在边界内
0.9999999633...
```

另外，**变量界优先用 `bounds=` 而不是写成约束**。求解器对 `bounds` 有专门处理（投影/变换），比把它当不等式约束更快也更稳。

### 5.4.4 局部极小：为什么"多跑几次"可能没用

非线性优化的算法几乎都是**局部**的：它们从一个初值出发，沿着下降方向走到最近的一个极小值就停。问题是 **"最近"不等于"最好"**。

构造一个能看清这件事的函数——Rastrigin 函数：

$$f(x, y) = 20 + x^2 + y^2 - 10\bigl(\cos 2\pi x + \cos 2\pi y\bigr)$$

它像一个布满规则凹坑的蛋托：**每个整数格点 $(i, j)$ 都是局部极小，值约为 $2(i^2 + j^2)$**，全局最小 0 只在原点。从不同初值出发：

```python
>>> def rastrigin(v):
...     return 20 + v[0]**2 + v[1]**2 - 10*(np.cos(2*np.pi*v[0]) + np.cos(2*np.pi*v[1]))
```

| 初值 | BFGS | Nelder-Mead | 该点附近的理论局部极小值 |
|------|------|-------------|----------------------|
| $(0.1, 0.1)$ | **0.0000** | **0.0000** | 0（全局） |
| $(0.5, 0.5)$ | **0.0000** | 1.9899 | 0 或 2 |
| $(1.0, 1.0)$ | 1.9899 | 1.9899 | 2 |
| $(2.0, 2.0)$ | 7.9597 | 7.9597 | 8 |
| $(2.5, 2.5)$ | 7.9597 | 17.9092 | 8 |
| $(3.2, 3.2)$ | 17.9092 | 17.9092 | 18 |
| $(4.5, 4.5)$ | 31.8385 | **49.7474** | 32 或 50 |

实测值与 $2(i^2+j^2)$ 严格吻合（2、8、18、32、50）。三个观察：

1. **初值决定一切**。从 $(0.1,0.1)$ 出发能找到真最优，从 $(4.5,4.5)$ 出发只能落在 $f \approx 32$ 的坑里。
2. **同一个初值下不同方法会给不同答案**：$(2.5,2.5)$ 上 BFGS 得到 7.96、Nelder-Mead 得到 17.91。**"我用 `minimize` 求了全局最优"这句话是不成立的**，除非你用了全局方法或验证过。
3. **初值离全局最优越远，结果越差**，而且差距不是渐进的——初值稍微移动就可能掉进另一个坑。

**那么"多起点"能救吗？** 直觉上跑 50 次随机的 Nelder-Mead，总该中一次：

```python
>>> rng = np.random.default_rng(0)
>>> best, hits = None, 0
>>> for _ in range(50):
...     x0 = rng.uniform(-5.12, 5.12, 2)
...     r = minimize(rastrigin, x0, method="Nelder-Mead")
...     if best is None or r.fun < best.fun: best = r
...     if r.fun < 1e-6: hits += 1
>>> hits, best.fun
(0, 0.995...)
```

**50 次全部失败，最好的结果是 0.995——连一个真最优都没碰到。** 原因在 Nelder-Mead 的实现细节：它的初始单纯形是"以初值为中心、每个坐标方向偏移 5%"的小三角形，尺度太小，跨不过 Rastrigin 相邻坑之间约 1 个单位的势垒。**多起点的有效性完全取决于局部方法本身的探索半径。**

**全局方法才是正解。** scipy 提供四个：

```python
>>> from scipy.optimize import differential_evolution, dual_annealing, shgo, basinhopping
```

| 方法 | 类型 | 结果 | `nfev` |
|------|------|------|--------|
| `differential_evolution` | 种群进化 | **0.000e+00** | 2013 |
| `dual_annealing` | 模拟退火 + 局部搜索 | 7.1e-15 | 2109 |
| `shgo` | 单纯形同调（确定性全局） | **0.000e+00** | 1064 |
| `basinhopping` | 随机跳坑 + 局部搜索 | 1.1e-14 | 7341 |

四个都找到了全局最优（到 $10^{-14}$ 以内），但代价与性格不同：

- **`differential_evolution`** 最通用，支持约束与整数变量（`integrality=`），是建模竞赛的默认选择。
- **`shgo`** 是**确定性**的——同样的输入给同样的输出，没有随机性，在需要可复现的场合有优势；但对高维问题开销增长快。
- **`dual_annealing`** 与 **`basinhopping`** 依赖随机重启，需要显式传 `rng=` 才能复现。
- `nfev` 都在 1000–7400 之间，比局部方法的几十次贵两个数量级。**这是"全局"这个概念的真实价格。**

> **⚠️ 陷阱**：**"全局优化"是相对搜索域而言的。** `differential_evolution(f, bounds)` 的 `bounds` 定义了你认为最优解所在的区域，它不会（也不能）告诉你区域之外有没有更好的点。上面 Rastrigin 定义在 $(-\infty, \infty)$ 上其实无下界，我在 5.4 的初始探索里就撞到过这个坑：不加界的多起点搜索跑到了 $(1.59, 7.95)$，$f = -1.81$，比有界搜索的 $-1.67$ 更好，但那个点已经远在题目定义的 $[-5, 5]^2$ 之外。**报告全局最优时必须同时报告搜索域，否则那个数字没有意义。**

> **实战建议**：先验知识比算法更重要。① 能推导出凸性就用凸方法；② 有物理范围就用 `bounds` 把它框死；③ 怀疑多峰再用全局方法；④ 全局方法的结果**必须**再用局部方法精化一遍（`differential_evolution` 的 `polish=True` 默认就做这件事）。直接采信全局方法的原始输出，在小梯度区域精度通常不如局部精化。

### 5.4.5 求根：方程与优化是两件事

解 $f(x) = 0$ 与最小化 $f(x)$ 数学上可以互相转化，但**数值上是两类问题**，用错工具会事倍功半。

| 场景 | 入口 | 是否需要导数 | 是否需要括号 |
|------|------|------------|------------|
| 一元方程，已知根所在区间 | `brentq` / `root_scalar(bracket=)` | 否 | **是** |
| 一元方程，只有初值 | `root_scalar(method="newton"/"secant")` | 建议 | 否 |
| 多元方程组 | `root` / `fsolve` | 建议 | 否 |
| 一元函数的最小值 | `minimize_scalar` | 否 | 建议 |

**括号（bracket）是一元求根里最值得用的一件事。** 如果 $f(a)$ 与 $f(b)$ 异号，那么区间 $[a,b]$ 内必有根（介值定理），Brent 方法能保证收敛：

```python
>>> from scipy.optimize import brentq, root_scalar
>>> f = lambda t: np.cos(t) - t            # 不动点方程 cos(x) = x
>>> r = root_scalar(f, bracket=[0, 1], method="brentq")
>>> r.root, r.iterations, r.function_calls, r.converged
(0.7390851332151559, 7, 8, True)
```

7 次迭代、8 次函数调用就收敛到机器精度。**有括号时优先用 `brentq`。**

没有括号时用 Newton 或割线法，**更快但不保证收敛**：

| 方法 | 需要导数 | 迭代次数 | 结果 |
|------|---------|---------|------|
| `brentq`（有括号） | 否 | 7 | 0.7390851332151559 |
| `newton`（给导数） | 是 | 4 | 0.7390851332151607 |
| `secant`（不给导数） | 否 | 5 | 0.7390851332151601 |

Newton 只需 4 次迭代——**但它的收敛性依赖初值**：

```python
>>> root_scalar(f, x0=10.0, method="newton").converged, root_scalar(f, x0=10.0, method="newton").iterations
(True, 33)
>>> r_bad = root_scalar(f, x0=-10.0, method="newton")
>>> r_bad.converged, r_bad.root, r_bad.iterations
(False, -451.8358838279, 50)
```

从 $x_0 = -10$ 出发，Newton 法跑到了 **$-451.8$** 并报告 `converged=False`。`cos(x) - x = 0` 只有 $0.739$ 一个根，$-451$ 附近 $f \approx -(-451) = 451$，根本没有根。**这里 `converged=False` 是唯一的救命信号——必须检查它。**

括号的代价是**必须自己确认异号**：

```python
>>> root_scalar(f, bracket=[2, 3], method="brentq")
ValueError: f(a) and f(b) must have different signs
```

这个报错是好事：它把"这个区间里没有根"这件事明确说了出来，比 Newton 法悄悄跑飞要好得多。

多元方程组用 `root`（推荐，可以给雅可比）或 `fsolve`（老接口）：

```python
>>> def sys2(v):
...     return [v[0]**2 + v[1]**2 - 1, v[0] - v[1]]
>>> from scipy.optimize import root, fsolve
>>> r = root(sys2, [1, 1], jac=lambda v: [[2*v[0], 2*v[1]], [1, -1]])
>>> r.message, r.x, r.nfev, r.njev
('The solution converged.', array([0.70710678, 0.70710678]), 9, 1)
>>> np.abs(sys2(r.x)).max()                 # 残差
4.440892098500626e-16
```

给雅可比后 `nfev` 从 11 降到 9、`njev` 只有 1 次——**和优化一样，能写解析雅可比就该写**。残差 $4.4\times10^{-16}$ 说明解是准确的（方程组的残差和线性问题一样可以直接算，见 5.2.6 的第 4 步）。

> **实战建议**：求根的问题往往出在"根不止一个"或"根本没有根"。**先画图或用网格扫一遍**，看清 $f$ 的符号变化在哪里，再决定括号或初值。这一步比调求解器参数有效得多——它的成本是几行代码，收益是避免解出一个你根本不需要的根。

### 5.4.6 验证：优化的结果必须自己检查

优化器返回的 `success` **只表示"算法认为它按自己的判据收敛了"**，不表示"你得到了想要的东西"。四道检查，从便宜到贵：

**第一道：残差/目标值的量级。** $f(x^*) \approx 0$ 是否合理（比如目标是最小化平方误差）？如果目标值是 $10^{-15}$ 而你的问题是"最小化成本"，那说明目标函数写错了（漏了量纲、写成了残差）。

**第二道：KKT 违背量。** 受约束问题的解必须满足 KKT 条件（平稳性、对偶可行性、互补松弛；完整推导与乘子符号约定见 `ds-05b` S4.1）。实操上只要检查两件事——**可行性**和**互补松弛**：

```python
def kkt_report(x, cons, tol=1e-6):
    """检查字典式约束的可行性；返回每个约束的违背量。"""
    rows = []
    for c in cons:
        val = c["fun"](x)
        if c["type"] == "ineq":
            violation = max(0.0, -val)          # 要求 val >= 0
        else:
            violation = abs(val)                # 要求 val == 0
        rows.append({"type": c["type"], "value": val, "violation": violation,
                     "ok": violation <= tol})
    return rows
```

对无约束问题，KKT 条件退化成 $\nabla f(x^*) = 0$，直接检查梯度的范数：

```python
>>> np.linalg.norm(rosen_der(r.x))
```

**第三道：梯度/雅可比的正确性。** 用 `check_grad`（5.4.2）。这条要在**写代码阶段**做，不要等到结果不对才查。

**第四道：敏感性。** 初值换几个、约束的右端项动一动，看最优值变化多少。变化剧烈说明问题本身病态或接近不可行边界。这也是第 5.2.6 节第 5 步的思路。

把它们串成一个模板：

```python
def optimize_checked(obj, x0, jac=None, bounds=None, constraints=(), method="BFGS", name="问题"):
    """跑一次优化并输出四道检查。"""
    r = minimize(obj, x0, jac=jac, bounds=bounds, constraints=constraints, method=method)
    rep = {"method": method, "success": r.success, "nit": r.nit, "nfev": r.nfev,
           "fun": r.fun, "x": r.x, "message": r.message}
    # ① 可行性
    if constraints:
        rep["violations"] = [row["violation"] for row in kkt_report(r.x, constraints)]
        rep["feasible"] = all(row["ok"] for row in kkt_report(r.x, constraints))
    # ② 无约束时用 ||∇f|| 代替 KKT
    if jac is not None and not constraints and bounds is None:
        rep["grad_norm"] = float(np.linalg.norm(jac(r.x)))
    # ③ 是否撞到了界
    if bounds is not None:
        rep["at_bound"] = bool(np.any(np.isclose(r.x, bounds.lb) | np.isclose(r.x, bounds.ub)))
    ok = r.success and rep.get("feasible", True)
    print(f"[{name}] method={method} success={r.success} nit={r.nit} nfev={r.nfev} f={r.fun:.6g}"
          + (f" ||∇f||={rep['grad_norm']:.2e}" if "grad_norm" in rep else "")
          + (f" 可行={rep['feasible']}" if "feasible" in rep else ""))
    if not ok:
        print(f"    ⚠️ 需要人工检查：message = {r.message}")
    return r, rep
```

```python
>>> r, rep = optimize_checked(rosen, x0, jac=rosen_der, name="Rosenbrock")
[Rosenbrock] method=BFGS success=True nit=32 nfev=39 f=2.53531e-15 ||∇f||=1.89e-06
>>> r, rep = optimize_checked(rastrigin, [4.5, 4.5], method="BFGS", name="Rastrigin")
[Rastrigin] method=BFGS success=True nit=7 nfev=36 f=31.8385
```

**注意第二个例子：`success=True`、`||∇f||` 也很小（局部极小点上梯度确实为零），但 $f = 31.84$ 而全局最优是 0。** 所有局部检查都会通过——这正是局部方法最危险的地方，**只有全局视野（多点初值、网格扫描、或全局算法）才能发现它**。这是本节最想留下的一个判断：**"优化成功"与"找到最优"是两件事，前者是求解器的自我评价，后者需要你自己论证。**

**随堂自测 5.4**

1. Rosenbrock 上十个方法都返回 `success=True`，但 $\max\lvert x-1 \rvert$ 相差九个数量级。这说明 `success` 字段的含义是什么？
2. 给解析梯度让 `nfev` 从 117 降到 39，而 `nit` 都是 32。为什么？如果 $n = 100$，这个比例会变成多少？
3. 字典式约束 `{"type": "ineq", "fun": g}` 要求 $g(x)$ 满足什么不等式？把 $x_1^2+x_2 \le 1$ 写成 `fun` 应该是什么表达式？
4. 50 次随机初值的 Nelder-Mead 全部没找到 Rastrigin 的全局最优。是随机性不好，还是方法的探索半径不够？怎么验证你的判断？
5. 一个优化问题返回 `success=True`、$f = 31.84$、$\lVert\nabla f\rVert = 10^{-8}$。所有局部检查都通过了。接下来该做什么？
6. `brentq` 需要括号而 `newton` 不需要。在什么情况下必须用 `brentq`？在什么情况下 `newton` 更快？

## 5.5 线性规划与整数规划

5.4 的目标函数是任意的。如果它和所有约束都是**线性**的，问题就从"能解但可能卡在局部极小"变成"有全局最优且保证找到"——这是优化里最幸运的一类结构，也是数学建模竞赛里出现频率最高的问题类型。

本节的两个工具：`linprog`（线性规划，LP）与 `milp`（混合整数线性规划，MILP）。它们的用法都是"把问题写成标准型"，所以本节的重点不是调参，而是**改写**。

### 5.5.1 标准型与四个改写动作

`linprog` 只接受一种形式：

$$\min_x \; c^{\top}x \quad \text{s.t.} \quad A_{ub}x \le b_{ub}, \quad A_{eq}x = b_{eq}, \quad l \le x \le u$$

任何线性规划问题都能通过四个动作变成它——**这四个动作覆盖了实际问题的全部改写需求**：

| 动作 | 做法 | 例子 |
|------|------|------|
| 最大化 → 最小化 | 目标全体取负，答案再取负 | $\max 3x+2y \Rightarrow \min -3x-2y$ |
| $\ge$ → $\le$ | 两端乘 $-1$ | $x+3y \ge 6 \Rightarrow -x-3y \le -6$ |
| 等式约束 | 放 `A_eq` / `b_eq` | 供需平衡、流量守恒 |
| 自由变量 | 拆成 $x = x^+ - x^-$，两者 $\ge 0$ | 允许为负的净流入 |

```python
>>> from scipy.optimize import linprog
>>> c = np.array([-3., -2.])                       # max 3x + 2y
>>> r = linprog(c, A_ub=[[1, 1], [1, 3]], b_ub=[4, 6], bounds=(0, None))
>>> r.x, -r.fun, r.status
(array([4., 0.]), 12.0, 0)
```

`status=0` 表示最优。整数规划不需要单独写 `A_eq` 那套——`milp` 用统一的 `LinearConstraint`，反而更简洁（5.5.3）。

> **⚠️ 陷阱**：`linprog` 的默认 `bounds=(0, None)` 表示**所有变量非负**。这符合大多数资源分配问题的物理含义，但如果你的变量可以是负的（例如净现金流、相对偏差），忘了改 `bounds` 会得到荒谬的结果而且不报错。**写每一行模型前先问一句：这个变量有下界吗？**

### 5.5.2 影子价格：灵敏度分析是免费的

求解器返回的 `marginals` 就是**对偶变量**（也叫影子价格、Lagrange 乘子）：**第 $i$ 个约束的右端项增加 1 个单位，目标函数会变化多少。**

```python
>>> r = linprog(c, A_ub=[[1, 1], [1, 3]], b_ub=[4, 6], bounds=(0, None))
>>> r.ineqlin.marginals
array([-3., -0.])
>>> r.lower.marginals
array([0., 1.])
```

$\text{marginals}[0] = -3$ 的含义是：`b_ub[0]` 从 4 加到 5，$\min$ 形式的目标会变化 $-3$，也就是原问题（最大化）提升 3。直接验证：

| `b_ub[0]` | 最优目标（max 形式） | 增量 |
|-----------|------------------|------|
| 4 | 12.0 | — |
| 5 | 15.0 | +3.0 |
| 6 | 18.0 | +3.0 |

完全吻合。而 `lower.marginals[1] = 1` 说明"$y$ 的下界放松 1 个单位能提升目标 1"——这就是**为什么报告里该带影子价格**：它直接回答了"该往哪个方向投资源"。

> **版本注意**：`linprog` 的 `marginals` 符号约定与多数非线性求解器的 Lagrange 乘子**相反**（官方文档明确说明）。对照时不要直接比数值，先确认符号约定。

### 5.5.3 整数规划：`milp` 与 `integrality`

`milp` 是 1.9 引入的统一入口，接口比 `linprog` 清晰得多：目标、`Bounds`、`LinearConstraint`、`integrality`，四件事。

```python
>>> from scipy.optimize import milp, LinearConstraint, Bounds
>>> # 0-1 背包：5 件物品，载重 10，价值最大
>>> w = np.array([2., 3., 4., 5., 9.])
>>> v = np.array([3., 4., 5., 8., 10.])
>>> res = milp(c=-v, constraints=LinearConstraint(w, -np.inf, 10),
...            integrality=np.ones(5), bounds=Bounds(0, 1))
>>> res.x, -res.fun
(array([ 1.,  1., -0.,  1.,  0.]), 15.0)      # 选物品 1、2、4：重量 10，价值 15
```

`integrality` 有四种取值，这是 `milp` 最容易被忽略的表达力：

| 值 | 含义 |
|----|------|
| 0 | 连续变量（默认） |
| 1 | 整数变量（在 `bounds` 内取整） |
| 2 | 半连续：取 0，或落在 `bounds` 内 |
| 3 | 半整数：取 0，或取 `bounds` 内的整数 |

`2` 和 `3` 对应一类很实际的约束——"要么不做，要做就得做到最小规模"（最小批量、最小开机量）。用 0-1 变量加 big-M 也能表达，但 `integrality=2` 一行就够了。

**状态码必须检查**：

| `status` | 含义 | 该做什么 |
|----------|------|---------|
| 0 | 最优 | 正常 |
| 1 | 达到迭代/时间上限 | 看 `mip_gap`，放宽 `time_limit` |
| 2 | **不可行** | 约束互相矛盾，回去查模型 |
| 3 | **无界** | 漏了上界，检查 `bounds` |
| 4 | 数值困难 | 缩放变量与系数 |

```python
>>> linprog([1., 1.], A_ub=[[1, 1], [-1, -1]], b_ub=[1, -3], bounds=(0, None)).status
2                                        # 不可行：x+y<=1 与 x+y>=3 矛盾
>>> linprog([-1., -1.], A_ub=[[1, -1]], b_ub=[1], bounds=(0, None)).status
3                                        # 无界：x 可以无限大
```

**不可行的定位方法**：从约束里一条条删，看哪条删掉后变可行。这比盯着矩阵看快得多。

**`milp` 的三个调度选项**：`time_limit`（秒）、`mip_rel_gap`（相对间隙，默认 `1e-4`）、`presolve`。大规模整数规划常常无法证明最优，此时返回的是**可行解 + 间隙**：

```python
>>> res.mip_gap, res.mip_dual_bound, res.mip_node_count
```

`mip_gap` 是"当前最好解与理论下界之间的相对间隙"。**报告 MILP 结果时必须带上 `mip_gap`**——间隙 5% 和间隙 0% 是两种可信度完全不同的结论。

### 5.5.4 建模模式库：五个标准套路

数学建模里 80% 的优化题可以归到这五类，每类的"标准型五件套"都值得背下来。

**① 运输问题**：$m$ 个产地、$n$ 个销地，供需平衡，最小化运费。变量是 $m \times n$ 的运量矩阵 $x_{ij}$，等式约束是每行的供应量与每列的销售量。

```python
>>> sup, dem = np.array([20., 30.]), np.array([10., 25., 15.])
>>> C = np.array([[8., 6., 10.], [9., 12., 13.]])
>>> n, m = C.shape
>>> A_eq = np.zeros((n + m, n * m))
>>> for i in range(n): A_eq[i, i*m:(i+1)*m] = 1        # 行和 = 供应量
>>> for j in range(m): A_eq[n + j, j::m] = 1           # 列和 = 需求量
>>> r = linprog(C.ravel(), A_eq=A_eq, b_eq=np.r_[sup, dem], bounds=(0, None))
>>> r.fun, r.x.reshape(n, m).round(3)
(465.0, array([[ 0., 20.,  0.], [10.,  5., 15.]]))
```

注意 `A_eq` 的构造用了切片 `j::m` 取出一整列——**这是运输问题里最值得记住的一行代码**。产销不平衡时，补一个虚拟产地或销地（运费 0）把等式凑齐。

**② 指派问题**：$n$ 个人 $n$ 个任务，一对一，最小化总成本。这是纯组合问题，用 `linear_sum_assignment` 专门算法，比 `milp` 快得多：

```python
>>> from scipy.optimize import linear_sum_assignment
>>> C = np.array([[4., 1., 3.], [2., 0., 5.], [3., 2., 2.]])
>>> rows, cols = linear_sum_assignment(C)
>>> rows, cols, C[rows, cols].sum()
(array([0, 1, 2]), array([1, 0, 2]), 5.0)
>>> r2, c2 = linear_sum_assignment(C, maximize=True)   # 最大化收益
>>> C[r2, c2].sum()
11.0
```

`maximize=True` 是 1.4 新增的参数，省去了"取负再还原"的手工步骤。三点注意：返回的 `rows` 已排序；**长方形矩阵（$m < n$）只会指派 $\min(m,n)$ 对**；成本矩阵里的 `np.inf` 表示"不允许这个人做这个任务"，这是表达硬禁止的标准做法。

**③ 背包问题**：即上面 5.5.3 的例子，`Bounds(0, 1)` + `integrality=1`；最优解是物品 1、2、4，恰好吃满载重 10。

**④ 选址问题**：0-1 变量 $y_i$ 表示是否开设，加上"只有在 $i$ 开设时才能从 $i$ 发货"的连锁约束。这几条连锁约束的写法是最容易错的地方：

```python
>>> # 3 个候选仓、4 个客户：开仓成本 + 运输成本 最小化
>>> open_cost = np.array([100., 120., 90.])
>>> ship = np.array([[10., 12., 15., 11.], [13.,  9., 14., 10.], [12., 14.,  8., 13.]])
>>> demand = np.array([15., 20., 18., 12.])
>>> M = float(demand.sum())                         # big-M
>>> c = np.concatenate([open_cost, ship.ravel()])   # 变量顺序: y(3) + x(12)
>>> A_ub, b_ub = [], []
>>> for j in range(4):                              # 每个客户的需求必须满足
...     row = np.zeros(15); row[3 + j::4] = -1.0
...     A_ub.append(row); b_ub.append(-demand[j])
>>> for i in range(3):                              # x_ij - M*y_i <= 0
...     for j in range(4):
...         row = np.zeros(15); row[3 + i*4 + j] = 1.0; row[i] = -M
...         A_ub.append(row); b_ub.append(0.0)
>>> res = milp(c=c, constraints=LinearConstraint(np.array(A_ub), -np.inf, np.array(b_ub)),
...            integrality=np.concatenate([np.ones(3), np.zeros(12)]),
...            bounds=Bounds(np.zeros(15), np.concatenate([np.ones(3), np.full(12, np.inf)])))
>>> res.fun, res.x[:3]
(834.0, array([0., 1., 1.]))
```

结果：开 2 号与 3 号仓，总成本 $834 = 210$（固定）+ $624$（运输）。

> **⚠️ 陷阱（本节最容易错的一处）**：连锁约束 $x_{ij} \le M y_i$ 写成矩阵时，**$x_{ij}$ 的系数是 $+1$、$y_i$ 的系数是 $-M$**。我在写这一节时把它写反成了 $y_i - M x_{ij} \le 0$（等价于 $y_i \le M x_{ij}$），结果模型仍然求解成功、`status=0`，但 **$y$ 全为 0**——因为"不开仓也能发货"，固定成本被完全忽略了，目标值从 834 变成 594。**约束写反不会报错，只会悄悄解出另一个问题。**

> **实战建议**：big-M 不要取 $10^6$ 之类的巨大数。$M$ 太大时 LP 松弛界很弱，求解器要多搜很多节点；$M$ 取"该变量的实际上界"最好（本例 $M = \sum_j d_j = 65$ 即可）。若 $M$ 取到 $10^6$，本例结果不变但数值条件变差。

**⑤ 排班问题**：整数变量表示各天开始上班的人数，约束矩阵是"0-1 轮转矩阵"。

```python
>>> needs = np.array([15, 12, 18, 20, 22, 25, 17])   # 每天所需人数
>>> A = np.zeros((7, 7))
>>> for d in range(7):
...     for s in range(7):
...         if (d - s) % 7 < 5: A[d, s] = 1          # 第 s 天入职的人在第 d 天在岗
>>> r = milp(c=np.ones(7), constraints=LinearConstraint(A, needs, np.inf),
...          integrality=np.ones(7), bounds=Bounds(0, np.inf))
>>> r.x.astype(int), r.fun
(array([1, 4, 8, 7, 2, 5, 0]), 27.0)
```

总人数 27。注意约束用的是 `LinearConstraint(A, needs, np.inf)`——下界是需求量、上界是无穷，这正是"至少满足"的写法。**`LinearConstraint` 的 `lb`/`ub` 位置比字典式约束更难搞反**，这是它相对 5.4.3 那套的一个实际优势。

### 5.5.5 何时离开 scipy

`linprog` 与 `milp` 覆盖了线性与整数线性问题。以下情形需要换工具：

| 问题 | 该去哪里 |
|------|---------|
| 二次目标（投资组合、最小二乘带约束） | `optimize.minimize`（SLSQP/trust-constr）或专用 QP 库 |
| 凸锥规划、半正定规划 | `cvxpy`（建模语言，底层调多个求解器） |
| 大规模整数规划（百万变量） | 商业求解器 Gurobi/CPLEX 或 HiGHS 的命令行版 |
| 需要列生成、分支切割自定义 | 建模语言 + 求解器接口 |
| 约束带逻辑（if-then、互斥） | 大 M 或指示变量人工线性化，仍可用 `milp` |

> **实战建议**：**先用 `milp` 试，不行再上 `cvxpy`。** scipy 的接口虽然朴素，但没有额外依赖、求解器（HiGHS）质量很高，绝大多数竞赛题规模的 MILP 都在毫秒到秒级完成。只有在需要"用自然数学写法描述复杂约束"时，建模语言的收益才显现出来。

**随堂自测 5.5**

1. `max 5x + 4y`、约束 $2x + y \le 10$、$x, y \ge 0$，写出 `linprog` 的 `c`、`A_ub`、`b_ub`。如果 $y$ 可以是负数，`bounds` 该怎么写？
2. `ineqlin.marginals` 返回 $-2.5$。右端项从 10 增到 12，目标函数变化多少？为什么符号要和"直觉"对照一下？
3. 选址模型里把 $x_{ij} \le M y_i$ 写成 $y_i \le M x_{ij}$，为什么求解器不报错？结果会怎样？
4. `linear_sum_assignment` 传一个 $3 \times 5$ 的成本矩阵，会返回几对指派？如果某个位置是 `np.inf` 呢？
5. 一个 MILP 返回 `status=0` 但 `mip_gap=0.047`。这个结果能不能作为最终答案？报告时要写什么？

**本节交付**：四个改写动作表、五个建模模式模板（运输/指派/背包/选址/排班）、状态码对照表、big-M 的取值纪律、以及"连锁约束系数写反不报错"这条陷阱。

## 5.6 曲线拟合与反问题

5.5 是"目标已知、求最优决策"；本节是"**模型已知、求参数**"。这是科研与建模里最常见的任务：有一批观测点和一个带参数的模型，要反推出参数值。

第 4 章的 `linregress` 处理的是**线性**模型的一元回归；本节要处理的是**任意**模型，而且要在做不出来的时候知道为什么。

### 5.6.1 `curve_fit`：参数与它的不确定度

最常用的拟合入口是 `curve_fit`：给它一个"参数在前、自变量在后"的函数，它会返回最优参数与协方差矩阵。

```python
>>> from scipy.optimize import curve_fit
>>> def model(t, a, b, c):
...     return a * np.exp(-b * t) + c
>>> rng_fit = np.random.default_rng(3)
>>> t = np.linspace(0, 5, 30)
>>> y = model(t, 5.0, 1.2, 0.5) + rng_fit.normal(0, 0.15, t.size)
>>> popt, pcov = curve_fit(model, t, y, p0=[1, 1, 0])
>>> perr = np.sqrt(np.diag(pcov))          # 参数标准误
>>> np.round(popt, 4), np.round(perr, 4)
(array([5.0064, 1.3103, 0.5743]), array([0.1327, 0.0704, 0.0481]))
```

真值是 $[5.0, 1.2, 0.5]$：三个参数都落在 ±2 个标准误内。**`pcov` 的对角线是参数方差，开方就是标准误**——这是 `curve_fit` 最容易被浪费掉的输出。有了它就能给出区间：

```python
>>> np.round(popt - 1.96 * perr, 3), np.round(popt + 1.96 * perr, 3)
(array([4.746, 1.172, 0.48 ]), array([5.266, 1.448, 0.669]))
```

$b$ 的区间 $[1.172, 1.448]$ 包含了真值 1.2，$c$ 的 $[0.480, 0.669]$ 包含 0.5。

**`pcov` 的非对角项也要看**——它反映参数之间的相关性。归一化成相关系数矩阵：

```python
>>> np.round(pcov / np.outer(perr, perr), 3)
array([[ 1.   ,  0.386, -0.14 ],
       [ 0.386,  1.   ,  0.638],
       [-0.14 ,  0.638,  1.   ]])
```

$b$ 与 $c$ 的相关系数是 $+0.638$：两者一起变大时拟合还能维持得不错。**相关系数接近 ±1 是"参数不可辨识"的预警**——此时单独报某个参数的标准误没有意义，因为它的不确定性主要来自另一个参数。

**`sigma` 与 `absolute_sigma` 决定 `pcov` 的含义**：

| 用法 | `pcov` 的含义 |
|------|-------------|
| 不给 `sigma` | 假设各点权重相同，`pcov` 已按残差方差缩放（可当绝对不确定度用） |
| `sigma=σ, absolute_sigma=False`（默认） | `sigma` 只表示**相对权重**，`pcov` 仍按残差重新缩放 |
| `sigma=σ, absolute_sigma=True` | `sigma` 是**已知的真实测量误差**，`pcov` 不重新缩放 |

第三行才是"我真的知道仪器精度"的场合。同一份数据：

```python
>>> popt, pcov2 = curve_fit(model, t, y, p0=[1, 1, 0], sigma=np.full(t.size, 0.15), absolute_sigma=True)
>>> np.round(np.sqrt(np.diag(pcov2)), 4)
array([0.1168, 0.062 , 0.0424])
```

标准误从 `[0.1327, 0.0704, 0.0481]` 缩小到 `[0.1168, 0.062, 0.0424]`——因为这里真实的噪声标准差就是 0.15，而默认情形是用残差估计的（残差均方根 0.1616，略大于 0.15）。**报参数不确定度时必须说明用了哪一种**，否则数字不可比。

> **版本注意**：`curve_fit(..., full_output=True)` 在 1.18 里对 `method='lm'` 与 `method='trf'` **都返回 5 元组** `(popt, pcov, infodict, errmsg, ier)`。早期文档里"`trf` 只返回 `(popt, pcov)`"的说法已经不成立。写通用代码时按 5 元组解包，或用 `popt, pcov = curve_fit(...)[:2]`。

**初值 `p0` 不是可选项。** 不给 `p0` 时 `curve_fit` 从全 1 开始，对指数、幂律、对数模型常常直接发散。本节例子里我给了 `p0=[1, 1, 0]`；如果真实 $a = 500$，从 1 出发很可能失败。**给初值的经验法则：先画图估数量级。**

### 5.6.2 稳健拟合：`least_squares` 与损失函数

最小二乘对离群点极其敏感，因为残差是**平方**进入目标的——一个偏离 10 个标准差的点贡献 100 倍权重。`least_squares` 提供了一族"压尾"的损失函数：

| `loss` | 形式 | 特点 |
|--------|------|------|
| `"linear"` | $\tfrac12 r^2$ | 标准最小二乘（默认） |
| `"soft_l1"` | $2(\sqrt{1+z^2}-1)$ | 小残差近似二次，大残差线性 |
| `"huber"` | 分段 | 与 soft_l1 接近 |
| `"cauchy"` | $\log(1+z^2)$ | 压尾最狠的常用选择 |
| `"arctan"` | $\arctan z$ | 有界损失，见下面的陷阱 |

其中 $z = r / \texttt{f\_scale}$，`f_scale` 是"多大残差算离群"的分界尺度，**应当设成噪声水平**。

用蒙特卡洛把差别量化（100 个点、噪声 $\sigma = 0.2$、$y = 2 + 1.5x$，随机挑若干点加尺度为 8 的粗差，500 次重复，报平均参数误差 $\lVert\hat{p} - p\rVert$）：

| `loss` | 干净数据 | 5% 粗差 | 10% 粗差 | 20% 粗差 | 10% 粗差的中位数 | 失败率（误差 > 1） |
|--------|---------|--------|---------|---------|---------------|----------------|
| `linear` | 0.0325 | 0.2839 | **0.4324** | 0.6085 | 0.3497 | 7.8% |
| `soft_l1` | 0.0339 | 0.0369 | **0.0424** | 0.0498 | 0.0353 | 0.0% |
| `huber` | 0.0343 | 0.0366 | **0.0409** | 0.0466 | 0.0348 | 0.0% |
| `cauchy` | 0.0376 | 0.0387 | **0.0404** | 0.0428 | 0.0355 | 0.0% |
| `arctan` | 0.0472 | 0.2202 | 0.4158 | 0.6500 | 0.0761 | **15.4%** |

三条结论：

1. **干净数据上五种损失几乎一样**（0.033–0.047）。换稳健损失的成本很小。
2. **10% 粗差下差别是 10 倍**：`linear` 的误差从 0.033 涨到 0.432（**13 倍**），而 `soft_l1`/`huber`/`cauchy` 几乎没动（0.040–0.042）——**改善约 10.5 倍**。
3. **`arctan` 是个陷阱**：它的中位数只有 0.0761（比 `linear` 的 0.3497 好得多），但**均值 0.4158、失败率 15.4%、最坏误差 5.5**。损失被压得太狠之后，目标函数对参数几乎失去约束，某些样本上会落到完全错误的解。**"越稳健越好"是错的**——`soft_l1`/`huber`/`cauchy` 才是可用区间。

**`f_scale` 必须调**。对 `soft_l1`，10% 粗差下（500 次平均）：

| `f_scale` | 0.05 | 0.1 | 0.2 | 0.5 | 1.0 | 5.0 |
|-----------|------|-----|-----|-----|-----|-----|
| 平均误差 | 0.0432 | 0.0421 | 0.0424 | 0.0507 | 0.0709 | 0.2117 |

在真实噪声尺度（0.2）附近最稳；取到 5.0 就退化成最小二乘了。**`f_scale` 应该等于你对"正常残差有多大"的最佳估计**，通常用最小二乘拟合后残差的中位数绝对偏差（MAD）来定。

> **实战建议**：稳健拟合的标准流程是——① 先跑一次 `loss="linear"`；② 算残差，找 $|r| > 3\sigma$ 的点；③ 用 `f_scale = 1.4826 × MAD(残差)` 再跑 `loss="soft_l1"`；④ **对比两次的参数**。如果差别很大，说明离群点确实在主导结论（此时必须报告）；如果几乎相同，说明数据干净，用哪个都行。

### 5.6.3 反问题：把求解器嵌进优化器

"从观测数据反推模型的物理参数"是最有价值也最容易失败的一类拟合。做法是：**残差函数内部调用一次求解器**。

用传染病 SIR 模型演示：

$$\frac{dS}{dt} = -\beta\frac{SI}{N}, \qquad \frac{dI}{dt} = \beta\frac{SI}{N} - \gamma I, \qquad \frac{dR}{dt} = \gamma I$$

已知 $N = 1000$、$S_0 = 995$、$I_0 = 5$，观测到 61 天的感染人数（含 5% 乘性噪声），反推 $\beta$ 与 $\gamma$：

```python
>>> from scipy.integrate import solve_ivp
>>> from scipy.optimize import least_squares
>>> def sir(t, y, beta, gamma):
...     S, I, R = y
...     return [-beta*S*I/N, beta*S*I/N - gamma*I, gamma*I]
>>> def resid(p):
...     s = solve_ivp(sir, [0, 60], [N-5., 5., 0.], args=(p[0], p[1]),
...                   t_eval=t_eval, rtol=1e-6)
...     return s.y[1] - obs if s.success else np.full(t_eval.size, 1e9)
>>> r = least_squares(resid, [0.2, 0.1], bounds=([1e-4, 1e-4], [3, 3]))
>>> r.x
array([0.39944, 0.15347])                 # 真值 [0.40, 0.15]
```

结果：$\beta$ 误差 0.14%、$\gamma$ 误差 2.32%，基本反演成功。四件事要检查：

**① 残差曲线是不是 V 形。** 把 $\gamma$ 固定在最优点、扫 $\beta$，看残差范数：

| $\beta$ | 0.30 | 0.35 | **0.40** | 0.45 | 0.55 | 0.80 |
|---------|------|------|---------|------|------|------|
| $\lVert r\rVert$ | 588.0 | 299.6 | **43.7** | 277.2 | 691.5 | 1227.3 |

清晰的 V 形，说明 $\beta$ 被数据确定了。**如果这条曲线是平的，参数就不可辨识，再好的求解器也救不回来**——而"平坦"最常见的成因是**参数化写错**，见下面的警示。

**② 多初值是否收敛到同一点。**

| 初值 | $(0.2, 0.1)$ | $(0.6, 0.25)$ | $(0.35, 0.13)$ | $(1.0, 0.4)$ |
|------|------------|-------------|--------------|------------|
| $\hat\beta$ | 0.39944 | 0.39944 | 0.39944 | 0.39944 |
| $\hat\gamma$ | 0.15347 | 0.15347 | 0.15347 | 0.15347 |

四个初值收敛到完全相同的点——这是可辨识性的正面证据。**如果不同初值给出不同答案，首先要怀疑的是"数据里没有这个参数的信息"，而不是"求解器不够好"。**

**③ 参数的不确定度与相关性。** 用雅可比矩阵算协方差：

```python
>>> J = r.jac
>>> cov = np.linalg.inv(J.T @ J) * (2 * r.cost / (len(obs) - 2))
>>> np.sqrt(np.diag(cov))                 # 参数标准误
array([0.0012, 0.0008])
>>> cov[0, 1] / np.sqrt(cov[0, 0] * cov[1, 1])   # beta 与 gamma 的相关系数
0.5788
```

$\beta$ 与 $\gamma$ 的相关系数是 $+0.58$：两者同向变动时拟合仍然不差。$\mathrm{R0} = \beta/\gamma = 2.60$（真值 2.67）。**在 SIR 类问题里，$\mathrm{R0}$ 与 $\gamma$ 的组合常比 $\beta$ 本身更可辨识**——报告时把 $\mathrm{R0}$ 一起给出，比只给 $\beta$ 更有意义。

**④ 残差量级是否与噪声相符。** $\lVert r\rVert = 43.6$，观测峰值 262.5，噪声水平约 5% × 峰值 = 13.1，最大残差约 2 倍噪声——合理。如果残差远大于噪声，说明模型结构不对（不是参数不对）；远小于噪声，说明过拟合。

> **⚠️ 陷阱（我在写这一节时真的踩了）：参数化写错会让参数变成"不可辨识"，而不是报错。**
>
> 第一版我把传播项写成 `beta*S*I`（**计数形式**，不除以 $N$），并取 $\beta = 0.4$。这时 $R_0 = \beta N/\gamma \approx 2667$——疫情在第一个观测日之前就结束了，我"观测"到的峰值其实是初始条件 $I_0 = 5$ 直接跳到 862。**后果是 $\beta$ 完全不可辨识**：

| $\beta$ | 0.35 | 0.40 | 0.45 | 0.80 | 1.50 | 5.00 |
|---------|------|------|------|------|------|------|
| $\lVert r\rVert$ | 49.558 | 49.490 | 49.441 | 49.291 | 49.218 | **49.168** |

残差范数在 $\beta$ 变化 **14 倍**的范围内只动了 **0.8%**，而且**单调下降、最小值在边界上**。`least_squares` 于是跑到上界 $\beta = 5$ 停下，返回 `status=2`、`nfev=11`、`optimality=0.497`（不是小量），**没有任何报错**。如果我只看 `r.x` 和"拟合残差不大"，就会把一个 $\mathrm{R0}$ 错了 12 倍的结果写进报告。
>
> **教训**：残差小、求解器不报错、参数落在物理范围内——这三件事同时成立也可能全错。**判断反问题成败的唯一可靠方法是 ① 画残差随参数的曲线、② 换几个初值看是否收敛到同一点。** 这两件事在本节例子里只需十几行代码。

### 5.6.4 两个变量的误差：`scipy.odr` 已经弃用

普通最小二乘假设**自变量没有误差**，只有因变量有。如果两个变量都是测量值、都带误差，标准做法是正交距离回归（ODR）。scipy 里曾经有 `scipy.odr`，但它**已经进入删除倒计时**：

```python
>>> import scipy.odr
DeprecationWarning: `scipy.odr` is deprecated as of version 1.17.0
and will be removed in SciPy 1.19.0.
Please use `https://pypi.org/project/odrpack/` instead.
```

三条出路：

1. **误差可忽略时**：直接用 `curve_fit`。判断标准是"自变量相对误差 ≪ 因变量相对误差"。
2. **两个都重要时**：装 `odrpack`（官方指向的替代包），或用 `least_squares` 手工构造"点到曲线的正交距离"作为残差。
3. **换成隐式模型**：把 $y = f(x)$ 改写成 $g(x, y) = 0$，然后最小化 $\sum g(x_i, y_i)^2$。这样两个变量的误差被对称对待，且不需要新依赖。**这是竞赛里最实用的替代方案。**

## 5.7 插值、平滑与数据补全

前面几节的对象都是"有限个未知数"。从本节起换成"一个函数"——给定有限个采样点，要重建出点与点之间的连续对象。这类需求贯穿全卷：`ds-02` 的缺失值填补、`ds-03` 的曲线绘制、传感器数据的等间隔重采样，本质都是插值。

三种任务的界线要先分清：

| 任务 | 数据特点 | 目标 | 工具 |
|------|---------|------|------|
| **插值** | 数据准确、要穿过每个点 | 点之间补值 | `CubicSpline`、`PchipInterpolator` |
| **平滑** | 数据带噪声、不要求穿过每个点 | 提取趋势 | `make_smoothing_spline`、`UnivariateSpline` |
| **拟合** | 已知模型形式 | 求参数 | 5.6 的 `curve_fit` |

**用错类别的代价很直接**：对带噪声的数据做插值，会把噪声当成信号原样复现；对准确数据做平滑，会把真实结构抹平。

### 5.7.1 龙格现象：为什么不能靠"加高点次"

最朴素的想法是"$n$ 个点可以唯一确定一个 $n-1$ 次多项式，那就用它"。这个想法在等距结点上会灾难性失败。用 Runge 函数 $f(x) = 1/(1+25x^2)$ 演示（它在 $[-1,1]$ 两端弯曲最剧烈）：

```python
>>> import scipy.interpolate as si
>>> def runge(x): return 1.0 / (1.0 + 25*x**2)
>>> xs = np.linspace(-1, 1, 2001)                  # 密集检验点
>>> for n in [5, 9, 15, 21]:
...     x = np.linspace(-1, 1, n)
...     p = si.BarycentricInterpolator(x, runge(x))
...     print(f"n={n:2d} 最大误差 {np.abs(p(xs) - runge(xs)).max():.4f}")
```

| 结点数 | 等距 + 高次多项式 | Chebyshev 结点 + 高次多项式 | 等距 + 三次样条 |
|--------|-----------------|------------------------|---------------|
| 5 | 0.4384 | — | — |
| 9 | 1.0452 | 2.05e-01 | 5.62e-02 |
| 15 | 7.1949 | 5.35e-02 | 2.48e-03 |
| 21 | **59.8223** | 1.77e-02 | 3.18e-03 |

逐行读：等距高次插值的误差**随点数增加而爆炸**——21 个点时最大误差 59.8，而函数本身的值域只有 $[0,1]$，插值曲线在端点附近甩出了 60 倍。**"多加点"在这里是负优化。**

两条出路，都不需要高次多项式：

1. **换结点**：用 Chebyshev 结点（$x_k = \cos(k\pi/(n-1))$）代替等距结点，误差随 $n$ 稳定下降（0.205 → 0.0177）。原理是 Chebyshev 结点让 Lebesgue 常数只按 $\log n$ 增长，而等距结点的 Lebesgue 常数按 $2^n$ 增长（`ds-05b` S6 有推导）。
2. **换成分段低次**：三次样条把 $n$ 个点连成 $n-1$ 段三次多项式，段间接缝处保证函数值与一、二阶导连续。误差随 $n$ 稳定下降（0.056 → 0.0032），而且**没有龙格现象**。

> **实战建议**：**默认用样条，不要用高次多项式。** 需要越过原数据点且要光滑，用 `CubicSpline`；需要保持单调性或不过冲，用 `PchipInterpolator`（5.7.2）；需要处理噪声，用平滑样条（5.7.3）。`BarycentricInterpolator` 与 `KroghInterpolator` 只在"数据确实来自多项式"或教学内容里用。

**阶数与点数的对应关系**要先记住，否则会撞上一个不直观的报错：$k$ 阶样条至少需要 $k+1$ 个点。

```python
>>> import scipy.interpolate as si
>>> x = np.arange(3, dtype=float)
>>> si.interp1d(x, x**2, kind="cubic")
ValueError: The number of derivatives at boundaries does not match: expected 1, got 0+0
```

报错信息看不出"点不够"，但只要记住**三次样条至少要 4 个点**就不会被卡住。

### 5.7.2 保形：`CubicSpline` 与 `PchipInterpolator` 的分工

三次样条保证 $C^2$ 连续（二阶导也连续），代价是**可能过冲**：在一个平台段旁边，它会把曲线甩到数据范围之外。用一段有平台的阶梯数据演示：

```python
>>> xd = np.array([0., 1., 2., 3., 4., 5.])
>>> yd = np.array([0., 1., 1., 1., 0., 0.])       # 值域是 [0, 1]
>>> xs = np.linspace(0, 5, 11)
>>> np.round(si.CubicSpline(xd, yd)(xs), 4)
array([ 0.    ,  0.7333,  1.    ,  1.0167,  1.    ,  1.075 ,  1.    ,
        0.5583,  0.    , -0.3083,  0.    ])
>>> np.round(si.PchipInterpolator(xd, yd)(xs), 4)
array([0.    , 0.6875, 1.    , 1.    , 1.    , 1.    , 1.    , 0.5   ,
       0.    , 0.    , 0.    ])
```

`CubicSpline` 给出了 `1.075` 和 `-0.3083`——**超出了数据的值域**。如果这段数据是浓度、概率、比例，结论就荒谬了。`PchipInterpolator`（分段三次 Hermite）在平台段保持精确的常数，在下降段严格单调，**从不越界**。

密集采样下的定量对照：

| 插值方法 | 最小值 | 最大值 | 单调段保持比例 |
|---------|--------|--------|--------------|
| `CubicSpline` | **-0.31130** | **+1.08346** | 249/500 |
| `PchipInterpolator` | +0.00000 | +1.00000 | **400/500** |
| `Akima1DInterpolator` | -0.12500 | +1.00000 | 350/500 |

`PchipInterpolator` 的值域精确等于 $[0,1]$。代价是它只有 $C^1$ 连续（二阶导在结点处跳变），画出来在结点处会有极轻微的不光滑——**在数据可视化和物理量重建里，这个代价几乎总是值得的**。

> **实战建议**：选择规则只有一条——**问"越界会不会导致结论荒谬"**。是（物理量、比率、浓度、必须为正的量），用 `PchipInterpolator`；否（一般趋势曲线、光滑性更重要），用 `CubicSpline`。`Akima1DInterpolator` 介于两者之间，适合数据本身有噪声、又不希望过冲的场合。

### 5.7.3 平滑样条：给带噪声的数据用

数据带噪声时**不应该**穿过每个点。`scipy.interpolate` 提供两个入口，区别在"谁决定光滑度"：

| 入口 | 光滑度控制 | 返回 | 适用 |
|------|-----------|------|------|
| `UnivariateSpline(x, y, s=...)` | **你给** $s$：残差平方和的**目标值** | `UnivariateSpline` 对象 | 你对噪声水平有判断 |
| `make_smoothing_spline(x, y)` | **自动**选光滑参数 | `BSpline` | 不想调参，只要一条好曲线 |

`UnivariateSpline` 的 `s` 参数语义值得单独记：**它要求"所有点的残差平方和 $\le s$"**，求解器在满足这个前提的条件下取最光滑的解。所以 $s$ 应该设成"噪声水平的期望平方和"：

```python
>>> rng_s = np.random.default_rng(0)
>>> x = np.linspace(0, 10, 80)
>>> y = np.sin(x) + rng_s.normal(0, 0.2, x.size)     # 真值 sin(x)，σ = 0.2
>>> for s in [10.0, 1.0, 0.1, 0.0]:
...     sp = si.UnivariateSpline(x, y, k=3, s=s)
...     rss = np.sum((sp(x) - y)**2)
...     print(f"s={s:5.1f} 结点数 {len(sp.get_knots()):3d} 残差平方和 {rss:8.3f} 对真值误差 {np.abs(sp(x)-np.sin(x)).max():.4f}")
s= 10.0 结点数   3 残差平方和   10.000 对真值误差 0.6298
s=  1.0 结点数  43 残差平方和    1.000 对真值误差 0.3862
s=  0.1 结点数  60 残差平方和    0.100 对真值误差 0.4572
s=  0.0 结点数  78 残差平方和    0.000 对真值误差 0.4650
```

两点必须读出来：

1. **残差平方和精确等于 `s`**（10.000 / 1.000 / 0.100）——这就是 `s` 的定义，不是巧合。于是 `s` 有了明确的取值依据：$s \approx n\sigma^2$。本例 $n = 80$、$\sigma = 0.2$，所以 $s \approx 3.2$。
2. **对真值的误差不是单调的**：$s = 10$ 太光滑（0.63），$s = 0$ 太贴合噪声（0.465），中间 $s = 1$ 最好（0.386）。`s = 0` 等于强制穿过每个点，**它就退化成插值**——这正是"用错类别"的后果。

`make_smoothing_spline` 不需要 $s$，它用广义交叉验证自动定光滑度，本例对真值的误差是 **0.188**，比我手工调出来的每个 $s$ 都好：

```python
>>> sp = si.make_smoothing_spline(x, y)
>>> type(sp).__name__, len(sp.t)                  # 注意：返回 BSpline，结点在 .t 而不是 .get_knots()
('BSpline', 86)
>>> np.abs(sp(x) - np.sin(x)).max()
0.188...
```

> **⚠️ 陷阱**：`make_smoothing_spline` 返回的是 `BSpline` 对象，**没有 `get_knots()` 方法**，结点向量是属性 `sp.t`（且包含重复的边界结点）。而 `UnivariateSpline` 返回的是另一个类型，有 `get_knots()`。两个 API 长得像但不一样，混用会得到 `AttributeError`。

> **实战建议**：除非你确实知道噪声水平，**优先用 `make_smoothing_spline`**。它自动选参数、不需要交叉验证代码，而且本节的实测里它的精度最好。需要"残差平方和恰好不超过某个值"这种硬性要求时，才回到 `UnivariateSpline(s=...)`。

### 5.7.4 多维插值：结构网格与散点各一套

数据落在**规则网格**上时用 `RegularGridInterpolator`。它的 `method` 参数决定精度与成本：

| `method` | 最大误差（本节算例） | 说明 |
|----------|-----------------|------|
| `"nearest"` | 1.20e-02 | 最近邻，不连续 |
| `"linear"` / `"slinear"` | 3.02e-03 | 线性，便宜、稳健 |
| `"pchip"` | 2.05e-04 | 保形 |
| `"cubic"` | 1.86e-06 | 三次，推荐默认 |
| `"quintic"` | 2.52e-06 | 五次 |
| `"quintic_legacy"` | 2.62e-08 | 旧实现，仅用于复现历史结果 |

精度从 nearest 到 cubic 提升了 **4 个数量级**。注意 `_legacy` 后缀的三种是**为了复现旧版本结果而保留的**：新代码不要用，但也别惊讶于"同样叫 quintic，两个实现结果不同"。

> **陷阱**：`RegularGridInterpolator` 的合法 `method` 是 `{"linear", "nearest", "slinear", "cubic", "quintic", "pchip"}` 加三个 `_legacy` 变体——**没有 `"quartic"`**。传一个不存在的名字会抛 `ValueError: Method 'quartic' is not defined`。

**外推默认是禁止的**，这是设计上的正确选择：

```python
>>> f = si.RegularGridInterpolator((gx, gy), V, method="linear")
>>> f([[6.0, 1.0]])                       # 网格范围是 [0, 5]²
ValueError: One of the requested xi is out of bounds in dimension 0
```

把 `bounds_error=False` 打开，就要自己承担后果：

```python
>>> f2 = si.RegularGridInterpolator((gx, gy), V, method="linear",
...                                 bounds_error=False, fill_value=None)   # None = 线性外推
>>> f2([[6.0, 1.0]])
array([-0.407707])                        # 真值 -0.150969，差了 2.7 倍
```

`fill_value=None` 表示"沿用边界处的线性趋势往外延伸"。这里真值是 $-0.1510$，外推给出 $-0.4077$——**在网格内精度 $10^{-6}$ 的插值器，往外一步就错 170%**。这是插值类工具最重要的注意事项：

> **⚠️ 陷阱**：插值器**只在数据范围内**有效，范围外它没有任何保证。`fill_value=None`（线性外推）是最危险的选项——它给出一个看起来合理的数字，而不是 `nan`。要么让默认的 `bounds_error=True` 报错，要么显式给 `fill_value=0.0` 或一个哨兵值，**让"没有数据"这件事在结果里看得见**。

**散点数据**（不规则分布）用另一套：

| 入口 | 性质 | 数据少时 | 数据多时 |
|------|------|---------|---------|
| `LinearNDInterpolator` | 分段线性，$C^0$ | 快 | 慢（三角剖分开销） |
| `CloughTocher2DInterpolator` | 分段三次，$C^1$ | 快 | 慢 |
| `NearestNDInterpolator` | 最近邻 | 最快 | 最快 |
| `RBFInterpolator` | 径向基，全局光滑 | 需选核函数 | 推荐 |

```python
>>> f = si.CloughTocher2DInterpolator(pts, vals)
>>> f(q)                                   # q 必须在 pts 的凸包内
```

> **⚠️ 陷阱（我在写本节时撞上的）**：`LinearNDInterpolator`、`CloughTocher2DInterpolator` 与 `griddata` 在**凸包之外返回 `nan`，不报错**。我的算例里查询点 $(0.2, 4.8)$ 落在 200 个随机点的凸包之外，三个插值器一致返回 `nan`（只有 `NearestNDInterpolator` 因为"总能找最近点"而正常返回）。**如果一个 `nan` 悄悄混进了下游计算，整个结果都会被污染。** 拿到散点插值结果后，第一件事就是 `np.isfinite(pred).all()`。

`RBFInterpolator` 是散点插值里质量最好的一个，但要选核函数：

| `kernel` | 最大误差（本节算例） |
|----------|-----------------|
| `"thin_plate_spline"` | 9.32e-02 |
| `"linear"` | 5.96e-02 |
| `"cubic"` | 6.87e-02 |
| `"quintic"` | **1.03e-02** |

`"multiquadric"` 之类的核需要额外给 `epsilon` 参数，否则报错。**默认先试 `"thin_plate_spline"` 或 `"quintic"`，再根据留出误差换。**

### 5.7.5 数据补全：三种策略的实测差别

插值在数据科学里最常见的落地场景是**缺失值填补**。以 $y = \sin(t/3)$ 为例，挖掉连续 3 个点和另外 1 个点，比较三种策略：

```python
>>> t = np.arange(20, dtype=float)
>>> y = np.sin(t / 3)
>>> y_missing = y.copy(); y_missing[[4, 5, 6, 12]] = np.nan
```

| 策略 | 填补点最大误差 | 平均误差 |
|------|-------------|---------|
| 线性插值 `np.interp` | 0.2131 | 0.1429 |
| 前向填充（ffill） | 0.2555 | 0.1519 |
| **三次样条** | **0.0117** | **0.0068** |

三次样条的误差比前两者小 **18 倍**。看具体数值更清楚：

| 缺失位置 | 真值 | 线性 | 前向填充 | 三次样条 |
|---------|------|------|---------|---------|
| 4 | 0.9719 | 0.8119 | 0.8415 | **0.9646** |
| 5 | 0.9954 | 0.7823 | 0.8415 | **0.9837** |
| 6 | 0.9093 | 0.7527 | 0.8415 | **0.9020** |
| 12 | -0.7568 | -0.7151 | **-0.5013** | **-0.7561** |

**前向填充在位置 12 上错得最离谱**（-0.5013 对真值 -0.7568）：它把上一个观测值一路带下去，曲线已经掉头了它还在原地。前向填充是**唯一一个在缺失区间内产生常数的策略**，只要数据有趋势或周期，它必然出错。

> **实战建议**：缺失值填补的选择顺序是——① 缺失比例 < 5% 且数据平滑，用三次样条（`CubicSpline`）；② 数据可能过冲而你无法接受，用 `PchipInterpolator`；③ 缺失段很长（超过整体跨度的 10%），**别用插值**，改用模型（`ds-02` 的插值 + 外推，或卷 3 的回归补全），并**显式记录填补位置**；④ 前向/后向填充只适合"状态类"变量（如"当前是否在促销"），不适合连续测量值。**无论用哪种，都要在报告里写清填补了多少、用了什么方法**——填补出来的数据不是观测数据。

## 5.8 数值积分

原函数不存在或写不出来时，定积分只能算数值。本节的所有工具都基于同一个思想：**用有限次函数求值逼近积分**，区别只在采样点怎么选、误差怎么控。

### 5.8.1 `quad`：自适应求值

`quad` 接受一个**函数**（不是采样点），返回 `(积分值, 误差估计)`：

```python
>>> from scipy.integrate import quad
>>> quad(np.sin, 0, np.pi)
(2.0, 2.220446049250313e-14)
```

它是自适应算法（QUADPACK 的 Gauss–Kronrod，见 `ds-05b` S7）：在被积函数变化剧烈的地方自动加密采样。实测的精度远超预期：

| 积分 | 结果 | 报告误差 | 实际误差 |
|------|------|---------|---------|
| $\int_0^{\pi}\sin x\,dx$ | 2.000000000000 | 2.2e-14 | 0 |
| $\int_0^3 e^{-x^2}dx$ | 0.886207348260 | 3.2e-11 | 4.4e-16 |
| $\int_0^1 x^{-1/2}dx$（端点奇点） | 2.000000000000 | 5.8e-15 | 1.6e-15 |
| $\int_0^1 \ln x\,dx$（端点奇点） | -1.000000000000 | 1.1e-15 | 1.1e-16 |
| $\int_0^1 \cos(50x)\,dx$（震荡） | -0.005247497074 | 6.2e-10 | 2.9e-16 |

**端点奇点不需要特殊处理**——QUADPACK 的变换自动化解了它们，全部达到机器精度。震荡函数 `cos(50x)` 也不需要给任何提示。

**无穷区间直接写 `np.inf`**：

```python
>>> quad(lambda t: np.exp(-t**2), -np.inf, np.inf)
(1.7724538509055159, 1.42e-08)            # 真值 √π
>>> quad(lambda t: 1/(1 + t**2), -np.inf, np.inf)
(3.1415926535897, 5.16e-10)               # 真值 π
```

`quad` 内部做变量替换把无穷区间映到有限区间，精度到 8–10 位。

> **⚠️ 陷阱**：`quad` 返回的第二个值是**误差估计**，不是"真实误差"。上表里两者量级相近，但这不保证总是如此——对高度震荡或有多个奇点的被积函数，误差估计可能严重低估。**报告积分结果时不要只写"误差 1e-12"，要说清用的是哪个积分器**；需要更高可信度时，用两种方法（如 `quad` 与 `fixed_quad`）交叉验证。

需要调参时，两个参数最常用：

| 参数 | 含义 | 什么时候动它 |
|------|------|------------|
| `epsabs` / `epsrel` | 绝对/相对误差目标 | 被积函数量级极小或极大时 |
| `limit` | 子区间数上限 | 报 `IntegrationWarning` 说" subdivision limit reached"时 |
| `points` | 已知的不可导/间断点 | 被积函数有已知拐点时，能显著提速 |

> **版本注意**：`simps`、`trapz`、`cumtrapz`、`romberg`、`quadrature` **在 1.18 中已全部移除**。替代关系是 `simps → simpson`、`trapz → trapezoid`、`cumtrapz → cumulative_trapezoid`；`romberg` 与 `quadrature` 没有直接替代，需要就自己写或用 `fixed_quad`。**连 `np.trapz` 也没了**（NumPy 2.0 起改名为 `np.trapezoid`），所以网上大量旧代码在这里会直接 `AttributeError`。

### 5.8.2 只有采样点：`trapezoid` 与 `simpson`

实验数据往往只有一张"$x$–$y$ 表"，没有可调用的函数。这时用采样点积分：

```python
>>> from scipy.integrate import trapezoid, simpson, cumulative_trapezoid
>>> x = np.linspace(0, np.pi, 101)
>>> y = np.sin(x)
>>> trapezoid(y, x), simpson(y, x)
(1.9998355038874434, 2.0000000108245044)      # 真值 2
```

两者的收敛阶不同，这是本节最该记住的一个数量关系。真值是 2：

| 采样点数 | 梯形法误差 | Simpson 误差 | 梯形收敛 | Simpson 收敛 |
|---------|-----------|-------------|---------|-------------|
| 11 | 1.648e-02 | 1.095e-04 | — | — |
| 101 | 1.645e-04 | 1.082e-08 | 100.2× | 10118× |
| 1001 | 1.645e-06 | 1.082e-12 | 100.0× | 10000× |

**点数增加 10 倍，梯形误差降 100 倍（$O(h^2)$），Simpson 误差降 10000 倍（$O(h^4)$）**。在 1001 个点上，Simpson 的误差比梯形小 **6 个数量级**。所以：

> **实战建议**：**只要有奇数个等距采样点，就用 `simpson` 不用 `trapezoid`**。代价相同（都是一次遍历），精度差好几个数量级。唯一用梯形的场合是：采样点不等距且你只想快速估个量级，或者数据有跳变（梯形不会像 Simpson 那样在间断处产生振荡）。

**累积积分**给的是"从起点到每个点的积分值"，是求分布函数、累积量的标准工具：

```python
>>> x = np.linspace(0, 1, 6)
>>> cumulative_trapezoid(x**2, x, initial=0)
array([0.    , 0.004 , 0.024 , 0.076 , 0.176 , 0.34  ])
>>> x**3 / 3                                # 真值 x³/3
array([0.        , 0.002667, 0.021333, 0.072   , 0.170667, 0.333333])
```

`initial=0` 表示"起点处累积值为 0"；省略它则返回数组比输入短一个元素。累积 Simpson 用 `cumulative_simpson`（要求偶数个区间）。

### 5.8.3 多重积分

```python
>>> from scipy.integrate import dblquad, nquad
>>> dblquad(lambda y, x: x*y, 0, 1, 0, 1)[0]
0.24999999999999997                      # ∫∫ xy over [0,1]²，真值 0.25
>>> nquad(lambda x, y, z: x*y*z, [[0, 1], [0, 1], [0, 1]])[0]
0.12499999999999999                      # 真值 0.125
```

两点要注意：`dblquad` 的**参数顺序是反的**（内层积分变量在前，函数签名是 `f(y, x)`）；`nquad` 的写法更自然但更慢。**维数超过 3 就别用它们**——多重积分的计算量随维数指数增长，转去 5.10 的蒙特卡洛积分（误差与维数无关）。

## 5.9 微分方程与动力学建模

"系统的状态随时间怎么变"是建模里另一条主干。人口增长、传染病、化学反应、电路、机械振动、热传导，写下来都是

$$\frac{dy}{dt} = f(t, y), \qquad y(t_0) = y_0$$

这一类叫**初值问题**（IVP）。本节讲它怎么解、为什么解不动、以及怎么确认解对了。5.6.3 已经用过一次 `solve_ivp` 做参数反演，那里它是"内层工具"；本节把注意力放到它自己身上。

### 5.9.1 一阶化：把任何方程写成标准形式

`solve_ivp` 只接受**一阶方程组**。高阶方程要手工降阶，方法固定：**把每一阶导数都定义成一个新变量**。

以阻尼振子 $\ddot{x} + 2\zeta\omega\dot{x} + \omega^2 x = 0$ 为例，令 $y_0 = x$、$y_1 = \dot{x}$：

```python
def damped(t, y, zeta, omega):
    x, v = y
    return [v, -2*zeta*omega*v - omega**2*x]
```

```python
>>> from scipy.integrate import solve_ivp
>>> sol = solve_ivp(damped, [0, 20], [1.0, 0.0], args=(0.1, 2.0), t_eval=np.linspace(0, 20, 201))
>>> sol.y.shape                            # (状态维数, 时间点数)
(2, 201)
```

参数表的用法与前几节一致：

| 参数 | 作用 | 注意 |
|------|------|------|
| `t_span` | `(t0, tf)`，必须是二元素 | 不能给数组 |
| `y0` | 初值向量 | 必须是向量，标量要写成 `[y0]` |
| `args` | 传给 `f` 的额外参数 | 顺序在 `t, y` 之后 |
| `t_eval` | 在哪些时刻取输出 | **不给则返回求解器自选的时间点** |
| `dense_output=True` | 返回连续解对象 `sol.sol` | 之后可在任意时刻求值 |
| `method` | 算法 | 见 5.9.2 |
| `rtol` / `atol` | 相对/绝对误差目标 | 见 5.9.6 |

> **⚠️ 陷阱**：不给 `t_eval` 时，`sol.t` 是**求解器内部的自适应步点**，点数与位置都不可预期。做曲线图或与实验数据比较时，一定要显式给 `t_eval`，否则两次运行会因为容差差异给出不同长度的数组。

### 5.9.2 方法选择：刚性是最大的分水岭

`method` 有三类：显式 Runge–Kutta（`RK45`、`RK23`、`DOP853`）、隐式（`Radau`、`BDF`）、自动切换（`LSODA`）。**选错的代价可以有三个数量级。**

用一个经典的刚性方程实测：$y' = -1000(y - \cos t) - \sin t$，真解是 $y = \cos t$。

```python
>>> def stiff(t, y):
...     return [-1000*(y[0] - np.cos(t)) - np.sin(t)]
>>> for m in ["RK45", "DOP853", "BDF", "Radau", "LSODA"]:
...     s = solve_ivp(stiff, [0, 1], [1.0], method=m, rtol=1e-6, atol=1e-9)
```

| `method` | `nfev` | `njev` | 内部步数 | 末值误差 | 耗时 |
|----------|--------|--------|---------|---------|------|
| `RK45`（默认） | 2162 | 0 | 360 | 1.14e-07 | 6.3 ms |
| `DOP853` | 2870 | 0 | 175 | 1.04e-08 | 7.2 ms |
| `BDF` | **54** | 2 | **25** | 4.95e-09 | 2.2 ms |
| `Radau` | 84 | 1 | **11** | 8.34e-10 | 1.3 ms |
| `LSODA` | 126 | 10 | 59 | 4.31e-10 | **0.4 ms** |

**同一精度目标下，RK45 比 Radau 多算了 26 倍函数调用、多走了 33 倍内部步。** 而 `Radau` 的误差还更小。这就是刚性的代价，也是本节最实用的一条经验。

判断是不是刚性，看**系统雅可比矩阵特征值的量级跨度**：

$$\text{刚性比} = \frac{\max_i |\mathrm{Re}\,\lambda_i|}{\min_i |\mathrm{Re}\,\lambda_i|}$$

本例只有一个特征值 $\lambda = -1000$，而解的振荡尺度是 $2\pi$，比值约 159 倍——不算极端，已经让显式方法多花 26 倍。**工程上比值超过 $10^3$ 就应当直接上隐式方法。**

> **机制洞察**：显式方法的步长被**稳定性**而不是精度限制。对 $\lambda = -1000$，显式 RK 的稳定域要求 $h \lesssim 2.8/1000 = 0.0028$，而解本身在 1 秒内只变化一个周期——精度只要求 $h \approx 0.01$。于是步长被压小了 3 倍多，而且**系统越刚，压得越狠**。隐式方法（Radau/BDF）的稳定域覆盖整个左半平面，可以用精度允许的步长。完整推导见 `ds-05b` S5。

> **实战建议**：**先用 `LSODA`**。它自动检测刚性并在显式/隐式之间切换，本节实测它在这道题上最快（0.4 ms）且最准（4.31e-10）。当你确认了问题性质，再换成专一的方法：非刚性用 `DOP853`（高精度需求）或 `RK45`（一般），刚性用 `Radau`（精度优先）或 `BDF`（速度优先）。

### 5.9.3 事件：抓"什么时候发生"

实际问题常常不问"$t$ 时刻状态是多少"，而问"**什么时候状态达到某个条件**"——落地时刻、种群灭绝时刻、温度降到阈值时刻。这就是事件（event），是 `solve_ivp` 最容易被忽略也最实用的功能。

事件是一个返回标量的函数，求解器在它变号时用求根算法精确定位时刻：

```python
>>> def proj(t, y):                        # 抛体：y[0] = 高度，y[1] = 速度
...     return [y[1], -9.81]
>>> def hit(t, y):
...     return y[0]                        # 高度为 0 即落地
>>> hit.terminal = True                    # 触发后停止积分
>>> hit.direction = -1                     # 只抓下降方向的穿越
>>> s = solve_ivp(proj, [0, 5], [0, 10], events=hit, dense_output=True)
>>> s.t_events[0][0], 2*10/9.81
(2.038735983690112, 2.038735983690112)      # 与解析解完全一致
```

结果存在 `s.t_events`（时刻列表）与 `s.y_events`（状态列表）里，**都是列表**——一个事件函数可能触发多次。`hit.terminal = True` 与 `hit.direction = -1` 是**给函数对象挂属性**，不是传参，这个写法有点特别但必须这样写。

**不设 `terminal` 就会抓到所有穿越**：

```python
>>> def wave(t, y): return [y[1], -y[0]]   # y'' = -y，从 (1, 0) 出发
>>> def cross(t, y): return y[0]
>>> cross.terminal = False
>>> cross.direction = -1                   # 只要下降穿越
>>> s = solve_ivp(wave, [0, 20], [1.0, 0.0], events=cross, rtol=1e-8, atol=1e-11)
>>> np.round(s.t_events[0], 6)
array([ 1.570796,  7.853982, 14.137167])   # 即 π/2, 5π/2, 9π/2
```

$y = \cos t$，向下穿零发生在 $\pi/2 + 2k\pi$——`direction=-1` 精确筛掉了向上穿越的那些，结果与理论完全吻合（误差 $2.8\times10^{-9}$）。

**事件时刻的精度由积分容差决定**，这一点在多次穿越时尤其明显：

| `rtol` | 最大时刻误差 |
|--------|-----------|
| $10^{-3}$ | 4.00e-03 |
| $10^{-8}$ | 2.77e-09 |
| $10^{-11}$ | 6.20e-13 |

> **实战建议**：事件定位本身用的是求根，精度很高；误差主要来自**积分轨迹本身的误差**。所以如果你的报告要写"疫情在第 37.2 天达到峰值"，就得把 `rtol` 收紧到 $10^{-9}$ 以下，否则那个小数位是假的。单次穿越且轨迹简单时（如抛体），默认容差就能到机器精度。

`dense_output=True` 让解变成可调用对象，用于取任意时刻的值：

```python
>>> s.sol(1.0)                             # 抛体在 t = 1.0 时的 [高度, 速度]
array([5.095, 0.19 ])                      # 解析值 [10 - 0.5*9.81, 10 - 9.81]
```

它比"给很密的 `t_eval` 再插值"更准也更省，因为用的是求解器内部的连续延拓多项式。

### 5.9.4 边界值问题：`solve_bvp`

初值问题的条件是"起点已知"，边界值问题（BVP）是"两端各知一些"。典型例子：一根两端固定的梁、稳态温度分布、两点边值问题。

```python
>>> from scipy.integrate import solve_bvp
>>> def ode(x, y):
...     return np.vstack([y[1], -y[0]])        # y'' + y = 0
>>> def bc(ya, yb):
...     return np.array([ya[0] - 0.0, yb[0] - np.sin(2.0)])   # y(0)=0, y(2)=sin2
>>> x = np.linspace(0, 2, 10)                  # 初始网格
>>> sol = solve_bvp(ode, bc, x, np.zeros((2, 10)))   # 初始猜测
>>> sol.status, sol.message
(0, 'The algorithm converged to the desired accuracy.')
>>> sol.x.size, sol.rms_residuals.max()
(10, 5.7679153151141686e-05)
```

三个要点：

1. **`solve_bvp` 要初始网格和初始猜测**，前者是 `x`，后者是与 `x` 同长的解数组。本例用全 0 猜测也能收敛（因为方程是线性的），非线性问题就需要好一点的猜测。
2. **返回字段是 `niter` 不是 `nit`**，另外有 `rms_residuals`（每个网格点上的残差均方根）——这是判断收敛质量的主要指标。`status=0` 只说"算法认为收敛了"，`rms_residuals` 才给出"收敛到什么程度"。
3. **`solve_bvp` 会自动加密网格**，`sol.sol` 提供连续解。本例 10 个网格点上解的最大误差 $1.03\times10^{-5}$、网格残差均方根 $5.8\times10^{-5}$，需要更高精度就调 `tol`。

> **实战建议**：`solve_bvp` 比 `solve_ivp` 难用得多，因为同时要处理"两端条件"和"初始猜测"。**能用初值问题凑出来的就别用 BVP**：打靶法（把未知初值当参数、用 `solve_ivp` + `brentq` 逼近边界条件）在低维问题上更直观，也更方便复用 5.4.5 的求根与 5.6 的拟合工具。BVP 求解器的优势在网格自适应和高精度需求。

### 5.9.5 验证四件套

微分方程的解没有"残差"这种便宜检查（方程是连续对象），所以验证要靠另外四件事。**至少做两件**：

**① 解析解对照。** 有解析解就用它——这是唯一"确定性"的验证。5.9.2 的刚性方程真解是 $\cos t$，直接比末值。

**② 守恒量。** 无阻尼摆的机械能应当守恒。跑 20 秒看能量漂移：

| `rtol` | 能量相对漂移 | 步数 |
|--------|-----------|------|
| $10^{-3}$ | 3.40e-02 | 67 |
| $10^{-6}$ | 2.02e-05 | 274 |
| $10^{-9}$ | 2.07e-08 | 1094 |

漂移随容差**线性变小**（$10^{-3} \to 10^{-9}$ 降了 6 个数量级，漂移也降了 6 个数量级）。**守恒量是检验长时间积分的最佳工具**：它不要求知道真解，而且对系统性偏差极其敏感——如果方法选错或步长太大，能量会单向漂移而不是随机波动。

**③ 收敛阶。** 把 `rtol` 每次收紧 100 倍，看误差降多少。同样测 $y' = y$（真解 $e^t$）：

| `rtol` | `RK45` 误差 | `BDF` 误差 | `RK45` 的 `nfev` |
|--------|-----------|-----------|----------------|
| $10^{-4}$ | 1.12e-05 | 8.95e-04 | 20 |
| $10^{-6}$ | 4.14e-07（↓27×） | 1.15e-05（↓78×） | 32 |
| $10^{-8}$ | 5.08e-09（↓82×） | 4.03e-07（↓28×） | 74 |
| $10^{-10}$ | 5.35e-11（↓95×） | 3.92e-09（↓103×） | 170 |

误差大致随 `rtol` **成正比**下降（每收紧 100 倍，误差降 30–100 倍）。**如果误差几乎不降，说明你不是在被容差限制，而是被别的东西限制**——最常见的是事件定位精度、刚性导致的隐式迭代误差、或者解本身不光滑。

**④ 步长/容差加密。** 把 `rtol` 和 `atol` 同时收紧一个数量级，看结果变化多少。如果变化超过你的报告精度，说明之前的结果不可信。这和第 4 章"重采样分辨率"（4.8.5）是同一个思路：**报告精度必须小于数值分辨率**。

> **⚠️ 陷阱**：`solve_ivp` 的 `rtol` 是**逐分量相对误差**，如果某个分量的值跨越 0（例如振荡解的过零点），相对误差在零点附近没有意义，此时 `atol` 才是实际控制量。**对解会过零的问题，`atol` 必须显式给**（例如 `atol=1e-9`）。默认 `atol=1e-6`，对量级 $10^{-3}$ 以下的物理量会完全失效。

## 5.10 随机模拟与不确定性量化

前九节都在"算出唯一答案"。现实中更常见的是：**输入本身不确定，答案也应该是一个分布**。5.2.6 第 5 步已经小规模用过这个思路（给投入产出系数加 2% 扰动看总产出的波动），本节把它系统化。

蒙特卡洛的地基在 `ds-00` 0.4.3 与 `ds-04` 4.8 已经打好。本节只讲三件在 `ds-04` 里没有的事：**低差异序列（QMC）**、**全局敏感性**、**方差缩减**。

### 5.10.1 低差异序列：把采样点摆得更均匀

朴素蒙特卡洛用伪随机数：点与点之间没有任何"不重叠"的保证，偶尔会扎堆、也会留下空洞。**低差异序列（quasi-Monte Carlo，QMC）** 用确定性的构造刻意避开这两种情况，让点尽可能均匀地铺满空间。

```python
>>> from scipy.stats import qmc
>>> sampler = qmc.Sobol(d=8, scramble=True, rng=1)
>>> pts = sampler.random(4096)             # 4096 × 8，每个分量在 [0, 1)
```

测一个 $d = 8$ 维积分 $\int_{[0,1]^8}\prod_i \cos x_i\,dx$，真值 $(\sin 1)^8 = 0.25136984$。为公平起见，每档规模重复 200 次取**中位误差**：

| 点数 $N$ | 朴素 MC | **Sobol** | Halton | 拉丁超立方 LHS |
|---------|--------|----------|--------|--------------|
| 256 | 4.84e-03 | 3.00e-04 | 7.56e-04 | 1.53e-03 |
| 1024 | 2.34e-03 | 4.84e-05 | 1.96e-04 | 8.81e-04 |
| 4096 | 1.20e-03 | 9.79e-06 | 6.02e-05 | 3.69e-04 |
| 16384 | 7.16e-04 | **1.81e-06** | 1.56e-05 | 2.01e-04 |
| 收敛率 | $\sim N^{-1/2}$ | $\sim N^{-1}$ | $\sim N^{-0.75}$ | $\sim N^{-0.5}$ |

读法：

1. **朴素 MC 的误差按 $N^{-1/2}$ 下降**（点数 ×4，误差 ÷2），这是它的定义性质，与维数无关。
2. **Sobol 按 $\sim N^{-1}$ 下降**（点数 ×4，误差 ÷5）。在 $N = 16384$ 时 Sobol 比 MC 精确 **396 倍**——相当于把 MC 的样本量增加 15 万倍才能追平。
3. **LHS 的表现远不如 Sobol**（只比 MC 好 3.5 倍）。原因很直接：LHS 只保证**每个一维边缘**被均匀分层，对高维的联合分布没有任何保证——它是"一维均匀"，不是"高维均匀"。

用 `discrepancy`（星差异，越小越均匀）可以直接看到这个区别：

```python
>>> for cls in [qmc.Sobol, qmc.Halton, qmc.LatinHypercube]:
...     pts = cls(3, scramble=True, rng=7).random(512)
...     print(cls.__name__, qmc.discrepancy(pts))
Sobol 1.0e-05
Halton 1.83e-05
LatinHypercube 1.34e-04
```

Sobol 的差异比 LHS 小 **13 倍**，与积分误差的差距一致。

> **⚠️ 陷阱：Sobol 序列要求点数取 2 的幂。** `Sobol.random(n)` 内部按 $2^k$ 的块生成，如果 `n` 不是 2 的幂，最后一块会被截断，**破坏序列的平衡性**（每个子区间里的点数不再相等）。scipy 不会报错。**始终取 `n = 2**k`**（256、1024、4096……），需要其他点数时改用 `Halton`。

> **实战建议**：`scramble=True` 是必选项。未随机化的 Sobol 点是确定性序列，**无法用来估计误差**（每重复一次结果完全一样）。加 `scramble=True` 并传独立的 `rng=`，才既能享受低差异，又能通过多次重复给出误差条。本节所有 QMC 结果都用了 `scramble=True` 与不同种子。

**QMC 不是万能的**：它的优势随维数衰减，$d$ 超过约 20 后优势基本消失。但建模问题里的不确定性维度通常只有 3–10，正是 QMC 的甜区。

### 5.10.2 全局敏感性：OAT 会骗人

拿到一个模型 $y = f(x_1, \dots, x_k)$，想知道"哪个输入对输出的不确定性影响最大"。最直觉的做法是**一次一因子**（OAT）：把其他参数固定在中点，单独扰动某一个，看输出变化多少。

OAT 给出的是**局部斜率**，而我们要的是**方差贡献**——两者不是一回事。看一个只有两个参数、可解析计算的例子：

$$y = b\,x_0 + c\,x_1^2, \qquad b = 2,\; c = -1.5,\qquad x_i \sim \mathrm{U}(0,1)$$

方差可以精确分解：$\mathrm{Var}(b x_0) = b^2/12 = 0.3333$，$\mathrm{Var}(c x_1^2) = c^2(1/5 - 1/9) = 0.2000$，于是**一阶 Sobol 指数**

$$S_1^{(0)} = \frac{0.3333}{0.5333} = 0.625, \qquad S_1^{(1)} = \frac{0.2000}{0.5333} = 0.375$$

用蒙特卡洛的 Saltelli 估计量 $\hat S_i = \dfrac{\overline{Y_B(Y_{AB_i} - Y_A)}}{\widehat{\mathrm{Var}}(Y)}$ 去估：

```python
>>> # A、B 是两批独立样本；AB_i 是把 A 的第 i 列换成 B 的第 i 列
>>> S1 = np.mean(Y_B * (f(AB_i) - Y_A)) / np.var(np.r_[Y_A, Y_B])
```

| 方法 | 参数 0 | 参数 1 |
|------|--------|--------|
| **解析值** | **0.625** | **0.375** |
| MC 估计（$N = 8192$，50 次重复的均值 ± 标准差） | 0.6242 ± 0.0152 | 0.3749 ± 0.0095 |
| OAT 的 ±1% 局部扰动（中心点） | +0.04000 | −0.03000 |

MC 估计精确复现了解析值。而 OAT 给出的两个数（0.040 与 −0.030）比值是 1.333，与真实的方差贡献比 1.667 **不一致**——它只反映了中心点处的局部斜率，换个中心点就会变。OAT 会在以下三种情况下给出**定性错误**的答案：

| 情形 | OAT 的表现 | 全局指数的表现 |
|------|-----------|--------------|
| **参数之间有交互** | 在特定点上可能得到 0 | 主效应 + 交互效应都能量化 |
| **非线性很强** | 只反映中点斜率 | 覆盖整个取值域 |
| **参数分布在远离中点的区域** | 完全看不到 | 正常 |

**交互效应的定量例子**：取 $y = x_0 x_1$、$x_i \sim \mathrm{U}(0,1)$。解析上 $\mathrm{Var}(Y) = 1/9 - 1/16 = 0.048611$，而 $\mathrm{Var}(E[Y \mid x_0]) = 1/48 = 0.020833$，于是

$$S_1^{(0)} = S_1^{(1)} = \frac{1/48}{1/9 - 1/16} = \frac{3}{7} \approx 0.4286, \qquad S_1^{(0)} + S_1^{(1)} = \frac{6}{7} \approx 0.857$$

**两个主效应加起来只有 0.857，剩下的 0.143 全部来自交互项。** MC 估计给出 $S_1 = [0.4535, 0.4212]$、总效应 $S_T = [0.5581, 0.5927]$——$S_T > S_1$ 正是交互作用的标志。而 OAT 在 $(0, 0.5)$ 处对 $x_0$ 扰动得到 $\Delta y = 0.01$、对 $x_1$ 扰动同样得到 $0.01$，**完全看不出交互**。

> **实战建议**：敏感性的正确做法是——① **先做 OAT 做粗筛**（便宜，能排除明显不重要的参数）；② **再用方差分解做全局指数**（`S1` 给主效应、`ST` 给总效应，$S_T - S_1$ 就是交互贡献）；③ **参数个数超过 10 时先用 Morris 筛选法降维**，再对少数重要参数算 Sobol 指数。scipy 没有现成的敏感性分析函数（`SALib` 是专用库），但 Saltelli 估计量只有几行代码，本节已经给出。

> **机制洞察**：Sobol 指数是一个**方差比**，不是简单积分。所以它**不能**直接享受 5.10.1 那样的 QMC 加速——把 MC 点直接换成 Sobol 点，估计量的统计性质会改变，实测方差反而更大（本节试过：$S_1$ 的标准差从 0.015 涨到 0.48）。要加速必须重新设计估计量，这属于 `ds-05b` S8 的范围。**"QMC 更快"这条经验只对期望型估计量成立。**

### 5.10.3 方差缩减：用同样的算力换更高精度

估计 $\int_0^1 e^{-x^2}dx = 0.7468241328124271$，用三种各 4096 次采样的策略各重复 300 次：

| 策略 | 平均绝对误差 | 相对朴素 MC 的提升 |
|------|------------|-----------------|
| 朴素 MC | 2.304e-03 | — |
| **对偶变量**（antithetic） | 5.280e-04 | 4.4× |
| **分层抽样**（stratified） | **3.748e-05** | **61×** |

- **对偶变量**：把每个样本 $u$ 配一个 $1-u$。若被积函数单调，两者误差反号，取平均后抵消。本例 4.4 倍提升，成本为零。
- **分层抽样**：把 $[0,1]$ 划成 $k$ 个等宽区间，每区各放 $n/k$ 个点。**保证每个区间都有代表**，从而消掉"某段没抽到点"这种最大误差来源。61 倍提升是本节最高效的手段。

```python
>>> k = int(np.sqrt(n)); edges = np.linspace(0, 1, k + 1)
>>> w = np.diff(edges)                                   # ⚠️ 不是 edges[1] - edges[:-1]
>>> xs = edges[:-1, None] + u * w[:, None]               # u 是 k×k 的均匀随机数
```

> **⚠️ 陷阱（我在这里写错过一次）**：上面那行宽度必须写成 `np.diff(edges)`。我第一次写成 `edges[1] - edges[:-1]`——`edges[1]` 是标量，减去数组后得到一组**递减的**宽度，最后几个甚至是负数，把样本推到了 $[0,1]$ 之外。结果分层抽样的误差是 0.159，比朴素 MC 差 **69 倍**，而代码不报任何错。**向量化代码里 `arr[k] - arr[:-1]` 与 `arr[k:] - arr[:-1]` 的差别不会报错，只会静默给出错误结果**；凡是涉及"相邻差分"的地方都应该直接用 `np.diff`。

**重要性抽样**解决的是另一类问题：**稀有事件**。估计标准正态分布 $P(X > 3)$（真值 0.0013499），朴素 MC 要用 $n$ 个样本去数"超过 3 的有几个"：

| $n$ | 朴素 MC 平均相对误差 | 重要性抽样 | 提升 |
|-----|------------------|-----------|------|
| 1000 | 68.6% | 5.3% | 13.1× |
| 5000 | 30.3% | 2.2% | 13.9× |
| 20000 | 15.3% | 1.0% | 14.6× |

做法是换一个提议分布：从 $\mathrm{N}(3, 1)$ 而不是 $\mathrm{N}(0,1)$ 采样，再用似然比 $w = \phi(z)/\phi(z-3)$ 加权修正。**直觉是"把采样预算花在事件真正发生的地方"，然后用权重把偏差修回来。** 对于概率 $10^{-6}$ 量级的失效分析，朴素 MC 需要的样本量是不可行的，重要性抽样是唯一出路。

> **实战建议**：方差缩减手段的选择顺序是——① **分层抽样**（收益最大，实现最简单，只要知道如何分层）；② **对偶变量**（零成本，对单调函数几乎总是有用）；③ **重要性抽样**（只在稀有事件估计时必要，且需要选提议分布）。**先跑朴素 MC 拿到基准误差，再上手段对照**——如果不量一次基准，就不知道"优化"到底有没有用。

### 5.10.4 可复现的随机优化

5.4.4 用到过随机优化。这里补一条纪律：`differential_evolution` 同时接受 `rng=` 与遗留的 `seed=`，**同时传两个会直接报错**：

```python
>>> differential_evolution(f, bounds, rng=np.random.default_rng(42), seed=0)
TypeError: differential_evolution() got multiple values for argument now known as `rng`.
```

只传 `rng=`，同一台机器上结果逐位可复现：

```python
>>> r1 = differential_evolution(rastrigin, [(-5.12, 5.12)]*2, rng=np.random.default_rng(42))
>>> r2 = differential_evolution(rastrigin, [(-5.12, 5.12)]*2, rng=np.random.default_rng(42))
>>> np.array_equal(r1.x, r2.x)
True
```

换个种子，最优值仍然是 0（Rastrigin 的真全局最优），但 `nfev` 从 1863 变成 1923——**随机优化里"结果稳定"和"过程稳定"是两件事**。报告随机算法的结果时，标准做法是**跑多次、报告成功率与最优值的分布**，而不是只报一次。这一点与 5.4.4 的"多起点 0/50"是同一条教训的另一面。

## 5.11 图、网络与匹配

很多建模问题的最自然表达是**图**：城市网络、供应网络、通信网络、社交关系、任务依赖。scipy 的图算法集中在 `sparse.csgraph`，它的世界观是"**图就是稀疏邻接矩阵**"——不做图的类，只做矩阵的运算。

### 5.11.1 邻接矩阵即图

$N$ 个节点的图用一个 $N \times N$ 矩阵 $W$ 表示：$W_{ij}$ 是从 $i$ 到 $j$ 的边权，0 表示没有边。**对角线必须是 0**（否则自环会被当成边），`directed=False` 表示按无向图处理（$i \to j$ 与 $j \to i$ 等价）。

```python
>>> from scipy.sparse import csr_array
>>> from scipy.sparse.csgraph import shortest_path, reconstruct_path, yen
>>> W = csr_array([[0, 4, 0, 0, 0, 0],
...                [4, 0, 8, 0, 0, 0],
...                [0, 8, 0, 7, 0, 4],
...                [0, 0, 7, 0, 9, 14],
...                [0, 0, 0, 9, 0, 10],
...                [0, 0, 4, 14, 10, 0]], dtype=float)
```

用稠密 `csr_array` 只是为了写得清楚；真实路网应当用 `coo_array` 从边列表构造，**稀疏是 csgraph 的性能前提**。

### 5.11.2 最短路：五种方法选一个

`shortest_path` 的 `method` 参数有五种取值：

| 代号 | 算法 | 适用 | 复杂度 |
|------|------|------|--------|
| `"D"` | Dijkstra | 非负权、单源 | $O(E \log V)$ |
| `"BF"` | Bellman-Ford | **允许负权**、单源 | $O(VE)$ |
| `"J"` | Johnson | 允许负权、全源 | $O(VE + V^2\log V)$ |
| `"FW"` | Floyd–Warshall | 全源、允许负权 | $O(V^3)$ |
| `"auto"` | 自动选择 | 默认 | — |

六个节点的小图上五种方法结果完全一致：

| `method` | `d[0]`（节点 0 到各点的距离） |
|----------|---------------------------|
| `"D"` / `"BF"` / `"J"` / `"FW"` / `"auto"` | `[0, 4, 12, 19, 26, 16]` |

选法很简单：**没有负权就用 `"D"`；有负权用 `"BF"`（单源）或 `"J"`（全源）；只要求任意两点的距离、图又很小，用 `"FW"`。** `"auto"` 在多数情况下等价于 `"D"`。

> **⚠️ 陷阱：`return_predecessors=True` 返回的数组形状随 `indices` 变化。** `indices` 是标量时返回一维数组，是列表时返回二维：

| 调用 | `d` 的形状 | `pred` 的形状 |
|------|-----------|-------------|
| `shortest_path(W, directed=False)` | $(N, N)$ | $(N, N)$ |
| `shortest_path(W, indices=0, ...)` | $(N,)$ | $(N,)$ |
| `shortest_path(W, indices=[0], ...)` | $(1, N)$ | $(1, N)$ |

写通用函数时用 `indices=[i]` 更安全，因为形状固定。

**`reconstruct_path` 返回的不是路径，是最短路径树。** 这是本节最容易误解的一处：

```python
>>> d, pred = shortest_path(W, method="D", directed=False, indices=0,
...                         return_predecessors=True)
>>> pred
array([-9999,     0,     1,     2,     5,     2])
>>> tree = reconstruct_path(W, pred, directed=False)
>>> type(tree).__name__, tree.shape, tree.nnz
('csr_array', (6, 6), 5)
```

它以 `pred` 为父指针，构造出**以源点为根的一棵生成树**（5 条边对应 6 个节点）。想拿到"0 到 5 的路径"，得自己沿 `pred` 回溯：

```python
def path_from_pred(pred, src, dst):
    """沿前驱数组回溯出 src -> dst 的路径。"""
    if src == dst: return [src]
    p = [dst]
    while p[-1] != src:
        nxt = int(pred[p[-1]])
        if nxt < 0 or len(p) > len(pred): return None      # 不可达
        p.append(nxt)
    return p[::-1]
```

```python
>>> for dst in [3, 4, 5]:
...     p = path_from_pred(pred, 0, dst)
...     print(p, sum(W[p[k], p[k+1]] for k in range(len(p)-1)))
[0, 1, 2, 3] 19.0
[0, 1, 2, 5, 4] 26.0
[0, 1, 2, 5] 16.0
```

三条路径的代价与 `d` 完全对上。`pred` 里的 `-9999` 是"无前驱"的哨兵值（源点与不可达点）。

**K 短路**用 `yen`（1.14 新增），注意它的返回值也有两种形态：

```python
>>> yen(W, 0, 5, K=3, directed=False)                     # 只返回代价
array([16., 33., 38.])
>>> costs, preds = yen(W, 0, 5, K=3, directed=False, return_predecessors=True)
>>> [(path_from_pred(preds[k], 0, 5), costs[k]) for k in range(3)]
[([0, 1, 2, 5], 16.0), ([0, 1, 2, 3, 5], 33.0), ([0, 1, 2, 3, 4, 5], 38.0)]
```

**默认只给代价**，这是一个容易踩的坑：想拿路径必须显式写 `return_predecessors=True`，此时 `preds` 的形状是 $(K, N)$。

### 5.11.3 连通性、最小生成树与最大流

```python
>>> from scipy.sparse.csgraph import (connected_components, minimum_spanning_tree,
...                                   maximum_flow)
>>> connected_components(W, directed=False)[0]
1                                          # 连通分量个数
>>> mst = minimum_spanning_tree(W)
>>> mst.nnz, mst.sum()
(5, 32.0)                                  # 5 条边连接 6 个节点，总权 32.0
```

`minimum_spanning_tree` 返回的**也是一棵稀疏树**（`nnz = N-1` 若连通）。它的典型用途是聚类前处理（MST 上最长的边往往就是簇的分界）与网络设计（用最小成本连通所有节点）。

**最大流**返回一个对象而不是标量：

```python
>>> G = csr_array([[0, 3, 2], [0, 0, 1], [0, 0, 0]], dtype=np.int32)
>>> mf = maximum_flow(G, 0, 2)
>>> mf.flow_value, type(mf).__name__
(3, 'MaximumFlowResult')
>>> mf.flow.toarray()
array([[ 0,  1,  2],
       [-1,  0,  1],
       [-2, -1,  0]])
```

`flow` 矩阵是**反对称**的：`flow[i, j] = -flow[j, i]`。正值表示净流量从 $i$ 到 $j$。要拿到最小割，对残留网络再跑一次连通性分析即可。`maximum_flow` 还支持 `method=` 参数（默认 `"dinic"`）。

### 5.11.4 匹配：三个入口的分工

| 需求 | 入口 | 返回 |
|------|------|------|
| 二分图最大基数匹配（只问"最多配几对"） | `maximum_bipartite_matching` | 每个节点配到的对方编号 |
| 二分图**带权**完全匹配（每对有权重） | `min_weight_full_bipartite_matching` | 行、列索引 |
| **任意**二分图的最小/最大权和匹配（不要求完全） | `linear_sum_assignment`（5.5.4） | 行、列索引 |

```python
>>> from scipy.sparse.csgraph import maximum_bipartite_matching, min_weight_full_bipartite_matching
>>> B = csr_array([[1, 1, 0, 0], [1, 1, 0, 0], [0, 0, 1, 1]], dtype=np.int8)
>>> maximum_bipartite_matching(B, perm_type="column")
array([0, 1, 2])
>>> C = csr_array([[1, 3, 0], [2, 0, 5], [0, 0, 4]], dtype=float)
>>> r, c = min_weight_full_bipartite_matching(C)
>>> r, c, C[r, c].sum()
(array([0, 1, 2]), array([1, 0, 2]), 9.0)
```

**注意 0 与"没有边"的区别**：`csgraph` 的匹配函数把矩阵中的 **0 当作"无边"**。所以带权匹配里权重恰好为 0 的边会被忽略——这与 `linear_sum_assignment`（把 0 当作合法权重）的行为不同。用 `1e-10` 之类的极小正数代表"零权边"，或改用 `linear_sum_assignment`。

没有完全匹配时它抛异常而不是返回部分结果：

```python
>>> min_weight_full_bipartite_matching(csr_array([[1, 3, 0], [2, 0, 5], [0, 0, 0]], dtype=float))
ValueError: no full matching exists
```

## 5.12 空间结构、聚类与信号

本节是本章的"工具层"：三组工具的**共同点**是都在处理"点与点之间的关系"——空间上的远近、类别上的相似、时间上的周期。层级标记为 ◐，用到再读。

### 5.12.1 空间：距离、邻近与几何

**距离矩阵**用 `cdist`（两组点之间）或 `pdist`（一组点内部，只算一半）：

```python
>>> from scipy.spatial import distance
>>> D = distance.cdist(P[:500], P[500:], "euclidean")     # 500 × 500
>>> D.shape
(500, 500)
>>> distance.pdist(P).shape                                # 1000 个点的两两距离
(499500,)                                                  # = 1000 × 999 / 2
```

`pdist` 只返回上三角部分（$n(n-1)/2$ 个值）以省一半内存，需要方阵时用 `squareform` 展开。**1000 个点的方阵距离矩阵要 8 MB（`pdist` 的压缩形式 4 MB），100000 个点就要 80 GB**——需要"附近有哪些点"时不要算距离矩阵，用 KD 树：

```python
>>> from scipy.spatial import cKDTree
>>> tree = cKDTree(P)                                      # P 是 1000 × 2
>>> d, i = tree.query([[0.5, 0.5]], k=3)
>>> np.round(d[0], 4)
array([0.0034, 0.0113, 0.0276])
```

`cKDTree` 建树 + 查询 3 个近邻合计 **0.34 ms**。它还支持 `query_ball_point`（半径内所有点）、`query_pairs`（距离小于阈值的点对）、`sparse_distance_matrix`（稀疏距离矩阵）——**这三个接口是"百万点找邻居"的标准解法**，比算距离矩阵快几个数量级。

**几何**：`ConvexHull` 给凸包、`Delaunay` 给三角剖分、`Voronoi` 给最近邻分区。

```python
>>> from scipy.spatial import ConvexHull, Delaunay
>>> h = ConvexHull(P)
>>> len(h.vertices), h.volume
(18, 0.9825)                                               # 2D 下 volume 就是面积
>>> Delaunay(P).simplices.shape
(1980, 3)                                                  # 每行是一个三角形的三个顶点
```

> **⚠️ 陷阱**：`ConvexHull.volume` 在二维时表示**面积**，三维时才表示体积。同一属性名在不同维数是不同的物理量，而 2D 下还有一个 `area` 属性等价于 `volume`——两者都存在，容易混用。

**刚体变换**用 `Rotation`（只旋转）与 `RigidTransform`（旋转 + 平移，1.17 新增）。四元数、旋转矩阵、欧拉角、轴角四种表示可以互转，这一点在姿态数据处理里很省事。注意 `RigidTransform.from_rotation()` **只接受一个旋转参数**，平移要用 `from_components` 或先构造再赋值——写成 `from_rotation(R, translation=t)` 会直接 `TypeError`。

### 5.12.2 聚类：层次聚类与 k 均值

**层次聚类**不需要预先指定簇数，它产出一棵完整的合并树，之后可以在任意高度切：

```python
>>> from scipy.cluster import hierarchy
>>> from scipy.spatial import distance
>>> X = np.r_[rng.normal(0, 0.3, (30, 2)),          # 三个团，每个 30 点
...            rng.normal(3, 0.3, (30, 2)),
...            rng.normal(0, 0.3, (30, 2)) + [0, 3]]
>>> Z = hierarchy.linkage(X, method="ward")
>>> Z.shape
(89, 4)                                             # 90 个点 → 89 次合并
```

`Z` 的每一行是 `[簇A, 簇B, 距离, 新簇大小]`。在任意高度切分：

```python
>>> for k in [2, 3, 4]:
...     lab = hierarchy.fcluster(Z, k, criterion="maxclust")
...     print(k, np.bincount(lab)[1:])
2 [30 60]
3 [30 30 30]                                        # 正确切出三个团
4 [30 30 14 16]
```

`criterion="maxclust"` 表示"最多切出 k 个簇"。**判断聚类质量用 `cophenet`**：它给出树状距离与原始距离的相关系数，越接近 1 说明树结构越忠实地反映了原始数据：

```python
>>> hierarchy.cophenet(Z, distance.pdist(X))[0]
0.9298
```

> **实战建议**：`linkage` 的 `method` 参数（`"ward"`/`"single"`/`"complete"`/`"average"`/`"centroid"`）对结果影响很大，比"切几刀"更关键。经验规则：**`"ward"` 是连续数据的默认选择**（倾向产生大小相近的紧簇）；`"single"` 会产生"链状"簇，适合找连通结构但容易被噪声串成一条；`"complete"` 倾向产生紧凑的等直径簇。**永远把树状图（`dendrogram`）画出来看**，`cophenet` 只给一个数，看不出局部结构。

**k 均值**用 `cluster.vq.kmeans2`。要注意它是**随机初始化 + 局部迭代**，结果依赖种子：

```python
>>> from scipy.cluster.vq import kmeans2
```

| 数据 | 结果 |
|------|------|
| 三个分离良好的团（中心相距 3，标准差 0.3） | 6 个不同种子给出**完全相同**的惯性 14.822861 |
| 三个重叠的团（沿一条线，标准差 1.0、间距 2.5） | 10 个种子给出 **4 种不同的惯性**：187.73 / 194.44 / 205.45 / 207.96（**相差 10.8%**） |

而且 `minit="++"`（k-means++ 初始化）**也不能保证**得到最好结果（实测惯性 187.73～207.96 都有）。

> **实战建议**：`kmeans2` 的结果必须做**多起点验证**——跑 20–50 个不同 `seed`，看惯性的分布。如果分布很窄（像分离良好的情形），说明数据里有清晰的簇结构，一次结果可信；如果分布很宽（像重叠的情形），说明**数据本身不支持这么多个簇**，该考虑减 k 或换方法。另外 `kmeans2` 提供了 `minit="++"` 与 `missing="warn"`（空簇处理）等选项，但对结果的改善有限——**多起点比换初始化方法有效得多**。

### 5.12.3 信号：频谱与滤波

**频谱**用 `fft.rfft`（实数输入）。实测信号是 10 Hz + 37 Hz 两个正弦叠加白噪声，采样率 200 Hz、2 秒：

```python
>>> from scipy import fft
>>> F = fft.rfft(sig)
>>> freq = fft.rfftfreq(sig.size, 1/fs)
>>> mag = np.abs(F) * 2 / sig.size                  # 单边幅值谱
>>> freq[np.argsort(mag)[::-1][:2]]
array([10., 37.])
```

两个峰精确落在真值上。三个要点：

1. **实数输入用 `rfft` 而不是 `fft`**。`rfft` 利用共轭对称性只算一半，输出长度 $n/2+1 = 201$；`fft` 输出 400 个点，一半是冗余的负频率。
2. **频率轴用 `rfftfreq(n, d)`**，参数是采样间隔而不是采样率。`fftfreq` 返回带负频率的完整轴（长度 400）。
3. **幅值要乘 `2/n`** 才是物理幅值（直流分量除外）。`np.abs(F)` 是"未归一化的谱"，直接当幅值用会差一个比例因子——这是频谱图纵轴最常见的错误。

**功率谱估计**有两个入口，取舍是"分辨率 vs 方差"：

| 入口 | 峰值位置（本例） | 特点 |
|------|--------------|------|
| `periodogram` | 10.0, 37.0 Hz（准确） | 单段，分辨率高但方差大 |
| `welch` | 10.16, 36.72 Hz（有偏） | 分段平均，方差小但分辨率降（受 `nperseg` 限制） |

`welch` 把信号切成多段、各段算谱再平均，代价是频率分辨率降到 $f_s/\texttt{nperseg}$。本例 `nperseg=256`，分辨率 0.78 Hz，所以峰位偏差 0.16–0.28 Hz。**噪声大的信号用 `welch`，要看精确频率用 `periodogram`。**

**零相位滤波**是信号处理的标配：普通 `lfilter`（因果滤波）会对信号引入相位延迟，`filtfilt`/`sosfiltfilt` 通过正反两次滤波抵消掉它。

```python
>>> from scipy import signal
>>> sos = signal.butter(4, 20, btype="low", fs=fs, output="sos")
>>> y = signal.sosfiltfilt(sos, sig)
```

| 分量 | 滤波前幅值 | 滤波后幅值 |
|------|-----------|-----------|
| 10 Hz（通带内） | 1.008 | 1.005 |
| 37 Hz（阻带内） | 0.402 | **0.0029** |

37 Hz 被衰减 **139 倍**，10 Hz 几乎无损。三点实践要点：

1. **用 `output="sos"` 而不是默认的 `b`/`a`**。高阶滤波器的传递函数系数在浮点下条件很差，二阶节（SOS）形式数值稳定得多。scipy 文档明确建议所有 IIR 滤波都用 SOS。
2. **`sosfiltfilt` 对短信号会失败**：

| 信号长度 | 结果 |
|---------|------|
| 20 | OK |
| **15** | `ValueError: The length of the input vector x must be greater than padlen` |

4 阶 Butterworth 的默认 `padlen` 让它需要至少约 18 个点。短信号要显式降低 `padlen`（会牺牲边缘质量）或改用 `sosfilt`（有相位延迟）。

3. **`fs=` 参数必须给**，否则 `butter` 的 `Wn` 是归一化频率（0 到 1，1 对应 Nyquist）而不是 Hz。写成 `butter(4, 20, output="sos")` 会被解释成"截止频率 20 倍 Nyquist"，得到完全不同的滤波器**而且不报错**。

**峰值检测**用 `find_peaks`，它的参数对应"什么算一个峰"：

```python
>>> pk, props = signal.find_peaks(x, height=0.5, distance=20, prominence=0.5)
>>> len(pk), np.round(props["peak_heights"], 3)
(3, array([1.052, 1.047, 1.079]))
```

| 参数 | 含义 | 什么时候用 |
|------|------|-----------|
| `height` | 峰的绝对高度下限 | 已知信号量级 |
| `distance` | 相邻峰的最小间隔（采样点） | 已知物理上两峰不可能太近 |
| `prominence` | 峰相对于周围地形的突出度 | **抑制噪声伪峰的最佳参数** |
| `threshold` | 峰两侧必须下降的最小量 | 对付平台 |

配套的 `peak_widths`、`peak_prominences` 给出峰的半高宽与突出度，是做峰形分析的标准工具。

### 5.12.4 图像与网格：`ndimage`

二维网格上的操作与一维信号同源，但接口在 `ndimage`：

| 任务 | 入口 |
|------|------|
| 连通域标记 | `label`（返回标签图 + 个数） |
| 距离变换 | `distance_transform_edt` |
| 平滑 | `gaussian_filter`、`uniform_filter`、`median_filter` |
| 形态学 | `binary_dilation` / `erosion` / `opening` |
| 几何变换 | `rotate`、`zoom`、`map_coordinates`、`affine_transform` |

```python
>>> from scipy import ndimage
>>> lab, n = ndimage.label(img)
>>> n, np.bincount(lab.ravel())[1:]
(3, array([49,  1, 28]))
```

`label` 用 4 邻域（默认）或 8 邻域把相连的前景像素归组。上面的测试图有两个方块（49 与 28 像素）加一个孤立像素——**孤立像素也被算作一个连通域**，这是做颗粒计数时最常见的伪计数来源，标准做法是用 `binary_opening` 先去掉小噪点。

> **实战建议**：`ndimage` 的操作几乎都有 `mode=` 参数决定边界怎么处理（`"reflect"`、`"constant"`、`"nearest"`、`"wrap"`）。**默认的 `"reflect"` 会在图像边缘制造对称的假结构**，做卷积或滤波时如果物理上没有镜像边界，应当显式改成 `"constant"`（补 0）并给出 `cval`。

### 5.13.1 综合实战：应急物资调度与疫情需求预测

> 某地区有 6 个城市，路网已知。疫情暴发，需要预测各城市的物资需求，并在 3 个候选城市建设储备库，决定开哪几个、各覆盖哪些城市。已知疫情早期的每日现存感染数（含观测噪声）。

这道题走完 5.1.4 的四步骨架，每一步都用到前面某几节的工具。

#### 第 1 步：写下来 —— 路网变成距离矩阵（5.11）

9 条边、6 个城市，权是里程（km）：

```python
>>> from scipy.sparse import csr_array
>>> from scipy.sparse.csgraph import shortest_path
>>> edges = [(0,1,40), (0,2,70), (1,2,30), (1,3,55), (2,3,45),
...          (2,4,80), (3,4,35), (3,5,60), (4,5,50)]
>>> W = np.zeros((6, 6))
>>> for i, j, d in edges: W[i, j] = W[j, i] = float(d)
>>> D = shortest_path(csr_array(W), method="D", directed=False)
```

得到的距离矩阵：

```
[[  0  40  70  95 130 155]
 [ 40   0  30  55  90 115]
 [ 70  30   0  45  80 105]
 [ 95  55  45   0  35  60]
 [130  90  80  35   0  50]
 [155 115 105  60  50   0]]
```

三角不等式成立（最短路必然满足）。两条代表性路径：0→4 是 `[0, 1, 3, 4]` = 40+55+35 = **130 km**（而不是走 0-2-4 的 150）；0→5 是 `[0, 1, 3, 5]` = 40+55+60 = **155 km**。

#### 第 2 步：问可解 + 求参数 —— 疫情反演（5.6）

用频率依赖形式的 SIR（$N = 10^{6}$、$S_0 = N - 100$、$I_0 = 100$）：

```python
>>> def sir(t, y, beta, gamma):
...     S, I, R = y
...     return [-beta*S*I/N, beta*S*I/N - gamma*I, gamma*I]
```

真参数 $\beta = 0.42$、$\gamma = 0.14$（$R_0 = 3.0$），累计感染 940,439 人，现存感染峰值 **300,159 人**出现在第 36 天。给 121 天的观测加 4% 乘性噪声，用 `least_squares` 反演：

| 量 | 值 |
|---|---|
| $\hat\beta$ | 0.41933 ± 0.00044 |
| $\hat\gamma$ | 0.14070 ± 0.00039 |
| $R_0 = \hat\beta/\hat\gamma$ | 2.9804 |
| 参数相关系数 | +0.6925 |
| `nfev` | 7 |

按 5.6.3 的四道检查：残差沿 $\beta$ 呈干净 V 形（0.30→1102302，0.36→628718，**0.42→36710**，0.48→564601，0.55→1015949）；三个不同初值收敛到同一点 `[0.41933, 0.1407]`；参数相关系数 0.69（中等，说明两者有耦合但仍可分辨）；峰值拟合的相对误差 2.07%，与 4% 的噪声量级相符。**四项全部通过。**

#### 第 3 步：求解 —— 选址-分配 MILP（5.5）

各城市人口占比 `[0.25, 0.10, 0.20, 0.15, 0.18, 0.12]`，按峰值感染数折算物资需求，得到 `[75000, 30000, 60000, 45000, 54000, 36000]`，总计 **300,000** 单位。

候选库在 0、2、4 号城市，启用成本 `[300万, 220万, 360万]`，容量 `[180000, 120000, 150000]`，单位运费 = 距离 × 0.5 元。

变量是 $y_k \in \{0,1\}$（是否开库）与 $x_{kj} \ge 0$（运量），约束三条：

| 约束 | 数学 | 作用 |
|------|------|------|
| 需求满足 | $\sum_k x_{kj} \ge d_j$ | 每个城市都要拿到物资 |
| 连锁 | $x_{kj} \le M y_k$ | 没开的库不能发货 |
| 容量 | $\sum_j x_{kj} \le c_k y_k$ | 每个库的吞吐上限 |

```python
>>> # 关键的两行（其余是循环）
>>> row[3+k*6 : 3+(k+1)*6] = 1.0          # 容量约束：第 k 个库的 6 个变量
>>> row[k] = -cap[k]
```

基准情景的结果：

| 量 | 值 |
|---|---|
| 开库 | **`[1, 1, 1]`（三个全开）** |
| 总成本 | **10,937,500** = 启用 8,800,000 + 运输 2,137,500 |
| 各库发货 | 75,000 / 90,000 / 135,000 |
| 容量利用率 | 66.7% |
| 需求满足 | True |

配送方案很直观：每个库服务离自己最近的城市（库 0 服务城市 0；库 1 服务城市 1、2；库 2 服务城市 3、4、5）；未开的库发货量为 0.0。

> **⚠️ 陷阱（我在写这一节时踩的第二个切片 bug）**：容量约束那行一开始写成 `row[3+k*6 : (k+1)*6]`。对 $k = 0$ 恰好是 `row[3:6]`（正确），但 $k = 1$ 变成 `row[9:12]`（只覆盖 3 个变量），$k = 2$ 变成 `row[15:18]`（同样只覆盖 3 个）。**结果容量约束对第 2、3 个库只约束了一半的运量，从未真正生效**——"只开库 0"在容量 18 万、需求 30 万时竟返回 `status=0`。正确的切片必须以 `3` 为基准偏移：`row[3+k*6 : 3+(k+1)*6]`。这与 5.10.3 的 `np.diff` 属于同一类错误：**向量化代码里"基准偏移"写错不会报错，只会静默给出错误模型**。凡是拼接"每个块长度相同"的约束矩阵，建议用 `np.zeros((n_blocks, block)).ravel()` 的形状断言核对一遍。

#### 第 4 步：验证与决策 —— 需求规模与不确定度（5.10）

**决策对需求的敏感性**（其他条件不变，只缩放需求）：

| 需求规模 | 总需求 | 开库 | 总成本 | 启用 | 运输 |
|---------|--------|------|--------|------|------|
| 峰值 × 0.30 | 90,000 | `010` | 4,641,250 | 2,200,000 | 2,441,250 |
| 峰值 × 0.45 | 135,100 | `110` | 7,681,750 | 5,200,000 | 2,481,750 |
| 峰值 × 0.60 | 180,000 | `110` | 8,582,500 | 5,200,000 | 3,382,500 |
| 峰值 × 0.75 | 225,100 | `011` | 9,488,500 | 5,800,000 | 3,688,500 |
| 峰值 × 0.85 | 255,100 | `101` | 10,330,250 | 6,600,000 | 3,730,250 |
| 峰值 × 1.00 | 300,000 | `111` | 10,937,500 | 8,800,000 | 2,137,500 |
| 峰值 × 1.10 | 330,000 | `111` | 11,151,250 | 8,800,000 | 2,351,250 |

**开库数量随需求单调增加**（1 → 2 → 2 → 2 → 2 → 3 → 3）。这张表才是一个有用的模型该有的样子：它不只是给一个答案，而是给出**答案怎么随条件变化**。

> **机制洞察**：这个模型是否"有趣"，在求解之前就能判断——**比较启用成本与运输成本的量级**。我第一版把启用成本设成 800/650/900 元，而运输成本是 2,137,500 元，**相差三个数量级**。结果是最优解永远"三个库全开"，而且对需求规模完全不敏感（从 90,000 到 420,000 都是 `111`）——**启用成本小到可以忽略时，模型退化成了纯运输问题**。把启用成本调到百万量级（更符合现实）之后，决策才开始依赖需求。**做优化之前先做量级分析**，这比调求解器参数有用得多。

**参数不确定度传播到决策**（用 QMC，5.10.1）：

```python
>>> sampler = qmc.Sobol(2, scramble=True, rng=11)
>>> P = r.x[None, :] + sampler.random(128) @ np.linalg.cholesky(cov).T
```

用反演参数的协方差生成 128 组 $(\beta, \gamma)$，各自重跑 SIR 得到峰值分布，再各自解一次 MILP：

| 数据质量 | $\hat\beta$ 标准误 | 峰值 90% 区间 | 区间半宽 | 5% 情景下的最优决策 |
|---------|-----------------|-------------|---------|------------------|
| 121 点、噪声 4% | 0.00044 | [297,086, 297,811] | ±0.12% | `111` |
| 31 点、噪声 15% | 0.00266 | [293,176, 297,490] | ±0.72% | **`101`** |
| 21 点、噪声 25% | 0.00546 | [286,483, 295,723] | ±1.54% | **`101`** |

**最后一行是本实战最重要的结论**：数据质量好时（±0.12%）参数不确定度**不足以改变决策**，可以放心按点估计执行；数据质量差时（±1.54%），需求区间的下端落到了另一个决策分区里——**5% 分位情景的最优决策是只开 0 号和 2 号库，与点估计不同**。

换句话说：**只报一个"最优方案"是不够的，还必须报这个方案在什么条件下会变。** 这正是第 4 章"区间优于点"（4.1.3）在数值建模里的对应版本——**决策也要给区间**。如果本例只能拿到 21 天的粗略数据，正确的做法不是"按 `111` 执行"，而是"按 `111` 准备、但把库 1 的建设设计成可分期"。

| **残差或违背量** | `A@x - b`、KKT 违背、约束违反量；求解器的返回值不是证据 |
| **规模与条件数** | $m \times n$、`nnz`、`cond`、`fill_ratio`；决定结果可信度 |
| **迭代/调用次数** | `nit`/`nfev`/`njev`；判断是否撞到上限、成本是否可接受 |

### 5.13.3 陷阱总清单

以下 26 条全部来自本章的实跑，按"错在哪里"分组。**每一条都不会报错，或者报错信息与真实原因无关。**

**A. 数学前提与可解性**

1. 行列式小 ≠ 病态：`diag(1e-8)` 的 det 是 $10^{-24}$ 而 cond = 1.0（5.2.3）。
2. 残差小 ≠ 误差小：Hilbert $n=12$ 的误差 0.39、残差 4.4e-16，**误差/残差 ≈ cond**（5.2.3）。
3. `la.solve` 只在 $\mathrm{rcond} < \epsilon$（$\mathrm{cond} \gtrsim 5\times10^{15}$）时警告，$10^{6}$–$10^{15}$ 是**静默失准区**（5.2.3）。
4. `matrix_rank` 的默认容差会把秩判定变成掷硬币（本例容差 $5.92\times10^{-14}$ 与最小奇异值 $7.48\times10^{-14}$ 只差 26%）（5.2.4）。
5. 不选主元的高斯消元在 $\mathrm{cond} = 2.6$ 的矩阵上给出完全错误的解——**算法稳定性与问题敏感度是两笔账**（5.2.2）。

**B. 接口与返回值的形状**

6. `scipy.linalg.lstsq` 返回**普通 4 元组**，没有 `.x` / `.rank` / `.s`（5.2.5）。
7. 秩亏时 `la.lstsq` 的 `residues` 是 **`nan`** 而不是报错；`b` 为一维时它是 **0 维数组**，`res[0]` 会 `IndexError`（5.2.5）。
8. `shortest_path(indices=0)` 与 `indices=[0]` 返回的数组形状不同（一维 vs $(1,N)$）（5.11.2）。
9. `reconstruct_path(csgraph, predecessors)` 返回**最短路径树**（稀疏矩阵），不是一条路径（5.11.2）。
10. `yen` 默认只返回代价数组，取路径要显式 `return_predecessors=True`（5.11.2）。
11. `OptimizeResult` 的字段随方法变化：Nelder-Mead 没有 `njev`，Powell 有 `direc`（5.4.2）。
12. `solve_bvp` 返回的是 `niter` 不是 `nit`（5.9.4）。
13. `make_smoothing_spline` 返回 `BSpline`（结点在 `.t`），`UnivariateSpline` 才有 `.get_knots()`（5.7.3）。
14. `csr_matrix` 的 `*` 是矩阵乘法，`csr_array` 的 `*` 是逐元素乘（5.3.2）。

**C. 语义写反或写错**

15. 约束字典 `{"type": "ineq"}` 要求 $g(x) \ge 0$，不是 $\le$：写反后求解器返回无约束最优解并报 `success=True`（5.4.3）。
16. 选址的连锁约束 $x_{ij} \le M y_i$ 系数写反 → 固定成本被完全忽略，目标从 834 变成 594（5.5.4）。
17. `spsolve` 遇奇异矩阵返回 `nan` 只发警告，`splu` 抛 `RuntimeError`——同一件事两种行为（5.3.3）。
18. `butter(4, 20, output="sos")` 的 `20` 是归一化频率（20 倍 Nyquist），不是 20 Hz；漏了 `fs=` 不报错（5.12.3）。
19. `find_peaks` 的 `prominence` 是抑制噪声伪峰最有效的参数，只调 `height` 会漏或误检（5.12.3）。
20. 插值器**外推给出貌似合理的数字**：网格内精度 $10^{-6}$ 的插值器，往外一步错 170%（5.7.4）。
21. `LinearNDInterpolator` / `CloughTocher2DInterpolator` / `griddata` 在**凸包外返回 `nan` 而不报错**（5.7.4）。

**D. 向量化切片与索引**

22. 分层抽样的宽度写成 `edges[1] - edges[:-1]` 而不是 `np.diff(edges)` → 宽度递减甚至为负，误差比朴素 MC 差 69 倍（5.10.3）。
23. 约束矩阵的块切片写成 `row[3+k*6 : (k+1)*6]` 而不是 `row[3+k*6 : 3+(k+1)*6]` → 容量约束对 $k \ge 1$ 只覆盖一半变量，从未生效（5.13.1）。
24. `diags_array` 的对角线长度必须等于该偏移的**真实长度（不含填充）**，与旧 `dia_array` 约定相反（5.3.2）。

**E. 求解过程本身**

25. 反问题的**参数化写错会让参数不可辨识**：残差在 $\beta$ 变化 14 倍时只动 0.8%、最小值落在边界，而 `least_squares` 返回 `status=2`、零报错（5.6.3）。
26. `success=True` 与"找到最优"是三件事：可能精度不足（默认容差）、可能违反约束（符号写反）、可能落在局部极小（Rastrigin 上 50 次多起点 0/50 命中全局）（5.4.4）。

另外三条"环境级"的版本差异（章首已列，此处只强调后果）：

- `integrate.simps` / `trapz` / `cumtrapz` / `romberg` / `quadrature` **与 `np.trapz`** 在 1.18 全部不存在了（5.8.1）。
- `signal.cwt` / `morlet2` / `ricker` / `lsim2` 已移除（5.12.3）。
- `scipy.odr` 自 1.17 起弃用、1.19 移除（5.6.4）。

### 5.13.4 断言化验证模板

本章每一节都以"验证"收尾。把它们写成可执行断言，就能让管道在出错时立刻停下，而不是把错误答案带到报告里。

```python
import numpy as np
from scipy import linalg as la

def assert_solution(A, x, b, name="Ax=b", cond_warn=1e10, tol=1e-8):
    """线性方程组解的四项断言：残差、后向误差、正性、条件数。"""
    A = np.asarray(A, dtype=float); b = np.asarray(b, dtype=float)
    res = np.abs(A @ x - b).max()
    scale = max(np.abs(b).max(), np.abs(A).max() * np.abs(x).max(), 1.0)
    cond = np.linalg.cond(A)
    assert res / scale < tol, f"[{name}] 相对残差 {res/scale:.2e} 超过 {tol:.0e}"
    assert np.isfinite(x).all(), f"[{name}] 解里出现 inf/nan（矩阵可能奇异）"
    if cond > cond_warn:
        print(f"[{name}] ⚠️ cond={cond:.1e}，只剩 "
              f"{np.finfo(float).precision - np.log10(cond):.1f} 位有效数字")
    return {"residual": res, "cond": cond}

def assert_optimization(res, jac=None, constraints=(), name="优化", tol=1e-6):
    """优化结果的三项断言：成功标志、梯度范数、约束可行性。"""
    assert res.success, f"[{name}] 求解器未收敛：{res.message}"
    if jac is not None and not constraints:
        g = float(np.linalg.norm(jac(res.x)))
        assert g < 1e-3, f"[{name}] ||∇f|| = {g:.2e}，可能未到驻点"
    for c in constraints:
        val = c["fun"](res.x)
        violation = max(0.0, -val) if c["type"] == "ineq" else abs(val)
        assert violation <= tol, f"[{name}] 约束违背 {violation:.2e}"
    return {"fun": res.fun, "nit": res.nit, "nfev": res.nfev}

def assert_ode(sol, conserved=None, name="ODE", rtol=1e-6):
    """ODE 结果的三项断言：求解成功、状态有限、守恒量漂移。"""
    assert sol.success, f"[{name}] 积分失败：{sol.message}"
    assert np.isfinite(sol.y).all(), f"[{name}] 解里出现 inf/nan"
    if conserved is not None:
        E = conserved(sol)
        drift = (E.max() - E.min()) / max(abs(E.mean()), 1e-300)
        assert drift < 1e-3, f"[{name}] 守恒量相对漂移 {drift:.2e} 过大"
        return {"drift": drift}
    return {}
```

用起来就是三行：

```python
>>> rep = assert_solution(M, x, d, "投入产出")
>>> rep = assert_optimization(res, jac=obj_g, constraints=cons, name="选址")
>>> rep = assert_ode(sol, conserved=lambda s: 0.5*s.y[1]**2 + 9.81*(1-np.cos(s.y[0])), name="摆")
```

> **实战建议**：**断言要检查"物理/业务不变量"，不只是"数值不报错"。** 第 5.2.6 的实战里最有价值的一条检查是 `(x > 0).all()`——总产出为负说明模型不成立，而求解器对此毫无意见。你的问题里一定有类似的量：概率必须在 $[0,1]$、质量守恒、容量不超限、比例之和为 1。**把这些写成断言，比多跑十次求解更有用。**

## 本章小结

| 主题 | 核心要点 |
|------|---------|
| 四步骨架 | 写下来 → 问可解 → 求解 → 验证；缺一步答案就不可信 |
| 三本账 | 精度账（残差 ≠ 误差）、成本账（`nfev`/`nnz`/迭代数）、稳定性账（条件数/刚性/局部极小） |
| 线性方程组 | `solve` 而非 `inv`；结构（对称/三角/带形/稀疏）决定路径；`solve_banded` 比稠密快 506 倍 |
| 条件数 | 约等于丢掉的十进制位数；`10^{6}`–`10^{15}` 是静默失准区；病态要换模型不要换求解器 |
| 最小二乘 | 永远不用正规方程（$\mathrm{cond}(X^{\top}X) = \mathrm{cond}(X)^2$，实测差 64 亿倍）；秩亏时查 `rank` 再看 `residues` |
| 正则化 | 岭回归 $\lambda = 10^{-4}$ 把系数误差降到 1/445，残差只涨 4.7%——**用一点拟合精度换稳定性** |
| 稀疏矩阵 | 填充决定成本（`permc_spec` 之间差 2.88 倍）；`splu` 复用 29×；**CG 在这类问题上是直接法的 42–77 倍慢** |
| 非线性优化 | 方法之间精度差 15 个数量级；解析梯度让 `nfev` 降到 1/3；`success=True` 有四种骗人方式 |
| 线性/整数规划 | 四个改写动作；影子价格免费给灵敏度；五个建模模式（运输/指派/背包/选址/排班） |
| 拟合与反问题 | `pcov` 给参数不确定度；稳健损失在 10% 粗差下好 10.5 倍，但 `arctan` 会 15.4% 失败；反问题必做 V 形残差与多初值检查 |
| 插值 | 等距高次插值会爆炸（21 点误差 59.8）；`PchipInterpolator` 保形，`CubicSpline` 会过冲；凸包外返回 `nan` |
| 数值积分 | `quad` 在端点奇点与无穷区间上到机器精度；采样点用 `simpson`（$O(h^4)$）而非 `trapezoid`（$O(h^2)$） |
| 微分方程 | 刚性是最大分水岭（RK45 比 Radau 多 26 倍调用）；事件时刻精度由 `rtol` 决定；守恒量是最好的长时间验证 |
| 不确定性与敏感性 | Sobol 比 MC 快 396 倍；OAT 看不到交互；分层抽样 61×、对偶变量 4.4×、重要性抽样 13–15× |
| 图与网络 | 图就是稀疏邻接矩阵；`"D"/"BF"/"J"/"FW"` 按负权与全源需求选；`reconstruct_path` 返回的是树 |
| 空间、聚类与信号 | KD 树代替距离矩阵；`cophenet` 给聚类质量；实数频谱用 `rfft` 并乘 `2/n`；IIR 滤波用 SOS |
| 验证方法论 | 断言 + 物理不变量；报告四件事（方法/残差/规模与条件数/迭代数） |

**三条最重要的收获**：

1. **"求解器返回了结果"与"我得到了答案"之间隔着四道检查。** 本章反复出现的三种骗局——精度不足、约束违反、局部极小——每一个都有 `success=True` 的实例。
2. **问题的难度不属于算法。** 条件数、刚性、不可辨识性都是问题本身的性质，换方法救不回来，只能换模型、加正则化或加数据。
3. **数字必须实测。** 本章修正过十余处"看起来合理但跑出来不是这样"的数值。凭记忆写下的数字与实测数字在外观上无法区分，这是数值工作中最容易被低估的风险。
